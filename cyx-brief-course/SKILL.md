  项目式创作课的**双轨交付**制作流程：同门课同时产出——①「课堂简版」深色赛博霓虹风单文件交互式 HTML 课件（图为主、字极简，老师投影照讲）；②「学案」A4 竖版可打印 PDF 型 HTML（章节制 · 序章 ＋ N 章，学生人手一份填）。
  当用户要求做「简版课件」「课堂简版」「图为主字极简的课件」「配套学案」「学生学案」「A4 打印学案」「项目课课件＋学案」时使用。
  核心判据：**内容骨架是章节制**（不锁时长，每章以一件可交付物收尾，且该物被后面的章节接着用），不是时长轨制——要做锁时长、双轨快线、游戏化晋升的课，改用 `cyx-course-html`。
  七步流程：收集素材 → 访谈定口径 → 定七章成果链 → 照抄 assets/template-courseware.html 与 assets/template-workbook.html → 分块写入 → 双轨咬合校验（页码互指、成果链闭合）→ 交付预览。
  **另有「换装」路径（第 5.5 步）**：手上已有内容齐全的课件、要套进另一套成熟版式时，先做差异审计 → 用 Python 脚本改外壳类名与脏 class → 按「最长语义段 ≤14 字」治理超长短句（三轮迭代）→ 补齐说课缺段 → 跑体检脚本。判据是两份文件的 CSS 体系是否同源。
  **另有「例标识」路径（第 5.10 步）**：用户要求「突出文中是例子的概念」「加例：的标识」时，先盘点三个层（SVG 内小字尾行／双栏卡「这样」侧／成品图范例行）的举例处，统一标成 `【例】` 方括号块——SVG 里的尾行要**提升为 `</svg>` 之后的独立例栏**（小字太弱标了看不见），成品图用 SVG 画标签且**放在画板外的信息带**（放画板内会被图片盖住），学案同步把徽标插进 `tr.ex` 首列（描边 + 浅底，印刷安全）。

p8 —— 改数字，别挪页序，一挪 29 处引用全得重排）。**用户圈出说课口播里的某句提醒说「这句话不要了」时同走这条路径**：先判**屏显上有没有落点**——p02 口播末句 `注意，这是参照，不是模板，别照着再出一遍。` 就是本页页底大字 `结构照抄，内容得是自己的` 的口语版，删了信息不丢；以 `注意／记住／顺便说` 开头的尾句优先怀疑（插入语，书面件不缺这个信息，删后以主句或提问收尾更利落）；**同一层才连带**——口播↔口播清副本（课件＋讲课稿＋Prompt 合集），口播↔学案纸面注记（`📌 这份成品是参照，不是模板…`）不动；断言「本页口播以…收尾」必须**先切本页切片再取层**，否则全文 `re.search` 会拿到 p01 的口播而误报失败（见 §5.23   **另有「五件套」路径（第 8.1 步）**：用户点名「按这几件的样式产出」时，交付 5 件——课件 HTML ＋ 学案 HTML ＋ 设计方案 md ＋ 全页 Prompt 合集 md ＋ 教师讲课稿 md；后三件由 `scripts/fourpiece/` 的 Python 工具从课件**程序化抽取生成**（fp_extract 抽结构 → fp_design／fp_prompts／fp_lecture 生成，fp_run 一键出三件，配置模板 `assets/fourpiece-config.example.json`），不手抄。**普适于任何课程**：只要课件按 §3 规范写（页页有 tnote 三段说课 ＋ todo 任务条 ＋ 真实章归属），跑 `fp_run.py` 即可派生后三件，第 5 件教师讲课稿把课件折叠的说课「展开成六块」，零转述失真。

  教师说课用 `details.tnote`（默认三段式 🗣 口播 / 🎬 操作 / ⚠️ 提醒；用户要求时降为单段口播，见 §5.18／§5.20／§5.21），默认收起、打印不输出。

# 简版课件 ＋ 打印学案 双轨制作（cyx-brief-course）

把一门**项目式创作课**做成一对文件：一份给老师投屏照着讲，一份给学生人手一份填。这对文件不是两份独立文档，是同一门课的两个面——**课件上每一页的任务，都落在学案的某个格子里**。

## 与 `cyx-course-html` 的分工（先判这一条，判错全篇重做）

| | `cyx-course-html` | 本技能 |
|---|---|---|
| 编排 | **时长轨制**（锁总时长、全时长版＋快线双轨）或通用章节制 | **章节制**，不锁时长 |
| 交付 | 讲台版 ＋ 备课版（+ 样稿） | **课堂简版 HTML ＋ A4 打印学案 HTML** |
| 视觉 | 暗色霓虹（同一套 template.html） | 课件暗色霓虹 ＋ **学案纸质米色**（两套） |
| 每页节奏 | pace 徽章（⏱ 核心／⚡ 选做／📎 skip） | **无 pace 徽章**；有 `.stepchip`（总览／第 N 步／过关） |
| 内容载体 | `.layout-tag` 版式规格 ＋ 卡片阵 | **手写 SVG 手工排版**（`.hero`）为主 |
| 互动 | 游戏化晋升、check-list | `.todo` 任务条（指向学案页码）＋ `details.tnote` 说课 |
| 学生页 | 无 | **学案**（A4，`@media print` 分页，可直接印） |

**判据**：用户说「不要时间、按章节来」「每章交一件」「配一份学案给学生填」→ 本技能。用户说「XX 分钟课堂版」「双轨」「快线」→ `cyx-course-html`。
**两者不要混用**：本技能的课件模板**没有** `pace`／`rank-ladder`／`rankup`／`layout-tag` 的 CSS；`cyx-course-html` 的模板**没有** `.tnote`／`.stepchip`／`.todo`／学案那套纸质变量。硬套会出现空白样式。
**例外 —— `.prep` 教师课前准备块本技能要用**（见第 3.7 节）：`assets/template-courseware.html` 里确实没有它的 CSS，但组件本身两轨都要。做法是从 `cyx-course-html/assets/template.html` 取 `.prep` 全套规则（同款设计令牌），追加到课件 `<style>` 末尾（放在 `@media(max-width:720px)` 之后、`@media print` 收尾），再写页。别因为「模板里没有」就跳过这一块。

## 第 0 步：收集素材

按优先级找：

1. **同系列已交付的简版课件 ＋ 学案**（最完整的一份）→ 结构、口径、风格、组件配法的唯一参照，**优先照它，别照本 SKILL 的示范模板**（示范模板是骨架，真东西在已交付件里）。
2. **教案 / 课程大纲 / 项目说明**（`*.md` / `.docx`）→ 内容主体。
3. **用户口述** → 缺的靠第 1 步访谈补齐。

项目里一份也没有时，把 `assets/template-courseware.html` 与 `assets/template-workbook.html` 复制到目标路径起步。两份模板里的 `【】` 全是占位符，逐项换掉，**删掉模板里用不到的章节横幅与示范页，但 CSS 一行都不删**。

路径约定：源素材与输出文件都用**绝对路径**。Windows 桌面类目录在工具调用里写正斜杠或双反斜杠均可，**不要用 shell 拼接**（本机 Bash 缺 coreutils，`ls`／`dirname` 都报 127）。

## 第 1 步：访谈（AskUserQuestion，推荐项放选项第一位）

必问：

1. **课程主题与受众**（学段、融合了哪几门学科）
2. **分几章、每章的产出物分别是什么**（章节制的骨架就长在这条上；用户给不出就按第 2 步的方法替他拆）
3. **最终成果是什么**（整套作品包 / 一场展 / 一条片子……）
4. **学案要不要**（推荐：要。只有课件没有学案时，本技能就退化成半套，课时任务没有落点）
5. **文件去向与命名**（推荐：新建 `N-<课程名>-课堂版-简版.html` ＋ `M-<课程名>-<共同体名>学案.html`，旧版不动）
6. **分组与岗位**（推荐：4–6 人共用设备 ＋ 四岗位；**岗位固定还是轮换必须问清**——两种都常见。
   - **固定制**（如四格漫画课）：序章定岗后整门课不变，让每个人在同一件事上越做越熟。学案第 2 页出「岗位分配表」（岗位／谁／一直负责的事）。
   - **轮换制**：每章往后挪一格、几章走完一轮。学案第 2 页出「每章轮换表」。
   - 两种都**要写清「组人数 > 岗位数时多出来的人干什么」**（如统一挂「助理」）。
   - 口径定下后三份产出（md／课件／学案／大纲）必须用同一套说法，别一处写固定一处写轮换。）
7. **AI 工具链口径**（AI 类课必问）：用哪些工具、**全课只有哪几处用 AI**、各管什么、边界在哪。已确认口径示例：豆包（对话 / 出候选 / 出方向 / 审稿 / 出新解法）＋ 绘图 AI（只出参考图，**不直接出成片**）＋ 手绘（成稿）。换课程、换工具时先让用户确认口径再写。

**用户明确批准设计后才开始写文件。**

## 第 2 步：定「七章成果链」（本技能的灵魂，别跳过）

章节制课件的骨架是一条**产物链**：第 N 章交的那件东西，就是第 N+1 章的输入。必须先把这条链写成一行，再动笔。

```
序章（定组定岗认规矩）
 → 01 角色卡（愿望 ＋ 弱点）
 → 02 冲突提纲（四行，第四行必须卡住）
 → 03 V1 失败稿 ＋ 问题清单
 → 04 修改记录（V1→V2 对照）
 → 05 成稿
 → 06 出厂自检（不新增东西，只回头查）
 → 07 展板 ＋ 讲解词 ＋ 反馈记录
```

### 2.1 拆章的硬规则

- **一章盖两件事时必须拆**，否则「按章推进」是假的。实测教训：`作品制作` 与 `作品完善` 原本挤在同一章，拆开后「自检」与「展出」才各归其位。
- **必须有一章只查不造**（如第 06 章）：明确写「**这一章不交新东西**」，把前面各件补到出厂标准。这一章是整门课的信任来源——它告诉学生「改」比「画」重要。
- **最后一章要有外部读者**（真观众 / 真反馈），不是自我展示。收尾金句通常长在这里。
- **尽量不动页码**：章一拆，正文里所有跨页引用与附录速查表都要跟着重排。拆之前先核对页数归属。

### 2.2 每章的统一页序列（三件套，别少）

| 位置 | `stepchip` | 内容 |
|---|---|---|
| 第 1 页 | `总览` | 本章 N 件事（SVG 横条卡片，**右侧各挂页码片**）＋ 📦 本章成果 ＋ 🎖 过关标准 |
| 中间页 | `第 N 步` | 顶部 `🔗 接第0N章【上一件成果】：…` 回扣条 ＋ 两栏对照（✅ 这样写 / ✕ 不要这样）＋ 可选 `.prompt` 指令框 ＋ `.todo` ＋ `.tnote` |
| 末页 | `过关` | **固定三块**：✅ 过关标准（绿）／ ✕ 不达标怎么办（品红）／ 🎖 盖章两个条件（黄） |

### 2.3 示范范例链（「例（XX）」贯穿全篇）

全课用**同一个示范角色、同一个麻烦**，从第 01 章推到最后一章，附录 C 里画成一条链给老师备课用。

- 同一个示范角色的每一件产物**按章排成一列，逐件往下推**——从上一件能不能推出下一件？推不出来就是断链。
- **断链时改上游，别改下游**：下游的全部内容都长在 V1／V2 上，动它等于重写半个课程；上游只有一章、一格例子，改完链条就闭合。
- 示范稿必须是**「有价值的失败」**：第 03 章的 V1 要错得具体、错得能推出第 04 章的改法。实测做法——V1 把最难的「开口」绕过去（趁同学背过身把绳拿走），卡点一丢结局就不成立，第 04 章换成真的开口借，第四行自动长成「绳递过来，人却走了」——**收在短处上，别收在圆满上**。

#### 范例链一致性审计（成品图／成品页改完后必跑，2026-09-18 立）

一旦课件里出现**成品图（手绘 SVG 四格、示例产出、欣赏页）**，它就必须和正文里的范例链逐字对得上。做法是把链条先抽出来再对图：

```python
# 1) 抽全课范例锚点：拿到每一处「例（跳跳）：…」
import re, io
s = io.open(课件, encoding='utf-8').read()
anchors = re.findall(r'例[（(]跳跳[）)]?[：:]\s*([^<\n]{0,90})', s)
```

2) 把锚点整理成**权威链**（本课为：① 储物柜里，跳绳不在 → ② 操场边，绳在别人手里 → ③ 话到嘴边，又咽回去 → ④ 绳递过来，人却走了 → 题《张不开嘴的下午》）。
3) 拿成品图每格的文字／小标题，与权威链**逐格比**；不一致就改图，不改正文。

**关键：区分「真漂移」与「假警报」。**

- **反面教材必须保留**。「终于借到了」出现在 p21 的「✕ 不要这样 / 太圆满了，读者不记得」里，
  是**故意写错的对照**，不是残留——扫到它别删。
- **同一概念的两种叫法可能都对**。「张不开」是**短处名称**（话到嘴边张不开嘴），
  「咽回去」是**第③格画面文案**，16:5 的比例不冲突。
- **页索引表天然不含台词**。设计方案 md（第 3 件）是页表，只命中标题锚点，不是漏转。

**反面教材合规自检**（防止「故意写错的例子」被误当成正文口径）：

```python
COUNTER = ['终于借到了', '等一轮']
OK_CTX = ('不要这样', '✕', '最没劲', '读者不记得')
for w in COUNTER:
    for m in re.finditer(w, s):
        ctx = s[max(0, m.start()-320):m.end()+40]
        assert any(t in ctx for t in OK_CTX), f'{w} 脱离了反面教材语境'
```

**症状 → 处置**（本轮实测）：

| 症状 | 病因 | 处置 |
|---|---|---|
| 同一处结局两种说法 | 说课口播随手改写成同义句 | 以**带 ✅/✕ 的收法块**为准，口播跟着改 |
| 成品图第④格画「等一轮」 | 图画在链条定稿前 | 改图，跟 p21 |
| 气泡写了课程里没有的台词 | 作画时自行编词（如「借我十分钟」） | 删掉，改「卡住的断句」——开口说到一半 |
### 2.4 计数类要素（各课替换内容，但数量固定）

- **四岗位**（固定制／轮换制二选一，见第 1 步第 6 条）：四个岗各写清「管什么／每章交什么／明确不许做什么」。
  固定制补一句为什么定死（如「换着当，七章下来每一样都是浅的」）；轮换制写清方向与「几章走完一轮」。
  **组人数 > 岗位数时，多出来的人干什么必须写清**（如统一挂「助理」）。
- **四个筛子 / 四条尺子 / 四个问题方向 / 四条一致性锚点**：这类「四件套」是给学生一套可操作的判断工具，标题要短（2–5 字），每条带**可证伪的判据**，不是形容词。
- **五问出厂自检**：每条含「自检问题 ＋ 具体查什么」，问的是**外部可验证**的事（陌生人能不能复述），不是自我感觉。
- **展板五块**：按顺序摆，顺序本身就在讲「一个作品怎么被改好的」。**第一块必须是失败稿**——它不是丢人的东西，是证据。
- **5 处 AI 使用点**：全课不多不少五处，每处都是「**它出参考、你做决定**」。附录 A 画成地图，各带页码片。

- **配色节奏**：cyan → purple → orange 循环（`.pnum` 与 `.page-num` **同步**变色）；附录统一 `yellow`。
- **页头标识三种口径，三选一（2026-09-18 定）**：
  - **① 页码式**：`.page-num` 写 `P 01`，页脚不再重复页码。
  - **② 章段点式**（**用户说「序号按 1.1、1.2 这样排」时用；Lulu 的默认偏好**）：`.page-num` 写 `章.节`（`1.1`），页码移到页脚居中（`.pfoot`）。
  - **③ 章段横杠式**：`.page-num` 写 `章-节`（`1-1`），页码同样在 `.pfoot`。
  - **两种章段式只是分隔符不同，编号骨架一致**；用户改口径时通常只说一句「改成 1.1 这种」，此时是**把现有横杠式换成点式**，不是重排页序——只需替换 `.page-num` 与全部引用里的分隔符。
- **章段号的编号规则（章段式专用）**：按章段顺序编。
  **两种起编法，用户没指定时按第一种**：
  - **A. 零段起 `0.1`**（Lulu 2026-09-18 指定）：封面 `0.1` → **成品欣赏 `0.2`** → 序章 `0.3` → 认识篇 `1.1…1.n` → 第 01 章 `2.1/2.2/2.3` → … → 第 07 章 `8.1…` → 附录 `9.1…9.n`。
    ⚠️ 注意这里封面是 `0.1` 而不是 `0.0`——**「第 0 章的第 1 页」**，比 `0.0` 读着顺，也与后面各章从 `.1` 起保持一致。
  - **B. 封面 `0.0` 起**：其余同上，只是封面那页写 `0.0`。
  两法**只影响第 0 章那三页**（封面 / 成品 / 序章），第 1 章往后完全一样。
  **注意**：章段号与全课页序是两套数——`2.1` 是全课第 8 页，不是第 2 页。页脚那行才写全课页序。
- **`.pfoot` 的配色必须与同页 `.page-num` 一致**（cyan 默认 / purple / orange / yellow），改了页头别忘了页脚。
- **⚠️ 中间插页 = 顺延其后全部编号，必须用显式编号表重排**（2026-09-18 实测踩坑）：
  一旦在序列中间加页（如封面后插「成品欣赏」），其后每一页的章段号与页脚页序都变。**不要逐页推导**——写一张显式表一次性重排：
  ```python
  # 示例按「零段起」口径：封面 0.1 → 成品 0.2 → 序章 0.3 → 认识篇 1.1… （见上「两种起编法」）
  NUMBERS = ["0-1","0-2","0-3","1-1","1-2","1-3","1-4",
             "2-1","2-2","2-3", … , "9-1","9-2","9-3"]   # 逐页列全，人工核对
  # 一个 pass 同时改 id(pNN) + .page-num；再单跑一遍 .pfoot 顺排 1→M
  ```
  重排后再跑一遍「页序表」核对：`for i, m in enumerate(re.finditer(r'<section class="page" id="(p\d+)"', c), 1)` 打印「页序 / 章段号 / 页脚号 / 标题」，三列必须同向递增。
- **改页头口径时，同步改这四处**（2026-09-18 实测，漏一处就不一致）：
  1. 课件每页的 `.page-num` ＋ 新增 `.pfoot`；
  2. `check_brief_course.py` 的页头识别正则（**三种格式都吃**：`P\s*(\d+)` / `(\d+)\.(\d+)` / `(\d+)-(\d+)`，`sep` 随之取 `-`）；
  3. `scripts/fourpiece/fp_extract.py` 的 `pages[].ord`（从 `id="pNN"` 取全课页序）＋ 四个生成脚本里的 `page_ord()`；`fp_lecture.py` 的章段号识别须兼容横杠：`re.fullmatch(r"\d+[.\-]\d+", raw_num)`；
  4. **附录 A 速查表与学案速查表的引用**（`text-anchor="end">2.0</text>` 这种点式要一并转横杠；学案 hint 区间 `3-1–3-3` 跟着改）。
  **根因**：`fp_*.py` 原先一律用 `re.search(r"(\d+)", p["num"])` 取页号——页头改写成 `2.1` 后，这行会把 `2.1` 当成第 2 页，导致 md 里所有页号、章区间、页脚全错。已统一改为 `page_ord(p)`（优先读 `ord`，退回从 `id` 抠数字），**任何脚本都不要从 `num` 取页序**。
- **⚠️ 横杠 ⇄ 点式互转：只改分隔符，别重排编号；且务必转全**（2026-09-18 实测踩两个坑）：
  用户说「序号改成 1.1、1.2」时，要动的**只是分隔符**，章段骨架不动。但「转全」比想象中难——**四个位置容易漏**：
  | 位置 | 形态 | 漏掉的后果 |
  |---|---|---|
  | 课件每页 `.page-num` | `<span class="page-num purple">3-1</span>` | 要查！**带配色变体的 `page-num[^"]*` 才匹配得到**，写死 `page-num">` 会漏统计 |
  | 课件附录 A 速查表 | `<text text-anchor="end">2-1</text>` | 速查表还指旧号，学生翻不到 |
  | 学案 hint 区间 | `<span class="hint">3-1–3-3</span>` | **最易半转**——只转了左端变成 `3.1–3-3` |
  | 学案速查表引用 | `3-1,4-1,…,9-1` | 同上 |
  **半转的典型成因**：用 `s.replace("3-1","3.1")` 逐对替换，一次只吃一个端点；区间 `3-1–3-3` 里两个 `3-1`/`3-3` 只命中前一个。**正解用正则一次吃完整个区间**：
  ```python
  s = re.sub(r'(\d)-(\d)[–-](\d)-(\d)', lambda m: f"{m.group(1)}.{m.group(2)}–{m.group(3)}.{m.group(4)}", s)  # 先吃区间
  s = re.sub(r'(text-anchor="end">)(\d)-(\d)(</text>)', lambda m: f"{m.group(1)}{m.group(2)}.{m.group(3)}{m.group(4)}", s)  # 再吃速查表
  ```
  转完**必查残留**：`re.findall(r'(?<![\w.-])\d+-\d+(?![\w-])', s)` 必须为空；再用 `re.findall(r'class="page-num[^"]*">\s*([\d.]+)', s)` 数出 31 个号逐个核对。

- **⚠️ 每一页的页头都必须齐三件：`.page-num` ＋ `.stepchip` ＋ `.page-title`**（2026-09-18 修订）。
  `page-num` 数量必须等于 `section.page` 数量；三件齐备由体检脚本新项把关（`p01:缺stepchip` 这种会直接 FAIL）。
  - **最容易漏的是封面页**：写封面时容易只写 `0.1` ＋ 标题，把中间的 `.stepchip` 省了——于是全篇 31 页里只有它一个页头少一个元素，视觉上很突兀（Lulu 原话：「0 章的序号，结构也要保持和这个一致」）。
  - **序章／附录页也一样要 `stepchip`**，只是标签词不同：封面 `封面`、成品欣赏 `看成品`、开场 `开场`、认识篇 `认识 1/4`、各章 `总览`／`第 1 步`／`过关`、附录 `速查`／`教师页`。
  - 反面例子：`<span class="page-num">0.1</span><span class="page-title">四格漫画故事工厂</span>` ← 缺 stepchip。
  - 正确例子：`<span class="page-num">0.1</span><span class="stepchip">封面</span><span class="page-title">四格漫画故事工厂</span>`。
  - 自查：`for m in re.finditer(r'<section class="page" id="(p\d+)">\s*<div class="page-head">(.*?)</div>', s, re.S)` 逐页查三个 `<span class="…` 是否都在。
- **每个 `<main>` 内不换章**：一章一段 `<main>`，章节横幅夹在两段 `</main>` / `<main>` 之间。
- **序章 P01 默认做成封面页**：SVG 里用 `linearGradient` 做渐变主标题 ＋ 四格定位卡（①起头 ②卡住 ③出手 ④结果）＋ 一行核心句。
- **⚠️ 实践类课程：封面之后、序章之前固定插一页「成品欣赏」（2026-09-18 定）**。
  判据：这门课的产出是一件**作品**（漫画、短片、海报、小程序…）而不是一份**认知**时，学生第一眼该看到的是成品，不是定义——**作品成品就是这门课的引子**。用户原话：「既然是实践课，就需要以作品成品为引子」。
  写法（`id="p02"`、章段 `0-1`、`.stepchip`＝**看成品**、横幅归封面同一段 `ch0`）：
  1. 手写 SVG `class="hero" viewBox="0 0 1000 640"` 画一件**完整成品**（四格漫画就画四格，短片就画分镜条），四格文案照 **起 / 承 / 转 / 合** 四职能各给一句；
  2. 底部加一行**四格职能标签**（`① 起…② 承…③ 转…④ 合…`）——让学生看见「四个格子各管一段」；

  **SVG 排版两个已踩的坑**：① 底部职能标签与 `.cap` 行会重叠 → 外框加高、viewBox 由 600 抬到 **640**、标签下移；② 两行标签（起/承 与 转/合）间距过近 → y=**580 / 612**、字号 **13**。

- **`.tbanner` 只写「怎么印」**（几页、双面、第几页按组印几份、装订后填什么），**不写「这是什么」**。它是教师打印说明，`@media print` 里 `display:none`。
- **`.wake` 六件成果格**：最后一格加 `.final`（双线红边 ＋ 米黄底），强调「第 ⑥ 件不是单件，是整套作品包」。

### 3.3 手写 SVG 的排版规范（课件正文图示全都这么做）

不引图、不占体积，靠 `<rect rx>` ＋ `<text>` 手工排版。**viewBox 默认 `0 0 1000 420`**（教师页用 `0 0 1000 650`）。

- **文字一律用 class 上色**，不要写 inline `fill`（除了 `<tspan>` 里的局部强调）：

  | class | 颜色 | 用途 |
  |---|---|---|
  | `.t` | `#E8ECFF` 正文白 | 主标题、条目名 |
  | `.td` | `#8E96C9` 暗蓝 | 补充说明 |
  | `.tf` | `#5A6094` 更暗 | 页码片、注释、最弱的层级 |
  | `.tc` | `#00F5D4` 青 | 1 号色／强调／引路句 |
  | `.tm` | `#FF2E97` 品红 | 警示、不许做的事 |
  | `.ty` | `#FFE74C` 黄 | 关键提醒、盖章条件 |
  | `.tn` | `#BB86FC` 紫 | 第 2 号色 |
  | `.to` | `#FF6B35` 橙 | 第 3 号色 |
  | `.tg` | `#5CE082` 绿 | 过关标准、肯定 |

- **卡片**：`<rect x y width height rx="12" fill="rgba(0,245,212,.06)" stroke="rgba(0,245,212,.4)" stroke-width="1.5"/>`。**fill 用对应色的低透明度 rgba，别用 `#0F1638`**（后者只用于圆形编号底）。
- **编号圆**：`<circle cx cy r="19" fill="#0F1638" stroke="色" stroke-width="2"/>` ＋ `<text text-anchor="middle" dominant-baseline="central" fill="色" font-size="17" font-weight="800">①</text>`。
- **页码片**：`<rect ... rx="14" fill="色" fill-opacity=".12" stroke="色" stroke-opacity=".55"/>` ＋ `<text ... font-family="ui-monospace,Consolas,monospace" font-size="13.5" font-weight="800">P 12</text>`。
- **顶部引路条**：`<text x="500" y="38" text-anchor="middle" class="tc" font-size="19">🔗 接第0N章…：… → 这一页做什么</text>`。
- **底部两行**：📦 本章成果 ＋ 🎖 过关标准，用 `<tspan font-weight="800" fill="色">` 做标签、`<tspan fill="#C8D0F5">` 做正文。
- **列宽算术**：1000 宽、左右各留 46 → 可用 908。两栏＝440＋440＋28 间距；四栏＝212×4＋28×3；五栏＝168×5＋14×4。**算完再写，别写出来再目测**。
- **viewBox 高度按内容算**，写小了内容会被裁掉（SVG 不报错，只是看不见）。
- **别用 `dy` 做副标题**：实测踩过——封面卡片的小字副标题写成 `y="300" dy="22"`，渲染后**压在卡片边框上**，像是排版事故。同一行多个 `<text>` 共享一个 y 值时，直接写最终坐标（`y="324"`），不要靠 `dy` 位移；`dy` 只在 `<tspan>` 里做同一 `<text>` 内的相对偏移才可靠。

#### 画「角色」类图示的三个几何坑（2026-09-18，成品四格漫画实测）

画动物／人物（企鹅、兔子这类）时，**小图看不出问题，必须放大渲染**（把该 SVG 单独抽出来、viewBox 收窄到 900 宽左右截图）。

1. **朝外的器官（鳍、翅、手臂）别画在身体轮廓线以内**。
   实测：身体最宽半宽 47，鳍片翅尖却画在 x=±44——比身体边缘还靠内 3 个单位，
   等于**完全藏在身体后面**，只有描边漏出来，读起来是「两只飘着的把手」（远看像戴耳机）。
   正解：翅尖外伸到 **±56**（约身体半宽的 19%），一眼能读出是翅膀。
   **判据：算「器官外缘 − 身体外缘」这个差值，小于半宽的 8% 就等于没画。**

2. **绘制顺序 = 图层顺序**。想让器官「长在身体上」，器官 path 必须写在身体 path **之前**
   （先画翅，再把身体盖上去，翅根自然被收口）；写在之后就会压住身体轮廓线，变成外挂的环。
   排查法：把该角色的 `<g>` 内子元素按出现顺序编号打出来，看器官排第几。

3. **眼睛要有瞳孔层**。只写 `<circle r="5.4" fill="#fff"/>` 会得到一对空心白圈，很空洞。
   补一层瞳孔 ＋ 一点高光即可：`<circle r="2.7" fill="#1B2350"/>` ＋ `<circle r="1.15" fill="#fff"/>`。

另外两条：

- **别用 `scale(x, -1)` 做左右翻转**：y 轴翻转会把五官、脚一起倒过来。要左右翻就用
  `transform="translate(x,y) scale(-s, s)"`（只翻 x），或干脆不翻。
- **辅助物要「挂」在角色上，不能飘**。跳绳弧的两端应落在角色手部高度：
  先算 `手部全局 y = 角色 y + (局部手部 y≈-30) × scale`，再定弧的两端坐标。
  实测原弧比手掌高 29–38 个单位，读作「飘在头顶的绳」而不是「两手间的绳」。

#### ⚠️ 别用 `<use>` 复用角色（会得到假光圈）

想省事把角色定义成 `<g id="peng">` 再 `<use href="#peng" stroke="色"/>` 换个色——
**不行**。给 `<use>` 设 `stroke` 只会重着色**被引用的最后一个元素**，其余部分保持原色，
渲染出来是一圈莫名其妙的假光环（实测远看像戴了耳机），而且每个引用点都得重新调色。
**正解：用 Python 辅助函数生成角色**，把色值当参数传进去，逐处展开成真实 markup：

```python
def peng(x, y, s=1.0, accent="#5CE082"):
    return (f'<g transform="translate({x},{y}) scale({s})">'
            f'<path d="{FLIP_L}" .../>'          # 器官先画
            f'<path d="{BODY}" fill="#05081A" stroke="{accent}" stroke-width="2.6"/>'  # 身体后画
            f'<circle cx="-11" cy="-44" r="5.4" fill="#fff"/>'
            f'<circle cx="-10.2" cy="-43.4" r="2.7" fill="#1B2350"/>'
            # …眼睛高光、喙、脚
            f'</g>')
```

展开后的 HTML 里搜不到 `peng(`——它是生成期的函数调用，不是页面里的标记。
排查时要在 **Python 脚本**里找 `peng(`，在 **HTML** 里找展开后的 `<path d="M0 -80 C-32 -80…`。

### 3.4 `.prompt` 指令框（有 AI 使用点的页才挂）

```html
<div class="prompt"><div class="ph">🤖 【工具名】 · 【用途】 · 指令【N】</div><div class="pc">整段可照抄的提示词，用 <span class="k">青色</span> 标要改的字段，<span class="v">紫色</span> 标「要求：」，<span class="warn">黄色</span> 标「负面要求：」</div></div>
```

- **指令编号全课连续**（①②③④⑤），与附录 A 的 AI 使用点地图一一对应。
- `.pc` 里换行**要真的换行**（栏内 `white-space:pre-wrap`），别全挤一行。

- **三段不必都写**：总览页常只留 `twarn` 一段，附录 C 留全三段。**宁少勿凑**。

- `.tl` 标签固定写 `🗣 口播` / `🎬 操作` / `⚠️ 提醒`，别自造。

## 第 4 步：内容红线

### 4.0 双轨锁步（硬规则）：课件 ＋ 学案 必须同步改

- **任何一处教学内容改动，两份都要改，且改在同一页同一处**。改完在回复里报清改了哪两份的哪几处。
- **唯一允许的差别**：课件有 `.tnote` 说课与 SVG 图示（给学生看的版本不需要）；学案有空白填写格与打印说明。除此之外——示范角色、章节结构、成果名、过关标准、五问、展板五块、AI 使用点——**必须逐字对应**。
- **改前先查跨页引用**：课件里的「填学案第 N 页」、学案的「见第 N 页」、附录里的页码片，全都是可证伪的断言。**动任何页码前先 grep 全部指代**。
- 改动多时**逐条串行发 Edit**，不要在一条消息里并行批量（并发写会互相覆盖，且全报 success）。

### 4.1 去 AI 腔（交付前必跑一遍）

读者是老师和学生，**任何一句读起来像咨询 PPT / 制度文件 / 教科书的话都要换掉**。

| 腔调 | 病灶 | 换成 |
|---|---|---|
| 咨询腔 | 「层」「维度」「颗粒度」「闭环」「链路」「抓手」「赋能」「沉淀」 | 说人话：`层` → 直接说是什么事；`闭环` → 有头有尾 |
| 公文腔 | 「落地」「载体」「该组」「核心目标」「统筹」「把控」「进行」 | `落地` → 做完 / 做齐；`该组` → 那一组 |
| 教科书腔 | 「本章」「本节」「上述」「此外」「同时」 | `本章` → 这一章；**面向学生一律用「这一章」** |
| 元描述腔 | 在讲「这份文档是怎么组织的」 | 直接给指令 |
| 标语腔 | `**A**　｜　**B**` 双栏口号、`**A** —— **B**` | 拆成正常句子 |

- **尾巴上的补语最容易露馅**：`A，才叫 B` / `A，那才是 C`——删掉补语或改直陈。
- **`不是 X，是 Y` 少用**，改成正面陈述。**但真实对比要保留**（「四个格子＝一篇完整的作品，不是四张画」是在纠正误解，不是修辞对偶）。**判据**：把 Y 删掉，读者会不会误解？会 → 是真对比，留；不会 → 是修辞对偶，改直陈。
  - 实测改法（2026-09-18 四格漫画课）：口播「它不是为了好看，是为了让读者一眼看懂情绪」→「漫符就一个用处：让读者一眼看懂情绪」；「这门课的核心不是会用某个工具，是会不会…」→「这门课真正要练的，是…这两样。工具是顺带的」。
- **一门课只改确有 AI 味的句子，别整篇重写**：本轮全五件过一遍，课件 30 页里实际只动了 4 处口播＋3 处短句＋2 处错字。散文改动越少，跨文件口径越不容易跑偏（§4.0 双轨锁步）。
- 改完**必须 Read 几段实际内容**：计数只能保证「没有那些词」，保证不了「读起来像人话」。
- **顺带查繁简错字**：手写 SVG 里的文字最容易混入繁体（本轮「额角**掛**一个汗滴」两处）。用一个繁体字黑名单扫可见文字即可定位。
- **上表只是起点，不是全部**：用户说「不要 AI 味道太浓重」时，按 **§5.16** 走整套流程（dump 全文 → 四类病灶分类 → 脚本批量替换 → 复扫）。本次实测 5 件里挖出 30+ 处，其中一半不在上表词库里。

### 4.2 说明性文字一律不进正文（硬规则）

口径声明、方法论自述、「我是怎么做的 / 可信度多高」的元叙述、表格前后的导语与收尾——**一律不进正文**。判断标准：**删掉这句，读者还能不能看懂？能看懂就删。**

- 需要的口径归属放到文档头部的信息区一句带过；**审阅建议类免责语连头部也不放**。
- **自指栏目**（讲「我们」的那一栏）用汇报者语体，不用公文语体：自称统一写「**我们**」，整栏不出现「我方」；叙述主体是**人**，不是文档、也不是「本次调研」这个流程。

### 4.3 术语要给白话定义，不能拿同义词当解释

交付物里出现行业词，第一次要给「**是什么 ＋ 为什么叫这个名**」，让非本行业的人能用自己的话复述。
「我们走的是『先在一所学校做试点』这一类」这种同义改写**不算解释**——词换了个说法，外人依旧不知道它指什么。

### 4.4 AI 类课的专属红线

- **全课 AI 使用点数量写死**（如五处），附录 A 画成地图，各带页码片。**数量以外的环节一律不动 AI**，这条要在说课里讲死。
- 每处都是「**它出参考、你做决定**」：让 AI 出 **5 个候选 / 5 组方向**（不是 1 个，一个就没得挑）；审稿那一步**只提问、不给答案**。
- **四条红线**（可换词但不可省）：原创角色 ／ 无真人肖像 ／ 无侵权画风 ／ **AI 图必须标注「AI生成·示意图」**（手绘成稿不标，只有 AI 出的图要标）。
- **教师控点 4 条**必盯：不许照搬 AI 成品 ／ AI 图必须标注 ／ 失败稿绝对不能删 ／ 解法不许违规。每条都要写**出事怎么处理**。
- **缺网预案三条**：上不了网→老师统一投屏、学生只做思考筛选记录；没有绘图 AI→纯手绘，参考图那一步整章跳过；没法实体布展→换班级线上漫画展，展板照旧只换载体。
- **V1 失败稿绝对不能删**：丢了的组用照片或组员复述重建一版，不许直接跳到 V2。展板少这一块等于把最难的部分藏起来。

### 4.5 课堂语汇红线

面向学生的内容**禁用职场语汇**（下班、交付物、交期、结营、复盘、立项、干到），一律换课堂说法。
**每章只写「这一章」**，不写「本章」（面向老师的说课块里可以放宽）。

## 第 5.5 步：改造已有课件去对齐另一套模板（「换装」路径）

有时不是从零做，而是**手上已有一份内容齐全的课件，要把它套进另一套已成熟的版式**（例：四格漫画简版 → 对齐 AI 小记者简版的样式规范）。这不是重写，是**结构对齐**；判据是「两份文件的 CSS 体系是否同源」。

### 5.5.1 先做差异审计，别急着手改

1. 把两份文件都读完，逐条比对这五处：
   - `:root` 变量表是否同一套；
   - `:root` 之后的组件类（`.page`/`.hero`/`.cap`/`.tnote`/`.prompt`/`.part-banner`/`.stepchip`/`.todo`）是否都有；
   - 外层包裹类名（`main` vs `mainwrap`）；
   - 页面解剖顺序是否一致（`page-head → hero → cap → prompt → todo → tnote`）；
   - 参考件**用了但没定义**的类（本次发现 `rankchip` 裸用无 CSS）——顺手补上。
2. 审计结论通常是：**CSS 同源，要改的是骨架、外壳类名和文案粒度**，不必动视觉。
3. 把「参考件的硬规则」提炼成一张检查表（本次 14 项：页码连续／零外链零 JS／SVG 内无 `<b>`／标签配平／导航锚点命中／每页 cap 与 tnote 各一／说课三段齐备／保命句在场／短句最长语义段 ≤14 字……）。

### 5.5.2 用脚本改，不要手改长文件

2000＋行的课件手改必出错。**全部改动走 Python 脚本**（本机 Python 路径见 §环境）：

| 改动 | 做法 |
|---|---|
| 外壳类名换代 | `s.replace("<main>", '<div class="mainwrap">')` ＋ CSS 选择器同步改名，含 `@media` 里的 |
| 脏 class 值 | 精确串替换掉多余空格（本次 `class="page-num "`） |
| 补缺失 CSS | 找锚点字符串插入（本次插在 `/* ---- 档一：动作层 ---- */` 之前） |
| 文案改写 | 建 `(旧串, 新串)` 表逐条 `replace`，**先判命中再替换**并把未命中项打日志，不要盲替 |
| 缺段补齐 | 用 `re.compile(..., re.S)` 定位 `(section 头 → 目标段)` 之间，在正确位置插入 |
| 压空行 | `re.sub(r'\n{3,}', '\n\n', s)` |

**三轮迭代法**（本次短句治理实测有效）：改一轮 → 跑体检 → 把剩余超限项列出来 → 再改一轮。41 条 → 21 条 → 3 条 → 全绿。一次想改干净反而容易改漏。

**⚠️ 改学案前必看：学案是 CRLF，课件是 LF**（2026-09-18 踩的坑）。规则：

- 读学案用 `io.open(p, encoding='utf-8', newline='')`，写回也用 `newline=''`，否则换行被转成 LF 或 `\r\r\n`。
- **替换串一律不要带 `\r\n`**，只匹配行内片段（`<td class="l">画面（一句话）</td>` 这种）。
  带 `\r\n` 的串一旦缩进对不上就整条 miss。
- **别猜标记**：第一遍脚本猜 `class="c"` / `<th>` 全没命中，实际是 `class="l"` ＋ `<tr><td>`。
  正确姿势是**先导出 `_wbraw.txt`（逐 `<section>` 原样打印）看真实标记，再写替换表**。
  本次第一遍 53 处 miss、第二遍 73 处全中零 miss，差别就在这一步。
- 每轮跑完打印 `未命中项` 列表，**miss 不为空就不要往下走**。

### 5.5.3 短句长度按「最长语义段」量，不是整串字符数

设计规范说「每条短句 ≤14 字」，量法要抠准：

- `.cl` 里若是**分隔符列表**（`·`／`→`／`；`／`——`），按**最长那一段**计，不按整串。写 `看得懂 · 有冲突 · 有转折 · 说得清` 视觉上是四个短块，合规。
- 单段（无分隔符）才用整串长度。
- 量之前先剥标签、剥空白：`re.sub(r'<[^>]+>','',t)` ＋ `re.sub(r'\s+','',t)`。
- **实测口径**：参考课件（AI 小记者 85 页）超限 **0 条**，是硬标准；改造前源文件超限 41 条。两边一比就知道差在哪。
- 压不下就**拆成两条 `.cl`**（`<div class="cl">A</div><div class="cl">B</div>`），`.cap` 本来就是纵向 flex，拆了不破版式。

### 5.5.4 说课三段的「允许缺段」要判清楚

章节制课件的**章总览页**天然只有 ⚠️ 提醒（它是路线图不是内容页）。这**不算缺**——但本次仍给它补齐 🗣 口播 ＋ 🎬 操作，理由是投影时老师照讲更顺。**该补还是该留，看这一页上课时老师要不要开口**：要讲→补，纯结构页→可留空。别机械地一刀切。

### 5.6 把「手绘课」重构为「AI 出图课」（2026-09-18 立项，硬流程）

**第一步：先访谈锁四件事**（AskUserQuestion，每项都要她拍板，别自己猜）：

### 5.7 整链换范例（如「以这张漫画为示例，重塑课程」）（2026-09-19 定，硬流程）

用户拿一张参考漫画说「以这个为示例重塑课程」时，先分清是**换骨**还是**换范**：
`结构动没动`一句话定生死。默认按**换范**做——页数、章段号、章节横幅、过关标准全部不动，
只把范例的故事整链替换掉。先 AskUserQuestion 问三件：**① 只换范例还是连结构也改；
② 用哪张图当新范例；③ 新范例里那些「与旧课重点不同」的规则（如某格故意不带气泡）要不要升为课程重点**。

**第一步：先用关键词清点旧范例出现了几页。** 别凭印象，一条命令拿到全图：

```python
kws = ['<旧角色名>','<旧物种>','<旧标题>','<旧道具>','<旧地点>','<旧数字>','<旧配角>']
# 逐 section 扫，打印「页号 + 各词命中数」，得到一张「受污染页清单」
```

典型结果：31 页里 **11 页**含旧范例（成品欣赏／成品解剖／角色卡／四格分步 4 页／
标题示范／漫符页／教师页示范链 等）。拿着这张清单再动手，避免改一半漏一半。

**第二步：把新范例的事实链先钉死成一张表**（后续所有页面都从这张表取词）：

| 项 | 取值 |
|---|---|
| 角色外形（要能直接粘进 Prompt） | 例：黑发少年，深蓝校服 ＋ 白衬衫 ＋ 红领带，五官与画风全程保持一致 |
| 配角外形 | 例：棕中长发少女，深蓝校服 ＋ 白衬衫 ＋ 红领结 |

| 尺寸口径 | 例：16:9 横版单页里的第 N 格 |
| 四格职能 | ①起… ②承… ③转… ④合…（每格一句，与页内底栏、学案表格、教师页链**三处同字**） |
| 标题 | 例：《清晨冲刺》——预告型，不说结果 |
| 负面词 | **用户给的原串照抄**，别自己改写 |

这张表一旦定了，**四格职能那一行是全文出现频率最高、最容易前后不一致的地方**
（p02 底栏 / p07 解剖 / p12·p15·p18·p21 分步页 / 学案第 2 页表格 / p31 示范链），
写替换脚本时把它当唯一真源，各处从它派生。

**第三步：分刀批处理，按「块从大到小」写脚本**。经验刀序：

1. **成品欣赏页的整块 SVG**（最大块，直接按 `<!-- 格① ... -->` 到 `<!-- 底栏 -->` 整段换）；
2. 各页**正文文案**（cap / todo / `details.tnote` 三段）；
3. **四格分步页 ＋ `.prompt` 指令框**（每格「✅这样出图 / ✕不要这样」两卡、例句、说课三段）；
4. **标题示范页 ＋ 漫符页指令③ ＋ 教师页示范链**。

每刀跑完立刻打印 `miss` 计数和残留词扫描，**零 miss 才写盘**。别攒到最后一起看。

**第四步：学案（第 2 件）单独一刀，注意它是 CRLF**（见 §5.5.2）：
成品解剖表、角色卡示范行、第 4/5/6 页 Prompt 示范行、「正确方向」、标题示范行，逐条换。

**第五步：重画 SVG 时预留「多轮目视校图」的预算 —— 一次画不好，这是常态。**
本机实测需要三轮：

- **第一轮常见病**：小人缩放取 0.6–0.8、眼睛只有 3–5px，渲染出来是**抽象色块**，认不出人。
  正解：主体人物缩放取 **0.9–1.0**，并把人物拆成**可复用函数**（`head()` / `body()` /
  `girl_full()` / `teach_full()`），眼距、脸宽、头发轮廓都做成参数。
- **第二轮常见病**：两个人物**互相压住**；扶额的手**没落在额头上**；刘海**盖住眼睛**。
  正解：远景人物压到 **0.70 并挪到讲台/道具之后**；手部用独立 `circle` **画在额角坐标上**
  （不要指望手臂路径的终点对）；刘海弧线的下沿要**高于眼睛 y**。
- **第三轮常见病**：气泡尾巴**没指向说话的人**、同一格文字与图抢位置。
  正解：气泡尾巴的三角坐标**从说话人头顶坐标反推**，别凭感觉给。

**第六步：收尾三件**（缺一不可）：

```powershell
# ① 全篇体检（应为 FAIL=0 / WARN=0 / SKIP=0）
& "<python>" "…\scripts\check_brief_course.py" "<课件>" "<学案>"
# ② 重跑派生件（**不加 --config**；加了而 config 不存在会 FAIL 在第 4 件）
& "<python>" "…\scripts\fourpiece\fp_run.py" "<课件>" "<输出目录>"
# ③ 五件套全文扫旧范例关键词，必须全 0
```

`fp_run.py` 的参数是 `<课件> <输出目录>`（位置参数），`--config` 是可选项。
**若项目里没有 `a6-config.json` 这类配置文件，就别传 `--config`** —— 传了会在生成第 5 件时报
`FileNotFoundError`，而前三件其实已经成功，容易误判成整体失败。

**「该静就静」这类规则的处置**：新范例里若有与旧课重点不同的设计（典型：某格故意不放气泡），
**默认按现有位置带过，不升为过关标准**——它属于「画法细节」，升为关卡会把课程重心带偏。
但要在两处点一下：① 该页 `.prompt` 的「要求」里写明「本格不要出现任何文字气泡」；
② 该页说课「⚠️ 提醒」里加一句「豆包爱自作主张加字，多了就把这句写进要求里重出」。

### 5.8 成品欣赏页嵌「真实出图」替换手绘 SVG（2026-09-19 定，硬流程）

用户做完课，自己用豆包出了一张真图，说「把这张图插在 XX 位置」时走这条。
**先 AskUserQuestion 问三件，别自决**（三件都会改变结构，猜错要返工）：

1. **插图方式**——① **整块替换 `<svg>` 为 `<img>`**（最干净）；② **在现有 SVG 里嵌 `<image>`**
   （保留自绘卡片外框与底栏，与全站风格连成一体）。**用户本次选了 ②**。
2. **页面自绘的标题栏与底栏是否保留**——图片自带标题时，页面再画一遍就重复。
   用户本次选了**删页面标题栏、保留底栏四行职能**。
3. **水印与图内短句怎么处理**——AI 出图常带「豆包AI生成」水印，与课程规范「无水印」冲突。
   用户本次选了**原样插入不裁**（此时课程正文里不写「无水印」这条要求，别去挑图的水印毛病）。

**第一步：图别引用临时区。** 剪贴板来的图在 `~/.workbuddy/clipboard-images/`，
**这是临时区会被清空**，必须先 `shutil.copy2` 进项目（推荐 `<项目>/img/<名>.jpg`），
HTML 里用**相对路径** `img/清晨冲刺.jpg` —— 这样课件与学案同目录、可整卷移动。

**第二步：<svg> 数字怎么定。** 用 JPEG 尺寸算等比高度，别凭感觉：

```python
def jpeg_size(p):          # 从 SOF 段读宽高，别依赖 PIL
    ...                    # 返回 (w, h)
w, h = jpeg_size(dst)
IW = 908.0                 # SVG 内容宽（画板宽，与全站一致）
IH = IW * h / w            # 等比高
VBH = IY + IH + 152        # 底栏三段共占 152 → viewBox 高
```

实测算例：图 1920×1078 → `IH = 509.8`，`VBH ≈ 676`（圆整即可，SVG 会自适应）。
**viewBox 高一定要跟着重算**，写死旧值会把底栏挤出画布。

**第三步：两个渲染坑（本机 Edge 实测）。**

- **`clip-path: inset(0 round 12px)` 对 `<image>` 不生效**，图片四角是直角，与卡片圆角打架。
  正解：改用 `<mask>` 包一层圆角 `rect`：
  ```html
  <mask id="p02round"><rect x="46" y="14" width="908" height="509.8" rx="12" fill="#fff"/></mask>
  <image href="img/…" x="46" y="14" width="908" height="509.8"
         preserveAspectRatio="xMidYMid slice" mask="url(#p02round)"/>
  ```
- `preserveAspectRatio` 用 **`slice`**（等比铺满＋裁边），别用 `meet`（会留白边）。

**第四步：图片四周要留出`<rect>` 底边间距**：画板 `rect` 的高度取 `IH + 8`，
图片只占 `IH`，这样图下沿与画板下沿之间有 4px 深色余量，不会「图贴边」。

**第五步：换了图，**说课与正文的口径要跟着对一遍**——这是最容易漏的。
本例踩到：原说课口播写着「这是**上一届同学做完**的一张四格」，而图是本次 AI 出的成品，
口径直接矛盾。正解：去掉「上一届同学」这类**归属陈述**，改写成
「这是一张做完的四格 …… 图是逐格生成、再拼起来的一张 16:9 横排成稿」。
**凡引用范例出处的句子，换图后逐句复核。**

**第六步：底栏职能行要与图片画面对得上。** 举例：页内底栏写「② 教室门口，喊一声报告」，
而 AI 出的格②顶上是窗、右下是门框、学生背影扶门框面对讲台——**窗口就是门框**，
文字与画面能圆上，就不用改底栏；若对不上（如图里格③还有气泡），**底栏必须跟着图改**，
不能留旧文案。

### 二、例栏组件（HTML 层）


```css
.exbadge{flex:0 0 auto;display:inline-block;padding:3px 9px;margin-right:10px;border:1px solid rgba(0,245,212,.62);border-radius:6px;background:rgba(0,245,212,.10);color:var(--cyan);font-size:12.5px;font-weight:800;letter-spacing:.5px;line-height:1.5;white-space:nowrap}
```

- **`align-items:center` 而非 `flex-start`**。例栏是一行短句，居中比顶对齐干净。

### 三、成品图上的标签怎么放（SVG 层）

成品图整块是 `<svg>`，HTML 标签写进去无效；**而图下方那行「范例《XX》」本身也是 SVG `<text>`**，

1. **别放在画板矩形内部**——图片用 `<mask>` 铺满画板，标签会被图片盖住（或与白底打架）。

### 五、例标必须带内容，不能只写「【例】」两个字（2026-09-19 追加，重要）

**用户原话**：「提示词的例可以写为【例：黑发少年，深蓝校服 ＋ 白衬衫 ＋ 红领带，五官与画风全程保持一致。】全文都改」。

| 层 | 改前 | 改后 |
|---|---|---|

## 5.12 去圈码：删装饰性的，留功能性的（2026-09-19 定）

「这个符号不要了」这类反馈，**先判它是装饰还是功能**——判错会连表格行项编号、
查找用索引一起删掉。本次用户只圈了一处封面格内的「①」，但同类标记全文有 49 处。

### 一、判据：删了之后，这一处还找得到吗？

| 形态 | 例 | 判定 | 理由 |
|---|---|---|---|
| **同一位置已有编号，圈码是重复** | 封面格：角上已有 `1/2/3/4` 圆号，格内又写 `① 起` | **删** | 编号只该出现一次 |
| **导航条：圈码＋名称** | 章总览页顶部进度条 `① 场景 ② 起 …⑦ 漫符` | **删** | 横幅已有章名，圈码是冗余装饰 |
| **查找用索引表** | 附录 A 速查表左列 `① 选场景 / ② 起 …` | **留** | 速查表靠编号定位，删了就不好翻 |
| **正文行项编号** | 过关标准 `① 标题没说破结局　② 全组人们都说得清…` | **留** | 这是 `ol` 的替代写法，不是装饰 |
| **表格行项编号** | 学案填表页 `① 起　他在哪、在干什么：___` | **留** | 学生要对着格号填，编号是功能 |
| **格号指代** | 正文 `第①格图`／`第③格：让事情变` | **留** | 指「第几格画面」，是全课通用叫法 |

一句话：**编号承担「定位」职能就留，只承担「好看」职能就删。**

### 二、删的时候要连布局一起调

进度条标签删掉圈码后，文字从 3 字变 2 字（`① 场景`→`场景`），
靠 `text-anchor="middle"` 居中即可自动居中，**不必改 x 坐标**。
但封面格内那处字号要放大补回视觉重量：

```python
# 原：font-size 17，文字「① 起」（3 字符宽）
# 新：font-size 19 + letter-spacing 1，文字「起」（1 字符宽）
'<g text-anchor="middle" font-size="17" font-weight="800">'
→ '<g text-anchor="middle" font-size="19" font-weight="800" letter-spacing="1">'
```
y 坐标也要 +1（`296`→`297`）——字号变大基线会偏，肉眼看得出来。

### 三、批量改法：只正则匹配圈码＋名称，不要全局替换「①」

全局替换「①」会把表格行项编号一起打掉。**必须带上下文匹配**，
用 `font-size` 值把「进度条标签」和「正文行项」分开：

```python
pat = re.compile(r'(class="(?:tc|tn|to|ty|tf)" font-size="1[23](?:\.5)?">)'
                 + re.escape('① 场景') + r'(</text>)')
s, k = pat.subn(lambda m: m.group(1) + '场景' + m.group(2), s)
```
进度条标签都在 SVG 里、字号 12.5/13/13.5；正文行项在 HTML 文本节点里、无字号。这是最稳的区分。

### 四、收尾

1. 残留自检用带上下文的 patterns，**不要**用裸 `s.count('①')`——
   保留项本来就有几十个，计数法只会误报。
   ```python
   re.compile(r'class="(?:tc|tn|to|ty|tf)" font-size="1[23](?:\.5)?">[\u2460-\u246F][^<]*</text>')
   ```
2. 重跑 `fp_run.py`——md 里的进度条是文字化输出，不重跑就不一致。
3. 渲染抽查：**进度条那一页**（看删圈码后是否还居中、高亮格是否仍可辨）＋ 封面页。

## 5.14 页头加「本章第几页 / 本章共几页」位置标识（2026-09-19 定）

用户指着页头说「这个地方再加一个每章页数位置的标识，比如 1/4，1 代表每个章节当前的位置，4 代表该章节的总页数」时走这条。

### 一、先盘清「章 → 页」映射，别边改边数

```python
# ① 横幅位置 + 中文名（名字在横幅后第一个 .pnum 里）
bans = [(m.start(), re.search(r'<div class="pnum[^"]*">([^<]*)</div>', s[m.start():m.start()+600]).group(1))
        for m in re.finditer(r'<div class="part-banner" id="([^"]+)">', s)]
# ② 每页位置
pages = [(m.start(), m.group(1)) for m in re.finditer(r'<section class="page" id="(p\d+)">', s)]
# ③ 某页归属 = 在它之前最近的一条横幅
```
本次实测：序章 3 ／ SECTION·先认识 4 ／ 选场景主题 5 ／ 起承转合各 3 ／ 补标题 4 ／ 附录 3 ＝ **31 页**。

### 二、`.page-num` 带颜色类，正则别写死（本次第一个坑）

页头三件看着一样，实际 `.page-num` 有 **4 种形态**：裸 `page-num`（11 处）＋ `page-num purple`（10）＋
`page-num orange`（6）＋ `page-num yellow`（4）。写 `class="page-num"` 只命中 11 处，剩下 20 页静默漏掉。
**正解：`class="(page-num[^"]*)"`**，并在重建时把捕获到的类名原样写回。

### 三、组件与样式

插在 `.stepchip` 与 `.page-title` 之间，`title` 属性给无障碍：

```html
<span class="poschip" title="本章第 1 页 / 共 4 页">本章 1/4</span>
```

```css
.poschip{font-family:"JetBrains Mono",Consolas,monospace;font-size:11.5px;font-weight:700;
 letter-spacing:.5px;padding:3px 9px;border-radius:6px;
 border:1px solid rgba(0,245,212,.55);background:rgba(0,245,212,.10);
 color:var(--cyan);white-space:nowrap;flex:none}
.poschip::before{content:"本章 "}
@media print{.poschip{display:none}}
```

**「本章」二字用 `::before` 注入**，不写进 HTML —— 数字变的时候不用管前缀，且 CSS 里改一次全站生效。
**视觉上必须与 `.stepchip` 拉开**：`stepchip` 是**灰虚线**（动作层标签），`poschip` 用 **cyan 实线 ＋ 半透明底**
（进度层），两枚并排时一眼分得清。`white-space:nowrap` ＋ `flex:none` 照抄 `stepchip`，防止长标题把它压变形。

### 四、写脚本的两个细节

- **`page-head` 里没有 `pid`**，无法从匹配文本反推是第几页。正解：先取
  `ordered_pids = [pid for _, pid in pages]`，再在 `finditer` 循环里用 `idx` 顺序取 —— 页头与
  `section.page` 的出现顺序必然一致。
- **计数断言会撞 `@media print`**：`out.count('.poschip{')` 得到 2，因为打印规则里也有
  `.poschip{display:none}`。断言要按 **2（主规则＋打印规则）** 写，或干脆单独断言
  `.poschip::before{` 与 `@media print{.poschip{display:none}}` 各 1 处（本次后者更稳）。

### 六、同一天就被撤回：装饰性标识要做成「可一键撤」（2026-09-19 实测）

不会的话，**先做但一定做成可一键撤**。

```python
body_end = i7 + k_end + len('</section>')
```
`page_block()` 这种「找下一个 section」的辅助函数**只能用来读内容，不能用来定删除边界**。

**三、删页之后必须全文重排的四样：**

1. **页脚**：`第 N 页 / 共 M 页`——逐页重编号，总数 −1。
2. **章段号**：按横幅分段重编 `n.m`。**注意章序号是「横幅序号」不是「数组下标」**
   （序章 0.x／认识篇 1.x／其后 CHAPTER 从 2.x 起），删一页只影响**该章内部的 m 与后续章**，
   章号 n 通常不变 —— 本次删 1.4 后序列是 `0.1 0.2 0.3 1.1 1.2 1.3 2.1 … 8.3`。
3. **该章的 stepchip**：认识篇原写「认识 n/4」，删一页后全部改 `n/3`。
4. **横幅 pdesc**：本次「定义 · 特点 · 例子 · 成品，**四页看完**」→ 去「成品」、改「三页看完」。

**四、被删页上的作业不能跟着消失，要改挂。** p07 原来布置「学案第 2 页最后一栏写四格各干了什么」，
删页后这道作业没了着落 —— 但学案那一栏还在（学案不跟着删）。
**处理：把这条件业挪到内容最贴近的存活页**（本次挪到 p02「先看成品」，本来就在看那张图），
并在该页说课的「🎬 操作」段补一句指路。**判据：作业挂在哪页，取决于学生做它的时候眼前是什么图。**

**五、删页必然暴露一批「上次没改干净」的旧口径 —— 顺手清掉。** 本次删页后扫「七」，挖出 5 处残留：
`meta description` 的「七个流程章」、两条横幅的「七个流程」、时间片的「七章走完」、
**页脚的「配套《漫画社学案》A4 共 10 页」（学案早已是 9 页，漏改好几轮）**。
**做法：删页后全文扫「上一轮删掉的那章的数字」**（本次删过漫符章，「七」就是这批的尾巴）。
扫词法：`for m in re.finditer(r'.{0,50}七.{0,50}', s)` 打全上下文，逐条判。

（`pages=` 应等于新页数）＋ 渲染抽查（改了 SVG 的页 ＋ 承接作业的页）。

## 5.16 全文语言审读：去 AI 腔 ＋ 去贬损词（2026-09-19 定，硬流程）

用户说「**从全文视角帮我审视，不要 AI 味道太浓重，语言要通俗易懂且专业，适合教学场景**」
这类话时走这条。**不是逐句润色，是先把全文 dump 出来分类，再一次性脚本改。** 本次实测
课件 30 页 ＋ 学案 9 页 ＋ 三件 md，共改 30+ 处，`check_brief_course.py` 与五件复扫全绿。

### 一、先 dump 全文可见文字（含说课），别翻页找

一步到位：把课件（正文 ＋ SVG `<text>` ＋ `details.tnote` 说课）与学案分别导出成纯文本，
一行一句，再通读。**说课必须一起 dump** —— 讲师口播是贬损词与竞技腔的重灾区，只看正文会漏一半。
本次 dump 结果：课件 1118 行 ／ 学案 475 行 ／ 含说课 1330 行。

### 二、四类病灶（本次实际挖到的，按优先级）

| 类 | 例子（改前 → 改后） | 判据 |
|---|---|---|
| **贬损词** | `前面全白铺` → `前面三格就都空转了`；`这一格就白画了` → `这一格就等于没画`；`出图也是废图` → `这张图也白出了`；`画面会糊成一团` → `会乱成一团` | 教学场景里，**别用「白干 / 废」评价学生将要产出的东西**，改说「这一步没起作用」 |
| **网络语 / 竞技腔** | `别急着抖包袱` → `别急着制造意外`；`读者愣一下，你就赢了` → `读者愣一下，这一格就成了` | 有输赢、有梗的口语，换成描述结果的说法 |
| **AI 判断句** | `判断方法很简单——` → `就看一件事——`；`判断标准很朴素：` → `标准就一条：`；`判据只有一句：` → `就看一句话：`；`本质上是` → 直陈 | AI 爱在给标准前**先给标准下个评价**（「很简单」「很朴素」「只有一句」）。**去掉评价，直接给标准** |
| **抽象名词 / 公文腔** | `你们要交的是同一形态的东西` → `就是这样一个东西`；`核心目标一件都不会丢` → `该练的东西一件都不会丢`；`全篇的关节` → `整篇的转折` | 见 §4.1 表；**「关节」「形态」「核心目标」是本次新挖出的，补进词库** |

**另有两条不同性质的，顺手一起改：**

- **刻意对仗的格言腔**（`.motto` 与页内金句）：`圆满收尾最没劲` → `一下把事办圆，故事就平了`。
  motto 允许精炼，但不该是**为对仗而生的空话**；改成陈述一件具体的事，力度反而更强。
- **元叙述**：`本文档` → `这份合集`（少自指）；`本报告 / 如上所述 / 需要注意的是` 一律删或改直陈（§4.2）。

### 三、`Prompt` 这类术语：不加白话解释（本次用户明确否掉）

用户对「给 AI 指令的术语加一句白话解释」的选择是 **「不加」**。理由：学案表格与说课里
`Prompt` 每次都带上下文（「写进第④格 Prompt」「外形写到能直接粘进 Prompt」），**语境已经说明白了**，
再加解释是重复。**判据：术语在句子里有没有自证？有 → 不加。**

### 四、说课句式：只换词，不改句式（本次用户明确要求）

讲师口播是**对着人讲话**，句式（短句 ＋ 破折号 ＋ 口语连接）本身是设计过的。所以：
**只动词，不动结构。** 本次只改了 1 处（`前面全白铺` → `前面三格就都空转了`），
其余口播原样保留。**不要以「更书面」为名把口播改成报告体。**

### 五、脚本写法（本次踩的坑）

替换串写文件、**不要用 `python -c`**（反引号 / 中文引号会被 shell 吃掉）。三条实践：

1. **同一个词在正文、SVG `<text>`、说课里各有一份，替换串要写全。**
   本次 `硬拧` 同时出现在 `<div class="cl">` 里（正文）、`<text>` 里（SVG）、`<p>` 里（说课）
   —— 带标签前缀的替换串匹配不到 SVG 版，要**补一组无前缀的变体**。
2. **替换前先 `assert s.count(a) == 1`**，计数不等于 1 就是上下文带了标签，改替换串。
3. **收尾断言用「词表归零 ＋ 骨架计数不变」双条件**：`assert '废图' not in s and s.count('section.page') == 30`。
   只查词表不查骨架，可能误伤结构；只查骨架不查词表，可能漏改。

### 六、后三件（md）必须再同步一轮

`fp_run.py` 派生出的三件 md（设计方案 ／ Prompt 合集 ／ 教师讲课稿）**是从课件再生成的**，
所以改完课件要**重跑 `fp_run.py`**；但**页脚那类只在 md 里存在的句子**（如讲课稿末尾的
`序章 ＋ 七章，每章以一件成果收尾`）派生产不出来，得单独再扫一遍。
**做法：改完课件 → 重跑 `fp_run.py` → 对三件 md 再跑一次同一张词表 → 有残留就补一轮。**
本次补了 3 处（讲课稿页脚旧口径、合集 `本文档`、三件共有的 `白画`）。

### 七、收尾

`check_brief_course.py`（FAIL=0 / WARN=0 / SKIP=0）＋ 词表复扫五件全绿
＋ 渲染抽查（改了 SVG 文字的页）。**词表复扫这一条是硬性的** —— 脚本查不出语言，
只能靠自建词表，而词表要随每次实践增补。

## 5.17 提示词与样例图对齐：漫符／气泡这类「画法约定」全篇统一（2026-09-19 定，硬流程）

用户说「**这个描述要与样例的第四个格子对应；全文使用的都是这个，所以要严谨，前后对应，不要乱改提示词**」、
或「**这个提示词中，加入需要呈现『XX』的气泡**」时走这条。

**根因**：样例图（成品图）是先做出来的，四格 Prompt 是后补的 —— 补的时候凭想象写，
于是同一格出现两套画法口径。**这类错不会让脚本报错，只能靠人看图比对。**

**本次是分两轮才修完的，这本身就是本条最该记住的教训**：
第一轮用户圈的是④格（Prompt 写「气息符号『呼——』」，样例图里实际是对话气泡「总算赶上了。」）；
第二轮用户又圈了②格（Prompt 写「**不要对话气泡**，喊报告用嘴型表示」，样例图里实际是对话气泡「报告」）。
**第二轮之所以要返工，是因为第一轮只改了用户圈出的那一格，没把对照表整表走一遍。**

### 一、先建立「样例图 ←→ 四格 Prompt」的逐格对照表 —— 每一格都要放大看图，别凭印象

样例图（成品图，在序章「先看一张做完的」页）＝**全篇唯一的画法基准**。
把每格的**视觉元素**列出来（气泡有没有／什么气泡／什么符号／几个人／在哪），
再与对应 Prompt 块的【画面】【漫符】【要求】【负面要求】逐条比。

⚠️ **填「一致」之前，先把那一格真正放大看一眼。** 本次第一轮就是在②格上凭印象填了「一致」，
把气泡看成了「手绘小竖线」，于是漏掉一处 —— 下一轮用户就为这一处回来了。

| 格 | 样例图里实际有的 | Prompt 原写 | 判定 |
|---|---|---|---|
| ① | 拟声气泡「唰——」 | 拟声词气泡「唰——」 | ✅ 一致 |
| ② | **对话气泡「报告」** | ✕ 三条小竖线；**不要对话气泡**，喊报告用嘴型表示 | ❌ **对不上**（第二轮修） |
| ③ | 无任何气泡（扶额） | 额角一滴汗；本格不要文字气泡 | ✅ 一致 |
| ④ | **对话气泡「总算赶上了。」** | ✕ 气息符号「呼——」 | ❌ **对不上**（第一轮修） |

### 二、四处连带（改一处要同时改四条，不然又出现新矛盾）

一处口径错牵出四条。以②格为例：

1. **【画面】**：`一只手扶住门框，正要开口` → `一只手扶住门框，张嘴喊了一句「报告」`
   —— 画面里的动作要和新加的气泡对得上，不能只改漫符、画面还写着「正要开口」。
2. **【漫符】**：`头顶三条小竖线表示急；不要对话气泡，喊报告用嘴型表示` →
   `少年开口喊一句「报告」，用对话气泡框住这句喊话，气泡样式与前后格统一；一格只放这一个气泡`。
3. **【要求】**：把气泡写成硬条件 ——「并给这个少年加一个**对话气泡**，气泡里写『报告』」。
4. **【负面要求】**：`多余箭头，气泡指向错误` → `多余箭头，多余气泡，气泡指向错误`。
   **原词与新口径直接打架**：一边要求「一格放一个气泡」，一边把「不要对话气泡」留在漫符里，
   模型会无所适从。**判据：负面要求里不许出现与正面要求同类的词，只能是它的「过量版」
   （要一个气泡 → 禁「多余气泡」）。**

④格同理（第一轮）：【漫符】换气泡、【画面】补台词、【要求】写硬条件、
【负面要求】`很多个符号` → `多余气泡`。

### 三、说课也要跟上（口播里要有对应的检查项）

Prompt 改了，讲师巡场的**检查项**得同步。两轮各加一条：

- ④格：「出图后重点看三样：人是不是明显坐下来了、旁边有没有一个自顾自低头翻书的同学、
  **他嘴里那句『总算赶上了』有没有落在气泡里**」。
- ②格：「出图后顺手看一眼气泡：**那句『报告』有没有写进去、气泡有没有指对人**」。

**判据：Prompt 里新增的硬条件，必须在说课口播里有一条对应的巡场检查项。**
⚠️ 源课件的说课若已改成「只有口播」一段（见 §5.18），检查项就直接写进口播，
不要去找「🎬 操作」段 —— 那一段可能已经被删了。

### 四、⚠️ 不要自己判「以脚本约定为准」的例外（2026-09-19 实证踩坑，硬规则）

**用户说「与样例图对应」时，样例图是唯一基准，不设例外。**

第一轮我给自己留了一个例外 —— ②格样例图上明明画了「报告」气泡，我却认为
「那张图是小助理按日常习惯生成的」，于是判定「喊报告用嘴型表示」是设计过的教学点、予以保留。
**结果用户第二轮就来纠正**：「这个提示词中，加入需要呈现『报告』的气泡」。

两条教训：

- **即使某处看起来像「更好的教学法」，只要与样例图不一致，就按样例图改。**
  真有疑虑，改完在回复里说明自己的顾虑，而不是擅自保留。
- **「这是刻意的设计点、不能改」这种判断，只能由用户下，不能由我下。**

### 五、四格气泡口径的最终状态（别顺手把③格也改了）

| 格 | 气泡 | 说明 |
|---|---|---|
| ① | 拟声词气泡「唰——」 | 画法约定，与样例图一致 |
| ② | 对话气泡「报告」 | 本轮加 |
| ③ | **无任何气泡** | **刻意的静默格** —— 靠额角一滴汗表达「卡住」，③格【要求】明写「本格不要出现任何文字气泡」 |
| ④ | 对话气泡「总算赶上了」 | 上轮加 |

**判据：①②④ 都有气泡，不等于③也要有。**
③格是「卡住」的沉默时刻，无气泡是设计点，与样例图一致，所以留；
②格那处「不要对话气泡」与样例图不一致，所以改。
**同样是「没有气泡」，一处该改一处该留 —— 判据只认样例图，不认「看起来是否整齐」。**

### 六、别乱改的边界

**只改对不上的那一处，其余原样不动。**

- **七段结构、字段名、`【例：…】` 包裹方式** —— 全篇统一的格式，一个字不动。
- **叙事性文字** —— 场景卡、附录备课链、SVG 分步图、成品图标签里的同一情节
  （如 p02 标签「② 承 · 教室门口，喊一声报告」、p10 场景卡「他追到门口，喊报告」），
  那是**剧情描述**，不是画法约定，保留原样。
  **判据：这处文字是在说「画什么」，还是「事怎么样」？** 说画法才改，说剧情不改。
  本次②格全文有 8 处「报告」，只有【漫符】那 1 处是说画法的，另外 7 处都不动。

### 七、改完的连带同步（同 §5.16 六）

`check_brief_course.py` → `fp_run.py` 重跑 → **三件 md 补扫** → 渲染抽查。

- 三件 md：「Prompt 合集」与「教师讲课稿」都带上了新口径；
  「设计方案」只记块的标题与页码、不含字段正文，**正确地无需改动** ——
  复扫时要看「这个文件本来该不该有这段文字」，不要为了凑数硬塞。
- 渲染抽查：说课面板展开时是**向上弹出的浮层，会盖住 Prompt 块的「要求／负面要求」两行**
  （模板固有行为，不是 bug）。所以**要截两张：展开态看说课、折叠态看那两行**，
  只看展开态就下结论会把被遮住的部分当成"没改"。

## 5.18 说课只留口播：删掉操作与提醒，并把要点吸收进口播（2026-09-19 定，硬流程）

用户说「**将说课里面的操作与提醒去掉，只留口播，全文都是。同时，口播内容要通俗易懂且专业，
前后语句连贯，不要跳跃**」时走这条。

**要改的不是课件一处，而是「课件 ＋ 三个派生器」四处** —— 派生器是照着源课件的说课段
逐个字段复制的，源里删了两段、派生器不改，出来的 md 就会留着「怎么带 / 要盯住」两行空壳，
或者干脆报错。**判据：源里没有的东西，生成器不许描述、不许留空标题、不许写「（待补）」。**

### 一、动手前先盘清「有多少块说课」，别边删边数

```
python -c "
import io,re
s=io.open(r'<课件.html>',encoding='utf-8').read()
for k in ['tseg tsay','tseg top','tseg twarn']:
    print(k, s.count(k))
print('section.page', s.count('<section class="page"'))
"
```

本次结果：`tsay=30 / top=30 / twarn=30 / page=30`。三个数相等才好动手 ——
**若 top 与 twarn 数量不一致，说明课件是半成品，先补齐结构再删**，否则删完对不上号。

### 二、删两段，但要点必须先「吸收」再删

**不要直接把 🎬 操作、⚠️ 提醒整块删掉就收工。** 那两段里写着教学要点
（巡场看什么、学生会在哪卡住、这一步为什么要这么安排），删了就丢了。正确做法：

1. 先把 30 条口播**全导出来**（`re.findall(r'<div class="tseg tsay">…')`），对着看原稿；
2. 再导**三段全文**到一份临时 txt，逐页读：这一页的「操作」在交代什么动作、
   「提醒」在防什么坑；
3. **把这两段的信息改写成口播的语气，并购进本来就该讲它的那句话里** ——
   不是另起一句「另外要注意……」，而是**接着上文往下说**。

本次示例（第 22 页，原来操作段写「巡场看两处」、提醒段写「别画成大团圆」）：

> ✕ 生硬拼接：这一格是收住的一格。另外要注意：巡场的时候看三处。
> ✅ 吸收进口播：……出图后重点看三样：人是不是明显坐下来了，旁边有没有一个自顾自低头翻书的同学，
> 他嘴里那句「总算赶上了」有没有落在气泡里；三样都在，这一格就收住了。
> 要是画成一团和气、大家一起笑，说明还没收住。

**判据：把「操作」「提醒」两个小标题去掉后，这一段念下来像不像一个人在连贯地讲话？**
像 → 吸收成功；中间出现「另外」「还要说一点」这种接缝 → 还是拼接，重写。

### 三、口播的四条硬标准（用户原话拆出来的）

| 标准 | 怎么落 |
|---|---|
| **通俗** | 不出现「核心 / 至关重要 / 赋能 / 抓手 / 闭环 / 维度 / 层面」这类书面词；用「关键 / 要紧 / 最要紧的」 |
| **专业** | 该有的教学判断必须留着 ——「Prompt 里有没有要求仿现成角色，那是一条红线」这种不能为了白话而删 |
| **连贯** | 一句接一句往下推，不跳 —— 上一句说的东西，下一句要接得住 |
| **不跳跃** | 同一个坑的「为什么」和「怎么办」要挨着说，中间不插别的话题 |

第 30 页（附录·备课页）例外：那一页是**教师向**的，口播用备课口吻（「备课时照示范链走一遍」），
不是对着学生讲。**判据：这一页投影给不给学生看？** 不投影的页，口播就是给老师自己的备忘。

### 五、三个派生器要跟着降级（本轮真正的坑）

源课件删段后，**派生器必须能「源缺段则整块跳过」**，否则 md 里会留下空标题。

**`fp_lecture.py`**（教师讲课稿）——三处：

```python
has_top   = any(((p.get("segs") or {}).get("top")   or {}).get("text") for p in pages)
has_twarn = any(((p.get("segs") or {}).get("twarn") or {}).get("text") for p in pages)
n_blocks  = 4 + (1 if has_top else 0) + (1 if has_twarn else 0)   # 六块 → 四块
```

① 「这份稿子怎么用」的表：`| 怎么带 |` 与 `| 要盯住 |` 两行改成 `if has_top:` / `if has_twarn:` 条件输出；
② 「最容易卡住的三个地方」那条提示（＝各页「要盯住」的汇总）也只在 `has_twarn` 时才写；
③ 正文里 `if top: A_("怎么带：%s" % top)` / `if twarn: A_("要盯住：%s" % twarn)`。
**「引导语」那行的说明词也要改** —— 原来写「可以直接照读，时间紧就只念这一段」，
在只剩一段口播时这句没意义了，改成「可以直接照读；一句话背后该做的事，都写在这一段里了」。

**`fp_prompts.py`**（Prompt 合集）——字段说明表原来硬编码三段：

```python
A("| 🎓 说课（🗣口播/🎬操作/⚠️提醒） | 给老师… | ❌ 不进图 |")   # 硬编码，要改
```

改成按源实际存在的段现拼：

```python
SEG_LABELS = [("tsay", "🗣口播"), ("top", "🎬操作"), ("twarn", "⚠️提醒")]

def seg_labels(pages):
    return "/".join(lbl for k, lbl in SEG_LABELS
                    if any((p.get("segs") or {}).get(k, {}).get("text") for p in pages)) or "🗣口播"
```

**`fp_design.py`**（设计方案）同理，把 `"分段为 🗣 口播 / 🎬 操作 / ⚠ 提醒"` 改成按 `page` 里实际
存在的 segs 拼（注意该文件的变量名是 **`D`** 解包出的 **`pages`**，不是 `data`）。

### 六、⚠️ 顺带踩到的旧坑：删过页之后，页码不能用 id 数字（本轮必修）

课件删过页时 id 会**留空号** —— 本次 `id` 从 `p01` 到 `p31`，但实际只有 **30 页**（删掉过 p07）。
`fp_extract.py` 的页序是这么产生的：

```python
ordv = int(re.sub(r"\D", "", pid) or 0)     # 直接抠 id 里的数字
```

于是 `fp_lecture.py` 用 `max(page_ord)` 当总页数会写成「对应课件 **31** 页」，
页脚也会跳号（…6 → 8）。**修法（两个派生器都要）**：

```python
total = len(data["pages"])                  # 总页数＝页数，不是最大页序
seq_of = {}                                 # 真实页序：按 id 排序后重编 1…N
for i, p in enumerate(sorted(pages, key=page_ord_raw), 1):
    seq_of[p["id"]] = i
gnum = seq_of.get(p["id"], page_ord_raw(p)) # 页脚用真实页序
```

`fp_prompts.py` 的写法是模块级 `SEQ` 字典 ＋ `build_seq(pages)`（在 `main()` 里先调），
`page_ord()` 优先查 `SEQ`、查不到才退回 id 数字；**原来的 `page_ord` 改名 `page_ord_raw`**
（它是排序键，不是页序），避免下次又有人误用。

改完复扫这几处（本次全部命中过）：

- 章节区间：`第 29–31 页` → `第 28–30 页`（附录）
- 逐页标题：`第 31 页 · 附录 C …` → `第 30 页 · 附录 C …`
- 讲课稿引言：`对应课件 31 页` → `30 页`；页脚 1…30 连续
- 待办表页号：`P31` → `P30`

**判据：任一派生件里出现的最大页码，必须等于课件页脚写的总数。** 不等就是还有一处没改。

## 5.19 成品收尾页：把分散的格子拼成一张（2026-09-19 定，硬流程）

四格是**逐格生成**的，学生手里是四张单格图，不是作品。全课最后一件事，是把四格拼成一张 16:9 成品页。用户说「**这样才算成品，学生完整的呈现了作品**」「在收官这还需要加入一页四格合并的提示词」时，走这一节。

### 一、先查缺口，再动手 —— 这一页往往「本来就该有」

别急着设计新页，先在全文搜一遍 `拼` / `拼接` / `成稿` / `成品` / `7.x`：
- 附录 A 速查表里若已列到「**⑦ 出成稿 · 四张图拼成一张**」，正文却没有对应页 —— 缺的就是它；
- 前面章节说课里若已写「等拼图时再打上去」「逐格生成、再拼起来」，说明这一步早被预告过；
- 开场页「N 件成果」**不一定要跟着改成 N+1 件**：收尾页是收束，不是新增一件交付物。

先把这一步在别处的口径摸清，再写新页；否则新页会和速查表、说课打架。

### 二、位置：收官页**之前**，不是之后 —— 且必须先问

拼成品是**动手工序**，验收是**盖最后那一枚章**。
- 放收官/验收页**之前**：出图 → 拼成成品 → 陌生人复述验收，工序不倒，且末页那句「这是最后一枚，全部流程走完」继续成立；
- 放**之后**：先盖章验收、再拼成品，工序倒置。

用户只说「在收官这加一页」时，**用 AskUserQuestion 先问插在哪一边**——这一问决定后面所有编号怎么走，猜错整轮返工。

### 三、插页的四项连带（一条都不能漏）

1. 新页章段号**接管**原收官页的号（本轮：新页 7.4「出成品」），原收官页**顺延**（7.5）；
2. 附录速查表里若该行现在跨两页，章号写成区间 `7.4–7.5`；
3. 页数 N → N+1：**全部页脚**的「共 N 页」改新总数；
4. 新页**之后**每一页的页脚序号 +1。

### 四、顺手重排 id，清掉删页留下的空号（本轮一并修掉）

早年删过页的课件，`id="pNN"` 会留空号（本轮 `p01…p31` 实际只有 30 页）。派生器 `fp_extract.py` 拿 id 数字当页序，空号会一路污染派生件页码。插页时**按物理序整体重排为连续 `p01…pN`**，一次把三套页码拉齐：

```python
SEC_RE = re.compile(r'<section class="page" id="p\d+"\s*>')
assert 'href="#p' not in s          # 有页内锚点就不能重排，先查
# 插入新页时占位 id 必须用【数字】（如 p90）
# ⚠️ 用字母占位（pNEW）会被 id="p\d+" 静默漏掉，重排时直接跳过 —— 本轮踩过
out, last, n = [], 0, 0
for m in SEC_RE.finditer(s):
    n += 1
    out.append(s[last:m.start()]); out.append('<section class="page" id="p%02d">' % n)
    last = m.end()
out.append(s[last:]); s = ''.join(out)
assert n == 31                      # 重排后页数
```

页脚 `.pf-n` 用同一手法按出现顺序重编为 `1…N`。重编后 `check_brief_course.py` 会直接报「**页码单调递增且无重号（p1…pN）**」，等于免费复核。

## 5.20 全篇口播凝练：删跨页重复、并同义句、控长度带（2026-09-19 定，硬流程）

用户说「**将说课的内容再帮忙优化下，语言通俗易懂且专业，能用一句话说完的不用两句话，
用词要凝练一些，从全文的视角**」时走这条。

与 §5.18 的分工：**§5.18 管结构（说课留几段），本节管文字（那一段怎么写）**。
两节常常连着来 —— 先按 §5.18 把三段并成一段，再按本节把这一个段压干。

### 一、先量基线，再动手 —— 别凭手感删

dump 每条口播的字数，算出四个数：条数 / 总字 / 最短 / 最长 / 均值。

```
python -c "
import io,re
s=io.open(r'<课件.html>',encoding='utf-8').read()
segs=re.findall(r'<div class=\"tseg tsay\">.*?<p>(.*?)</p>', s, re.S)
L=[len(re.sub(r'<[^>]+>','',x)) for x in segs]
print(len(L), sum(L), min(L), max(L), sum(L)//len(L))
"
```

本次基线：**31 条 / 5922 字 / 最短 98 / 最长 280 / 均值 191**。
**长短差到 2.8 倍就是病灶** —— 不是「有的页内容确实多」，是长的那几条里塞了
不该由口播承担的话（重复的通则、操作的复述、同义铺垫）。

改完复测：**31 条 / 4449 字 / 最短 74 / 最长 190 / 均值 143**（-25%）。

### 二、定长度带（本课定 70–190 字，均值 ≤150）

| 页型 | 长度带 | 为什么 |
|---|---|---|
| 概念页 / 附录页 | 70–130 | 一句要点 ＋ 一句查法，念完 15 秒 |
| 操作页（出图、拼图、验收） | 130–190 | 步骤要念全，但只念「做什么、看哪里」，不念原理 |
| 极复杂操作页（拼成品） | 上限 190，不许破 | 破 190 就是又回到旧稿 |

**判据：一条口播念下来超过 40 秒，里面就一定有两句能说成一句。**

### 三、从全文视角找三类冗余（本轮实际战果）

**① 跨页重复 —— 最高优先级，只有全文视角看得见**

通则在**最靠前讲它的那一页说一次**，后面各页只留呼应，不重讲。

判据一句话：**这句话的主语是「这门课的规矩」，还是「这一页的动作」？**
前者 → 只在首次出现处说；后者 → 留在本页。

本次实例：「用豆包出图，不用手绘」在 p03（六件成果）与 p12（出第一格）各说一遍
→ 删 p12 那句（p03 是全课第一次交代工具，p12 的正文图示里本来也有）。
同理「倒着来」在 p03 只留一句预告、方法在 p09 讲全，p24／p29 不再重讲原理、只讲本页做法。

**② 同义反复 —— 一句话里把同一件事说两遍**

本次实例（p01）：

> ✕ 先说一句定心的话：四格漫画的功夫不在画工，在结构——画得像不像，从来不是这门课要查的
> 东西。所以一上来要是有人跟你说「我不会画」，你可以放心：这门课只看你有没有把一件事说清楚。
> ✅ 调子先定下：四格漫画的功夫不在画工，在结构——画得像不像不查，只看你有没有把一件事
> 说清楚。谁说自己不会画，都可以放心。

「功夫在结构」「不查画得像不像」「只看说不说得清」讲的是同一件事，说了三遍，压成一遍；
「所以一上来要是有人跟你说……你可以放心」这种「铺垫 ＋ 反转」的口语壳子，
白话里一句「谁说自己不会画，都可以放心」就够。

**③ 虚词堆叠**

`其实`／`就是`／`这样`／`这件事`／`这个东西` 在一句里出现两次以上，删掉不损义。
本次实例：`你们这学期要交的就是这样一个东西` → `这学期要交的就是它`。

### 四、四条合并手法（「一句能说完的不用两句」怎么落）

1. **把「原因」并进「结论」**，用破折号接 —— 顺手删掉自问自答的结构：
   > ✕ 注意顺序：先想第四站落在哪，再想第三站发生什么变化。为什么倒着来？因为先知道终点，
   > 中间两站该放多重的料才配得准。
   > ✅ 顺序倒着来：先想第四站落在哪，再想第三站变什么，最后倒回来补第一、二站 ——
   > 先知道终点，中间两站该放多重的料才配得准。
2. **删流程连接词**：`现在`／`然后`／`接着`／`抄完我随机点两个人念` 这类。步骤在正文图示里
   已经写了，口播不必复述操作顺序。
3. **假设句改条件短语**：`要是出图里主角一脸轻松，当场把 Prompt 里的情绪词加重`
   → `出一脸轻松就加重情绪词`。
4. **例证只留一个**：同一道理给了两个例子，留画面里那个。
   本次实例：`操场、食堂、教室、家里，每一处都好画` → 只留「挑四个好画的地方凑数，
   每处都好画，合起来什么都不是」。

### 五、不能压的三样（压了就是丢教学）

1. **具体数字与阈值** ——`三分钟定不下来`／`不超过十个字`／`16:9`；
2. **术语与红线** ——`一格一个动作`／`落点`／`Prompt 里仿现成角色是红线`；
3. **查法与判据** —— 组间互查怎么查、卡在哪一格回去重出。
   这三样是口播的骨架，**宁删形容词，不删判据**。

### 六、脚本与收尾（沿用 §5.18 八，另加两条）

- 新稿写成**独立 `.py`**，`NEW = {1: "…", 31: "…"}`，键就是页序；
  断言四样：**长度带**（越界即报出是哪几条）／**禁词表**（首先·其次·总之·旨在·赋能·抓手·闭环…）／
  **无 HTML 特殊字符**（`<` `>` `&`）／**总长度必须减少**。
- **改完复扫「旧文特征串」，不能只验新稿在不在。** 每条旧稿取前 10–14 字当指纹，
  在三件 md 里逐一 `count`，必须全 0 —— 本次挑 10 个旧串（`这门课教你画四格漫画`、
  `现在给你们三十秒安静看图`、`先说一句定心的话`…）逐个验，全 0 才收工。
  **只验新稿会出现「一半改了一半没改」而看不出来。**
- 收尾链：`check_brief_course.py` 全绿 → `fp_run.py` 重跑（看 `segs=31`）→
  三件 md 复扫（新稿逐字命中 31/31 ＋ 旧串 0；**设计方案 md 本来就不引用口播，
  命中 0/31 属正常，别当失败**）→ 渲染抽查**最短页与最长页各一**
  （本次 p01＝74 字、p27＝190 字，确认说课面板不溢出、不出现滚动截断）。

- **改 SKILL.md 自己的 frontmatter 时，插入锚点必须选 `description` 内部的串**
  （比如某条「另有…路径」段落的结尾），**不能选 `brief-course` 这种同时也出现在 `triggers` 里的词** ——
  上一轮往 `description` 追加「成品收尾页」那一段时就踩了这个坑：一整段被插进了 `triggers` 列表项，
  变成 `- brief-course  **另有「成品收尾页」路径…`，YAML 语法上仍然解析得通（它只是变成了一个很长的
  列表项值），所以**不报错**，但 `description` 里反而缺了那一段，路径描述等于没写进去。
  修法：把该段剪出来，移回 `description` 的段间（**缩进 2 空格**），并断言
  `s.count('- brief-course\n') == 1`、且它后面直接跟 `---`。
  **判据：往 frontmatter 里加东西，加完必须回头看一眼「这段现在属于哪个键」。**

## 5.21 说课口播的老师口吻：主语落地、人称三分、页与页接得上（2026-09-19 定，硬流程）

用户说「**说课的语言需要以老师的口吻来写，还是语言通俗易懂且专业，语句凝练，前后段落连贯**」时走这条。

与相邻三节的分工：**§5.18 定结构（留几段）／§5.20 定长度（多长）／本节定口吻（谁在说）**。
三节共用同一批文本，次序固定：**先 §5.18 合段 → 再本节换口吻 → 最后 §5.20 压字**。
本轮实测：换完口吻字数先涨 4%，通读一遍再压回 −2%。

### 一、判据一句话：这句话是「文档在介绍这门课」，还是「老师站在讲台上说」？

主语是「这门课／本章／这一页／任务」，谓语是「教／查／包含／建议」→ **文档腔**；
主语是「咱们／我／你们／你」，或干脆省略主语的祈使句 → **老师口吻**。

| 文档腔（改前） | 老师口吻（改后） |
|---|---|
| 这门课教你用四个格子讲一件事 | **咱们这门课**，就学一件事：用四个格子讲一个故事 |
| 本章不写故事，只交一张场景主题卡 | **所以这一章不写故事**，只交一张场景主题卡 |
| 这一页三块：缺网预案、教师控点…… | **这一页有三块**：缺网预案、教师控点…… |
| 第一格任务很单纯 | 第一格**要办的事简单** |
| 第一格要拿到一张图 | 第一格，**我们要的是一张图** |
| 练法是列三个主角可能的反应 | **怎么练？**列三个主角可能有的反应 |
| 查法是把标题念给隔壁组 | **怎么查？**把标题念给隔壁组听 |
| 做法是请隔壁组一位同学看图复述 | **请隔壁组一位同学**看着成稿复述（删掉「做法是」） |
| 标准一条：读者看到它，会愣一下 | **标准只有一条**：读者看到它，会愣一下 |
| 另外说清：「靠画面讲」不是「不要写字」 | **还有一点讲清楚**：「靠画面讲」不是「不要写字」 |
| 给个上限：三分钟定不下来 | **给你们一个上限**：三分钟定不下来 |
| 组间互查：／互查看图 | **两组换着查：／两组合起来看图** |
| 建议单独打印贴在教室后面（附录页） | **可以单独打一份贴教室后面** |
| 第三格有两种变法 | 第三格有两种**做法** |

「怎么练？／怎么查？」这类**自问自答是老师口语的典型节奏，要留**；
但「具体怎么弄？」的「具体」是书面词，删掉更利落 —— **自问自答留，书面副词不留**。

### 二、人称三分（整课统一，别混）

| 人称 | 用在哪 | 本项目实例 |
|---|---|---|
| **咱们** | 师生共同体：讲这门课的规矩、共识 | 咱们这门课就学一件事／这门课偏偏倒着来 |
| **我** | 老师自己的动作 | 我点两个人念／我一会儿下来看／每一章我都会回来查／我推荐第二种 |
| **你们** | 明确交给学生的动作 | 你们先说自己想在哪一点收住／你们习惯顺着想 |
| **你** | 单个学生 | 只看你有没有把一件事讲清楚／你的第二格 |

参考量级（本项目 31 条 / 4536 字）：**我 11、你们 6、咱们 2、我们 2**。
**「我」出现少于 8 次就不像有人在讲** —— 这是最省事的自检数。

### 三、附录页要分两种口吻 —— 判「这一页的动作是谁做的」

别一刀切成「全篇对学生讲」，也别一刀切成「全篇备课口吻」。
判据与 §5.19 同源：**这一页的动作是谁做的**。

| 页 | 谁的动作 | 口吻 |
|---|---|---|
| 0.1–7.5 课堂页 | 学生课堂动作 | **对学生讲** |
| 8.1 附录 A 速查表 | 老师打印、贴墙 | **教师备课口吻**：可以单独打一份贴教室后面 —— 学生卡住不用举手，先让他们翻这页 |
| 8.2 附录 B 五问 | 学生念、学生打勾 | **对学生讲**：全组每人念一条 |
| 8.3 附录 C 控点／备课链 | 老师巡场、打印贴讲台 | **教师备课口吻** |

同一章里视角切换不算「跳跃」—— **因为每页的动作主体本来就不同**。

### 四、「前后段落连贯」的落点：每章首页补半句承接

31 条孤立地看都通顺，连着念才有「跳」的感觉。检查法：**把全部口播按顺序念一遍，
每次出现「这一章」起头时问自己 —— 读者知道「这一章」是从哪来的吗？**

本次实际补的六处（都在章首页）：

| 页 | 补的承接半句 |
|---|---|
| 2.1 | 四格长什么样、守什么规矩，**第一章讲完了**。这一章做第一件事：…… |
| 3.1 | **场景主题定好了**，这一章开始出图。 |
| 4.1 | **第一格把人交代清楚了**，这一章往前推一步，出第二格。 |
| 6.1 | **前三格铺了那么多**，全靠最后一格收住。……所以这一章，出最后一格。 |
| 7.1 | **四格画完了**，这一章说标题。 |
| 7.4 | 四格分四次画，**现在拼成一张完整作品**，这是全课的收尾。 |

**承接半句不超过 12 字**，不要写成「上一章我们学习了……接下来我们将……」。
判据与 §5.20 同源：**这句话的主语是「上一页的动作」还是「本页的动作」** ——
承接句必须一句话说清「上一页交出了什么」。

### 五、次序硬规则：先定口吻，再压字 —— 反过来会把口吻标记压掉

本轮踩到的坑：第一轮同时改口吻 ＋ 压字数，为了省字把

> ✕ 卡住时，**人的**性格才露出来 → 卡住时，性格才露出来（主语没了）
> ✕ **这两样**分不清，第四格就转不起来 → 分不清，第四格就转不起来（起句突兀）

**省略主语的压缩只对「承接上一句主语」成立；起句省主语要当心。**
正确次序是：**先按本节把口吻全部换到位（这个阶段别管字数）→ 通读一遍 → 再按 §5.20 压。**

### 六、脚本纪律（本轮新增两条）

1. **逐条替换要当场确认改动生效**：`prev = new_s; new_s = new_s.replace(old, new); assert new_s != prev`。
   **不能事后靠「旧串还在不在」判断** —— 旧串可能是新串的子串（`例子：` ⊂ `看例子：`），
   会误判成「没换掉」而卡住（本轮实测踩到）。
2. **词表扫描只作提示，逐条人读判断**：「前三件……**最后**一张」「**最关键**的一格」
   「**最后**一页」都是普通用法，不是「首先／其次／最后」的列举腔。
   扫出命中后要**逐条贴出上下文让人读**，别一律判错、也别一律放过。

### 七、收尾链

同 §5.20 六：`check_brief_course.py` 全绿 → `fp_run.py` 重跑（看 `segs=31`）→
三件 md「新稿逐字命中 31/31 ＋ 20 个旧串全 0」（设计方案 md 命中 0/31 属正常）→
渲染抽查**第 1 页 ＋ 最长页**（最长页看说课面板有没有溢出）。


## 5.22 交付口径的课程时间框架：学期制 ≠ 实践课（2026-09-19 定，硬流程）

用户原话：「不要写这学期，写这个课程结束，因为这是一个实践的课程，从全文视角帮我审视」。

### 一、判据：这门课的时间单位是什么

**先定时间单位，再谈措辞。**

| 课型 | 时间单位 | 交付物怎么说 |
|---|---|---|
| 校内长课（一学期、每周一节） | 学期 | 「这学期要交的」成立 |
| **项目式实践课 ／ 工作坊 ／ 系列课 ／ 短训** | **课程本身** | 「**这门课结束时要交的**」 |

实践课可能跨周推进、也可能几次课走完，**它没有学期边界**。
写「这学期」等于把交付物钉在一个不存在的行政周期上 ——
这不是措辞偏好，是**事实错**，老师念出来不对味。

### 二、全文视角怎么查：搜「词族」，不搜「学期」两个字

只搜「学期」会漏。按**整个词族**扫，覆盖五件套：

| 类别 | 词 |
|---|---|
| 学期制 | 学期 ／ 本学期 ／ 学年 ／ 上学期 ／ 下学期 ／ 开学 ／ 放假 ／ 寒假 ／ 暑假 ／ 期中 ／ 期末 |
| 课时制 | 课时 ／ 学时 ／ 学分 ／ 结业 ／ 学号 |
| 交付 | 交 ／ 交作业 ／ 交上来 ／ 上交 ／ 提交（看它前后挂的周期词是「学期」还是「课程」） |

**最隐蔽的是「课时」**：本次实测命中一处 —— 派生件里的附录标题
「全课待办与**课时**动作一览」，而它正下方的表头写的是「课堂动作」。
**标题与表头自相矛盾**，只盯一处看不出来。

### 三、改哪里才算改完：源头有两处，不是一个

1. **课件 HTML** —— 口播、正文、表格里的口径。
2. **派生器脚本**（`scripts/fourpiece/fp_*.py`）—— **写死的标题与字段名**。
   只改课件，`fp_run.py` 重跑后脚本里的老口径照旧出现。

**学案是独立文件，要单独扫**。本次实测学案本来就没有学期词 ——
而且它反过来是**对照基准**（见下节）。

### 四、替换词不要自己造：先找文档里已有的正确说法

本轮定稿前先在文档里翻，发现学案封面早就写着

> 六件 · **这门课要交的**六件东西 · 给每件编上序号，写下在第几章交

**这就是全文既有的正确口径。** 于是课件里的改法照它写：

> …逐格生成、再拼成一张 16:9 横排成稿 —— **这门课结束时要交的就是它**。

自己造新词（「结课作品」「期末成果」）会和既有说法打架。

### 五、与 §5.20／§5.21 是三把不同的尺子，各查一遍

| 层 | 查什么 | 节 |
|---|---|---|
| 长度层 | 太长、跨页重复、同义反复 | §5.20 |
| 口吻层 | 主语是文档还是人 | §5.21 |
| **口径层** | **时间框架与交付物名对不对** | **本节** |

三层都对才算过。长度和口吻都对了、时间框架错了，照样返工。

### 六、改完要能说清「哪些看着像、其实不该动」

不动的三类，理由要落到判据上，**不能只说「感觉没问题」**：

- **「课末」**（p02 动手条「写学案上，课末回头对」）——
  指课程结束那一刻，与实践课口径**同向**，不是学期词，留。
- **学案封面「这门课要交的六件东西」** —— 本来就是正确口径，
  它是**基准**，不是待改项。
- **p27「这是全课的收尾」／p28「全课验收」** ——
  「全课」是课程级范围词，没有学期含义，且与 §5.19 成品收尾页配套，留。

### 七、脚本纪律（本轮新增一条）

**断言要按「改前的真实计数」写，不能按脑补的计数写。**
本轮把「课堂动作」改后应为 4 处误写成 3 处（漏算了脚本里本来就有的
「给老师（课堂动作…）」字段说明），断言当场失败。这是好事：
**先跑一次「只数不改」的脚本拿到真实计数，再写断言**，比猜快。
（断言全部前置、`io.open(...,'w')` 压最后一行 —— 本轮正是靠这条，
断言失败时两个文件都没被写坏。）

### 八、收尾链

同 §5.20 六，外加一条 **五件套词族复扫**：

- `学期／课时／学年／…` 全套在**五个文件**里全部为 0；
- 新口径在**课件 ＋ 合集 ＋ 讲课稿**三处**各逐字命中 1 次**（学案不引用口播，为 0）；
- `check_brief_course.py` 本来就有一项「无课时语汇残留」，本节能过它会直接绿。

## 5.23 页底大字压一行 ＋ 同页跨层去重（2026-09-19 定，硬流程）

**触发**：用户对着课件截图说「**布局上也不要重复赘余，能用一句话说完的就不用两句话**……
像 PPT 一样，语句凝练，但也要让人一眼就知道说的是什么」。

这不是「把句子改短」，而是**先找重复、再收句子**。课件的文字是四层叠的：
`页标题`／`图示`（SVG 内文字）／`页底大字`（`.cap` → `.cl`）／`动手条`（`.todo` → `.tt`）／`指令说明`（`.exhint`）。
**同一个道理在两层各说一遍**，读者就会觉得翻来覆去 —— 本轮实测每页的
「SVG hero 底部黄色小结带」与「页底大字」就是在说同一件事：

| 页 | 图示小结带 | 页底大字（改前） |
|---|---|---|
| p05 | 四条规矩里最要紧的是第①条：一格一个动作 | 一格一个动作，画面多说，字少说 |
| p17 | 第二格的关键是「难处长在短处上」 | 难处要长在他的短处上 |

### 一、先把「同页重复」变成可复查项：`check_repeat.py`

```
python scripts/check_repeat.py <课件.html> [报告.txt]     # 退出码 0 = 同页无重复
```

- 把每页的五个层抓出来，**两两比 LCS 覆盖率** `lcs(a,b)/min(len)` ≥ **0.78**（且短句 ≥10 字）判重复。
  用 LCS 覆盖率而不用「整串包含」或「二元组 Jaccard」：插字（「场景管讲得通」vs
  「场景那栏管讲得通」）不漏判，语序大改也不误判。
- **必须先用改前版验证灵敏度**：本轮拿 `x10_before.html` 跑出 **10 处**真重复，改完 **0 处**，
  才敢信这个 0。脚本第一次写出来时旧版也报 0 —— 那是**失灵**不是干净（见 §5.21 六的同类教训）。
- 报告里另有一节 **跨页近似句**（≥0.80），**仅供复核、不计失败**：本轮 60 处命中，
  拉开看全是两类正常项 —— ① 结构性 BOILERPLATE（`🎖 盖章两个条件（同时满足才盖）`、
  `章盖在学案第 1 页的章格上`、`📌 指令里的【例】取自范例《清晨冲刺》…` 在每章页重复）；
  ② **议程 → 章节标题**（p07 章总览图里的 `② 把主题拆成四个连着的场景` = p09 的页标题）。
  这两类**不要动**：它们是「表单每页都有同一行」「先列议程再进小节」，删了反而断导航。

### 二、收句子：页底大字从「两行」压成「一行」

- 一条 `.cl` 仍守 **最长语义段 ≤14 字**（`check_caption_len.py`，见 §5.5）。
- **压短不是等比缩句，是换角度**：若某页的 `.cl` 与图示小结带同义，就不要把图示那句抄短，
  改从**这一页独有的动作/后果**切 —— 本轮 31 页里挑了 31 个新角度，例：
  p01 「一格一个动作，最后要有落点」／p05 「四条里，第一条一票否决」／
  p22 「不是把事办完，是把事讲完」／p31 「练的是难处和画面，工具次要」。

### 九、换表述：孤立的口语习语要落地成动作

用户圈 p03 页底大字 `习惯顺着想，这门课倒着来` 说「换个别的表达方式，现在这样组词理解不了，

  词换了，方位词照样裸着。

  1. **不与同页小字重复**：本页 SVG 已有 `先定转和合，再倒回来补承和起 —— 顺序别按格子走`，

### 十二、规矩句要点名比较的对象（场景 ≠ 事）

用户圈 p09 口播 `每一站都要跟上一站不一样` 说「场景可以一样，但在里面发生的事可以
不一样，这样才合理」。

- **毛病不在方向，在比较对象没点名。** 本意是「事情要往前走」，主语却写成了
  「（场景）每一站」——把地点当成了比较对象，学生照办会得出「四个格子必须换四个地方」，
  而**同一间教室里发生四件不同的事完全成立**。判据：写「A 要跟 B 不一样／一样」这类
  规矩句时，先自问**比的是什么名词**；名词不点名的规矩句是隐患，用户补一句常识
  （「场景可以一样」）就能暴露它。
- **同页其余层先查再动，别只改圈中一句。** 该页页底大字 `念着别扭，就是中间缺一站`、
  动手条 `各写一句「这一站发生什么」`、SVG 卡片提示 `顺着上一站往前推／不能原地打转`
  都已是「事」的口径——确认只有口播一处跑偏，动一处是「最小改动」而非「漏改」。
- **两个毛病的表述也跟着换对象**：`四站说成两件事，中间两站是同一件事说两遍`／
  `事情到了第三站还停在第二站，没往前走`。原来的 `第三站跟第二站一个样` 同样没点名
  比的是场景还是事。
- **闸**：旧口径词族（`每一站都要跟上一站不一样`／`四个场景其实只有两个`／
  `一个样、没变化`）课件清零；新关键句课件＋合集＋讲课稿各 1；其余层零改动。

### 十三、口径反转还要查「结构残留」——行序、步骤序不进词族扫描

口径反转的次日，用户圈学案 p3 场景表的行序（例行下依次是
第 4 站→第 3 站→第 2 站→第 1 站）说「改为正序，1-4 站顺着向下，方便学生填写」。

- **行序是倒着做时代的遗物，但它不含口径词。** 十一轮的反转词族扫了文字层
  （`倒回来`／`别按格子走`…），表格行序这种**结构载体**一个词都不带，扫描天然漏掉——
  于是出现「小节提示已改成 `顺着 1 到 4 写`，表体却还是 4→1」的自相矛盾。
  判据：**口径反转后，除文字层外要再过一遍结构层**——表格行序、步骤排序、
  卡片从左到右的次序、检查项编号，看它们承载的顺序跟新口径一致吗。
- **结构残留的修法是搬行，不是改字。** 直接整块替换 `<tr>` 序列，闸卡三道：
  旧块唯一、改后行序断言（`re.findall` 抽站号应为 [1,2,3,4]）、学案页数/结构计数不变。
  纯行调换字节数不变，是正常的。
- **示例行跟着新口径复核摆放。** 本表示例行是`【例：第 4 站 · 落点】`，
  改后保持置顶（示例行教「一行怎么填」，置顶是表单惯例），不硬把它搬去第 4 站旁边；
  但若新口径下示例本身示范的是「先填的那一行」，要考虑换示例内容，别只挪位置。
- **手写件（学案）不走派生器**：改完跑双轨体检即可；课件没动就不用重跑 `fp_run.py`。

### 十四、用户把模板填一遍，就是模板最好的体检报告

用户按课件 p16 的指令模板自己填了一版第②格 Prompt（全文六段：角色／画面／情绪／漫符／
风格／尺寸 ＋ 要求 ＋ 负面），拿它圈课件 p13 说「按这个优化模板」。对比填版与模板即得三类问题：

- **字段缺失**：p13 模板少【情绪】段（p16/19/22 都有）——补齐为六段，
  位置与族内其他页一致（画面之后、漫符之前）。
- **规格含糊**：模板【例】只写「气泡留白充足、文字居中」，用户填版会写
  「椭圆形白底、黑色粗轮廓、指向嘴巴、仅此一个」——模板的示例要按**能直接跑通的
  真 Prompt 水准**写，因为学生会照抄示例的颗粒度。
- **清单偏瘦**：负面词族模板比用户版少 `破碎线条／复杂纹理／真人照片质感／多余气泡／空走廊`。

同步范围与例外（逐字核过再动手）：

- **【角色】线四处同步**（p13/16/19/22 同一角色）：升级为全套外形
  （蓬松黑色短发／深灰长裤／棕色皮鞋）。**书包只进 p13**（跑动画面背着），
  p16/19/22 的角色线不带——③④格人已坐下，背着书包反而错。
- **【风格】线四处同步**，保留各页前缀（与第①格／第①②格／前三格保持一致）。
- **p19 负面要求保持短**（不要平静的脸／不要文字…）——那页教学焦点在表情，
  长清单会冲淡焦点，属刻意例外。
- **闸**：`【情绪】=4 页`、角色新线 3＋1（无书包版 3 处、含书包版 1 处）、
  新负面词各 3 页、页数/说课数不变；改后真机量 `.pc` 卡
  （scrollHeight−clientHeight=0、卡底距页底 166px）确认新增行不撑爆。
- 探针复用 `check_svg_overflow.py` 的 dump-dom 管道；注意 pre 带 style 属性时
  序列化为 `<pre id="..." style="...">`，正则要写 `<pre id="X"[^>]*>`。

### 十五、用户按格逐个喂完整 Prompt，模板跟着升一格（p13→p16→p19→p22 轮番）

十四节是第②格填版喂进来的；后续用户又把**第①格**、**第②格**的完整 Prompt 逐个喂进来
（七段：角色／画面／情绪／漫符／风格／尺寸／**合成约束** ＋ 要求 ＋ 负面）。规律成立：
**用户每填一格，就把那一格的指令卡【例】升到真 Prompt 水准**。改动范围分两层：

- **内容【例】只动该页**（画面／情绪／漫符的写法是「这一格怎么填」的示范），
  但**格式段（画面尺寸／合成约束）属于全族统一口径**：用户说「保证统一」时，
  尺寸＋合成约束要一次铺满四卡（②③④各配一段「与第 1、3、4 格」式的互指），
  别只改当页——p19/p22 的旧口径（16:9 横版）就是漏网残留。
- **【例】升级后，同页（乃至族内）引用旧口径的地方要逐处扫掉**：
  示例行 exbadge、SVG 示例文字、说课口播、总览页的各格摘要行，都可能写着旧事实
  （门框→门板、老师站着→坐着）。全文 grep 旧关键词定位；**闸要给合法残留留口子**——
  ①格走廊里的「门框」是真场景词，闸写「全文门框==1」而不是清零。
- **口播里例子要标明「是例子」，通则与范例事实分开说**：写「画面里多一道门、
  多一个老师」学生会当成第二格的硬性要求；要写「例子里是……——这只是例子，
  你的第二格添什么，由你们的故事定」。自查口径：别的组套用这条口播会不会被带偏？
  族内其余口播（p13「比如」、p19/p22「看例子」）已有此框架，别改坏。
  过关页口播另要对准本页：开头按过关标准三条顺序念（页上写着哪三条，口播就查哪三条），
  别只挑一条展开；例子里凭空长出来的 QA（「丢东西」之类）页上没有就删；
  时机词要跟章节对齐（转在第三格，就别写「第四格转不起来」）。
  总览页同理：口播要扫全「做什么」①②③（含情绪词写进【情绪】段这类操作细节），
  反例必须取自本课范例的故事情节并标「例子里」，别拿外来故事举反例（「去借绳子」之误）。
- **口播每段 ≤60 字（2026-09-20 用户定，全 25 段已压）**：一句话讲清就一句，
  不凑字数、不加过渡客套。压缩优先级：本页「做什么/查什么」的操作要领 ＞ 例子
  （标「例子里」）＞ 提醒句；页上 SVG/要求行已写明的细节（如四站名单、拼稿参数）
  口播不重复。压缩后自查：删掉这句读者还能不能照着做——能就删。
- **新增段要有闸**：【合成约束】是第七段，插在【画面尺寸】之后；
  闸写 `【合成约束】</span>`==4（带 `</span>` 后缀——裸「【情绪】」会在正文口播里误命中，
  x99 第一版闸就栽在这）。
- **【画面尺寸】逐格不同要跟用户的实拍工作流**：①②格 `9:16 竖版单格漫画，纵向窄构图`
  （适合上下拼接），③④格若用户没给新 Prompt 就先统一成同款 9:16＋互指合成约束；
  内容段（画面/情绪）不动——③④的教学焦点（表情卡住／收住余味）不能被冲淡。
- **探针读数要懂行**：`.pc` 卡 `overBottom` 恒为 −166 是**假安全信号**——那 166px 是
  卡片下方的固定家什（任务条＋收起的说课＋页脚），页面本身是自适应高度
  （四卡实测 pageH 1119～1200）。真判据是 `clipY=0`（卡内无裁切）＋
  `CANVAS_OVER/CARD_OVER=0`；加行只会把页面撑高，不会撑爆。
- 改完老三样：`fp_run.py` 重派生（合集行数＋新增段数）、四体检、
  探针复核，抽查合集 md 里该页段落逐行带新内容。
- **技能 frontmatter 的 version 可能被宿主同步回写**：改完隔轮再看可能回到旧值，
  属宿主行为，重改即可，别当成自己漏改。

### 十六、结构级加页：先重排、再删旧、后插新（31→33 页实操）

用户要把某块内容独立成页、或在某节点后加新页时，这是**结构级改动**——id、页脚页码、
章段号、页脚总数、派生 md 全链条都要动：

- **替换顺序铁律：全部从大到小**。id（`id="p31"`→`id="p33"` 先做）、页脚
  （`第 <b>31</b> 页`→`第 <b>33</b> 页` 先做）、章段号同理——正序替换会把已改好的
  新值又当旧值改一遍（串号）。页脚总数 `共 <b>N</b> 页` 全局替换放最后。
- **插入点用锚定验证**：新页插在某 `</section>` 之后时，断言后跟内容
  （如 `\n</main>`）确认没切错页；新页 id 用重排后空出的号。
- **闸词的计数预期必须先对磁盘文件 grep 实数，别拍脑袋**。本轮连撞三个闸：
  aria-label 里的词、说课口播里的词都算数——「先看一张做完的」==2（标题＋口播）、
  「我们的校园》故事集」==3（新页 aria-label 也算一处）。先数旧文件，再推导新值
  （旧值 − 删除量 ＋ 新增量）。
- **check_repeat 会抓新页内部的两层同句**：SVG 底行别抄页底大字，一页一个金句。
- **同章内加页（2026-09-20 R49 补）**：章段号顺延即可（认识 1.1–1.3 后插 1.4/1.5，
  其它章的 X.Y 不动）；但 **stepchip 若带分母必须同步重编号**——「认识 1/3、2/3、3/3」
  →「1/5…5/5」，漏改分母是肉眼最容易放过的漏网之鱼。另一坑：fp_run 报的 todo 数
  与课件里 `<div class="todo">` 裸计数差 1（口径不同），两边闸各按各的实数定，别强行对齐。
- **新页骨架**照抄既有页：page-head 三件 ＋ hero SVG（文字行宽 ≤ 卡内）＋ 可点卡
  ＋ cap ＋ tnote 口播（≤60 字）＋ pfoot；SVG class（tc/td 等）全局可用。
- 截图预览两个不相邻的新页：抽 `</head>` 前样式 ＋ 两个 `section` 拼临时 html
  再截——比 7.1 节的注入 JS 隐藏法更快，且不受嵌套 main 影响（切的是 section 不是 main）。
- 收尾老三样照旧：fp_run 重派生（pages/todos/segs 全变）、四体检、双轨咬合
  （课件页码变了但学案页码没变，学案引用不受影响）。

### 8.1 五件套齐套交付（用户点名要「和 XX 一样的那几件」时）

**触发**：用户给出一组参考文件名（或说「按 AI记者训练营 那几件」「和这几件同款」），要求「按这几件的样式产出」。交付物是 **5 件**（不是 2 件），编号前缀便于排序。

**五件套清单**：

| # | 文件名 | 形态 | 来源 |
|---|---|---|---|
| 1 | `1-<课名>-课堂版-简版.html` | 深色霓虹单文件课件 | 主轨，按 §3.1 手写／改造（**非脚本生成**） |
| 2 | `2-<课名>-漫画社学案.html` | A4 打印学案 | 副轨，按 §3.2 手写／改造（**非脚本生成**） |
| 3 | `3-<课名>-简版-设计方案.md` | Markdown 设计方案 | **脚本生成**（fp_design.py） |
| 4 | `4-<课名>-简版（全页Prompt合集）.md` | Markdown 逐页字段稿 | **脚本生成**（fp_prompts.py） |
| 5 | `5-<课名>-教师讲课稿.md` | Markdown 教师讲课稿 | **脚本生成**（fp_lecture.py） |

**为什么 3、4 用脚本**：从课件 HTML 程序化抽取结构（横幅／页面／短句／说课／指令框／任务条／SVG 信息），再各自生成。手抄必然转述失真，且课件一改就重跑脚本，四件永远同源。脚本在技能目录 `scripts/fourpiece/`：

| 脚本 | 输入 → 输出 | 作用 |
|---|---|---|
| `fp_extract.py` | 课件 `.html` → `data.json` | 抽 9 类结构：横幅（含 pnum/title/chip）、页面（含短句·说课·指令·任务条·SVG 统计·**真实章归属**）、SVG 的 aria-label 与内文文字 |
| `fp_design.py` | `data.json` + `config.json` → `3-设计方案.md` | 决策→每页解剖→贯穿链路→六类主视觉表→逐页映射→施工校验 |
| `fp_prompts.py` | `data.json` + `config.json` → `4-Prompt合集.md` | 风格锚定段→页面地图→字段用途→分章逐页 5 字段→待办一览 |
| `fp_lecture.py` | `data.json` + `config.json` → `5-教师讲课稿.md` | 头部＋怎么用＋全课地图＋分章逐页「六块」+ 页脚 |
| `fp_run.py` | 课件 `.html` + `config.json` → 同时出 3、4、5 三件 | 一键：抽取→设计→Prompt→讲课稿，报告体积与「待补」项 |

**一键命令**（Python 走隔离运行时，输出 UTF-8）：

```bash
PY="C:/Users/admin/.workbuddy/binaries/python/versions/3.13.12/python.exe"
SK="C:/Users/admin/.workbuddy/skills/cyx-brief-course/scripts/fourpiece"
$PY "$SK/fp_run.py" "C:/.../1-<课名>-课堂版-简版.html" "C:/.../输出目录" \
     --config "C:/Users/admin/.workbuddy/skills/cyx-brief-course/assets/fourpiece-config.example.json"
# 上面一条命令会一次性产出 3-设计方案.md ＋ 4-Prompt合集.md ＋ 5-教师讲课稿.md
# 任一件也可单独跑：$PY "$SK/fp_lecture.py" data.json 输出.md --config cfg.json
```

**config.json 字段**（照 `assets/fourpiece-config.example.json` 抄，全可省——省掉的自动推导并标【待补】）：

- `course` / `date` / `courseware` / `workbook` / `audience` / `style` / `ai_tool`：填入即替换 md 头部元信息占位。
- `decisions` / `change_note` / `rules` / `chains` / `stamp_note`：填了就进设计方案的「四项决策／变更记录／守则句／贯穿链路／七枚章」段；不填则这些段留【待补】。
- `visual_types`：六类主视觉映射（`[类型,[页码…]]`），填了就替换自动分类。
- `ai_points`：全课 AI 使用点表（`[序号,章,页,动作,学生动作]`）。
- `check_items`：施工校验清单。
- `map_rows`：页面地图的「篇」行（`[篇名,页码区间,内容]`）；**只填前几章做人工润色也行**，其余章自动用横幅 `pnum` 生成；章标题统一由脚本内 `chapter_label()` 取（map_rows[i][0] 优先，否则用横幅 pnum），页面地图与分章标题由此保持一致。
- `style_anchors`：风格锚定段（喂给 AI 的【】定义）；不填则用 `style` 字段生成通用版。
- `layout_overrides`：`{页号: {版式,画面}}`，个别页的「版式／画面」想手写精修时填这里，覆盖 SVG 自动推导。
- **`lecture`（第 5 件专用，全可省）**：
  - `workbook_name`：学案名（如「漫画社学案」），进讲课稿头部「配套《X》A4 共 Y 页」。
  - `workbook_pages`：学案页数（填了才显示「共 Y 页」）。
  - `stance`：立场三句（list），进头部 blockquote。
  - `chain_text`：全课单向链一句（进「整门课是一条单向链」）。
  - `red_lines`：红线 list（进「红线」段）。
  - `chapters`：`{横幅id: {subtitle, intro, delivers, solves, stamp, pass, main_line, pitfalls:[3句]}}`，横幅 id 即 `ch0/ch1/.../ch7/appendix`（看 `data.json` 的 `banners[].id`）。**章级框架全在这里**；不填的章标【待补】。
  - `page_what`：`{页id: 一句话}`，覆盖「这页要干什么」默认（默认=页标题）。
  - `page_bottom`：`{页id: 页底收口句}`，填了就在「投影内容」末加 `> 页底收口：` 行。
  - `page_dot`：`{页id: "X.Y"}`，个别页想手动指定章.节编号时填（默认按章顺序自动编）。

**第 4 件字段规范（固定五行，与参考件一致）**：

```
### ⏱ 第 N 页 · <标题>
- **版式**：（自动从 SVG 结构推导；可被 layout_overrides 覆盖）
- **画面**：（自动从 SVG 的 aria-label + 内文文字拼接）
- **要显示的文字**：标题＋短句（⏱/⚡/⏭ 弹性标记按课程阶段加）
- **🎓 说课（❌不进图）**：🗣口播／🎬操作／⚠️提醒（与课件 HTML 说课逐字一致）
- **给 AI 的指令引文（完整版，❌不进图）**：（仅指令页有；一字不改）
```

章归属优先用抽取到的**真实章**（源文件横幅顺序），不再靠页码猜；页码区间自动算出。尾部附「全课待办与课时动作一览」表（页｜课堂动作｜时长），动作里凡出现「学案第 N 页」的，必须与学案实际页数咬合（`check_brief_course.py` 双轨咬合项会查）。

**第 5 件「教师讲课稿」的六块（每页固定）**——核心洞察：课件每页的 `details.tnote` 三段说课（🗣口播／🎬操作／⚠️提醒）＋`.todo` 任务条＋`.prompt` 指令框，**正好就是**讲课稿的六块，脚本只是把它们「展开」，不手抄：

```
## X.Y ｜ <页标题>

这页要干什么：<page_what 或 页标题>
投影内容：<页 .cl 短句 → 逐条列；可有「页底收口」>
引导语（可照读）：<segs.tsay 口播原文>
怎么带：<segs.top 操作原文>
学生动手（N 分钟）：<todo 文案；分钟从 todo.tp 抽；无 todo 写「本页不动手」>
要盯住：<segs.twarn 提醒原文>
指令① · <名称>（复制给豆包）：<仅指令页；prompt.body 原样进代码块>
> **X.Y**　｜　第 N 页 / 共 M 页   ← 章.节 ＋ 全文页序，自动算
```

章头（每章一次）从 `config.lecture.chapters[横幅id]` 取「subtitle／intro／delivers／pass／main_line／pitfalls」；全课地图的「单向链／各章交付／AI 使用点／红线」分别来自 `chain_text`／`chapters[].solves+delivers+stamp`／`ai_points`／`red_lines`。**普适任何课程**：只要课件是按本技能 §3 规范写的（页页有 tnote 三段＋todo＋真实章归属），跑 `fp_run.py` 就能一键派生 3、4、5 三件，第 5 件尤其省事——六块全自动。

**⚠️ 七个已修的坑 ＋ 一条用 config 前必做的体检（2026-09-19 补）：**

1. **`pitfalls` 写成字符串会被逐字迭代**。config 里若写 `"pitfalls": "学生一上来就说「我不会画」，要当场接住"`
   （而非三句的 list），`for x in v` 会输出 `1. 学 2. 生 3. 一`。已在 `fp_lecture.py` 加 `as_list()`
   兜住（字符串按 `；;。` 拆句；`stance`／`red_lines`／`ai_points` 一并走它）。
2. **页脚章数不能写死**。默认页脚本写死过「序章 ＋ **七章**」，拆章后（§5.13）就与课件页脚口径打架。
   现已改为**从横幅现算** `CHAPTER` 条数 → 「序章 ＋ 6 个流程章」。
3. **`本课程` / `《学案》` 这类占位名**：不传 config 时三件 md 的抬头与页脚全是占位。
   传一份**最小身份 config** 即可修好（`course`／`date`／`courseware`／`workbook`／`audience`／`ai_tool`／
   `workbook_pages` ＋ `lecture.workbook_name`／`workbook_pages`），**不必**传 `decisions`／`chains`／
   `lecture.chapters`。
4. **合集「画面内文字」曾被截断成前 14 条**（`fp_prompts.py` 的 `keep[:14]`）。第 4 件是给 AI
   重画页面用的**屏显文字底账**，截断＝AI 少画几行：本轮 A6 的第 3 页 SVG 有 23 条文字，
   前 14 条刚好停在末尾卡片，把**底部三行**（`场景主题 ＋ 起承转合 ＋ 标题 ＝ 六个章`／
   `六件凑齐，才是一张能贴的四格`／`先定转和合，再倒回来补承和起`）整段砍掉了。
   已改为**全量输出**（上限 40 条，超出才附「…（共 N 条，其余见课件该页）」）。
   **判据**：卡片阵／表格类页面，`svg_text` 条数常达 20–35 条，凡见到「画面内文字」正好 14 条就要起疑。
5. **无页底大字的页，讲课稿「投影内容」会退化成卡片碎片**（`fp_lecture.py` 原是 `sv[:6]`）。
   删掉 p05 的 `.cl` 后，该页投影内容变成 `① ／ 一格一件事 ／ 一格只干一件事 ／ 一格塞两个动作 ／ 读者就乱了`
   —— 全是卡片里的短词，不成句。已改为取 **`svg_text` 末尾两条**（收口句总在 SVG 末尾）：
   现在是 `后面每一章都会回来查这一条 ／ 画工不好不影响；一格塞两件事，一定不过`。
   **判据**：凡「兜底取文字」，先问一句「哪一头才是收口句」——开头往往是标题与卡片碎片。
6. **用 config 前先体检它是否过期**：本轮 A6 的 `_build/a6-config.json` 停在 30 页的旧结构
   （写着 `30 页`／`p01…p30`／`七个流程`／`含已删的「加漫符」章 ch7`／`题材链` 而现版叫 `场景主题`）。
   拿它去填【待补】会把过期口径灌进交付件 —— 所以**只用了身份字段**，章级【待补】原样留着。
   **判据**：config 里的「页数／章数／章名」任一与 `data.json`（`fp_extract.py` 产出）对不上，
   就只用身份字段，别用它的章级内容。
7. **「学案第 N 页」不能用公式推**：旧稿用「学案页 = 章号 + 1」，到章5（学案把「承＋转」并页）
   就整体偏大 1 页，六处引用全错而**体检全绿**（越界检查只问「有没有超过 9 页」）。
   现改由 `check_brief_course.py` 第 8 项**按章段对表**核查指向，细节见 §5.23 十。
   **判据**：凡两个交付物之间的页码／编号映射，都要从**两边文件自身**取底账去核，不要用一条通用公式。

**第 1、2 件（课件／学案）的产出**：脚本不管，按本技能 §3.1／§3.2 手写或改造（从 `assets/template-courseware.html`／`template-workbook.html` 起步）。但**双轨咬合是硬规则**——课件里 `.todo` 写「学案第 N 页」，学案就必须有那一页；学案份数口径（每组一张 vs 每人一张）要与成果格／盖章栏的组共享语义一致（见 §4.0）。

**第 2 件学案若已有成熟版式，做增量对齐而非重写**：先核 `4-` 里所有「学案第 N 页」引用与学案页码逐条对上（**按章段对表，不按公式**），再补窄屏段（见「已知限制」）、校份数口径。

## 已知限制

- 两份模板**无外链、无 `<script>`**（纯静态 HTML+CSS），可离线双击打开；也因此没有 JS 交互。
- 学案是 **A4 打印型**：`width:210mm` 写死。**但必须补一段窄屏自适应，否则 `--render` 第 10 项会 FAIL**（2026-09-17 实测：600px 视口报 `横向溢出 ['sheet','mast','wake','grid2','sheet']`）。仅靠「它的使用场景是打印」不成立——脚本照样判 FAIL，而且老师在分屏／手机上也会看到溢出。做法：在 `@media print` **之后**再加一段 `@media screen and (max-width:794px)`，把 `.sheet` 改成 `width:100%;max-width:100%;min-height:0`，并把 `.wake` 降两列、`.grid2`／`.sieve`／`.fourgrid` 降一列、`.stampbar` 降四列、`td.l` 取消 `nowrap`。**打印走 `@media print`，A4 版式不受影响**（见 `assets/template-workbook.html` 末尾的现成写法）。
- 本机 **Bash 工具不可用**（缺 coreutils，退出码 127）：外部命令走 PowerShell；文件读写走 `Read`/`Write`/`Edit`/`Glob`/`Grep`；拷贝用 `Copy-Item -LiteralPath`（中文、带括号路径必须 `-LiteralPath`）。**PowerShell 不回显 stdout**，要结果就让它写文件再用 `Read` 看。Python 脚本开头加 `sys.stdout.reconfigure(encoding="utf-8")`。
- 手写 SVG 是**手工排版**，改一处文字很容易撞到旁边的框。改完一定渲染看一眼，别只看代码。
- **课件主体容器必须用 `<main class="mainwrap">`，不要用 `<div class="mainwrap">`**（2026-09-17 实测）。体检脚本第 3 项按 `<main>` 实体数量与 `.part-banner` 数量比对（「章节横幅数 = main 段数」）；写成 div 会报 `banner=9 main=0` 直接 FAIL。CSS 选择器仍写 `.mainwrap` 即可（class 选择器不受标签影响），闭合处保留 `</main><!-- /mainwrap -->` 注释便于定位。**注**：脚本早先的正则是写死的 `r"<main>"`，遇到带属性的 `<main class="...">` 会误判——已改为 `r"<main\b[^>]*>"`（宽松匹配属性）。改课件外壳类名时若脚本报「banner ≠ main」，先确认是文件真缺 main，还是脚本正则未更新。
- **`.prep` 的 `<span class="pt">` 每项必须闭合 `</span>`**（2026-09-18 两次复发）。六项各漏一次 → 课件 `<span>` 计数差 6 → 体检「标签配平」直接 FAIL。这个错极易漏，因为浏览器渲染看不出来（`</label>` 会兜住），只有计数才发现。写完 `.prep` 后**先跑一次体检再合并**，别等交付前才发现。
- **分块 `_build` 文件可能与已交付版不同步**（2026-09-18 实测）。改完一轮后重新合并时，分块里可能还留着旧的 `PART ·`、重号的横幅 `id`、漏掉的 `<main>` 拆分段——即「上一轮的修复没落到分块上」。**合并前先逐块核对**（横幅数／main 数／禁用词／span 配平），别默认分块是对的；发现问题改分块而不是改合并产物，否则下次重合并又白改。
- **`.prep` 的实际位置以用户当下要求为准**（2026-09-18）：它不计页码，所以能从顶部搬到附录末尾而不影响任何引用。搬完只需确认「`.prep` 在最后一页之后、`</main>` 之前」，并渲染一次看六项网格与复选框是否正常。
- **全课改名要连带改 config 的四处**（2026-09-18 实测踩坑）。用户说「全课改名」时，除了课件（`<title>`／meta description／`.brand`／`.nav-links`）与学案（报头／页脚／每页抬头），**还必须改 `fourpiece-config.json` 的 `course`／`courseware`／`workbook`／`lecture.chapters[*].subtitle`**——漏了 `subtitle` 会让派生出的教师讲课稿残留旧课名。改完 grep 一次旧名，确认四处都归零。
- **删旧文件再交付**：改名后旧课名的 HTML 要删掉（同一门课不留两份），否则交付目录看着像两个课。**删前先确认新文件已生成且体检全绿**。
- **专门写一个 `verify.py` 当体检器，比每次手敲 Grep 强得多**（2026-09-17 实测）。把 §5.5.1 那张硬规则检查表一次性写成脚本，`sys.argv` 收文件路径与报告路径，把结果 `Out-File` 成 txt 再 `Read`。改一轮跑一次，全绿才算完。同类改造可直接复用：本次的 `verify.py`（14 项结构体检）、`caps_audit.py`（短句按语义段审计）、`static_check.py`（内容结构抽查）都在 `WorkBuddy\<日期>\build\` 下留档。
- **四件套的第 3、4 件（设计方案 md／Prompt 合集 md）已有可复用生成工具，在 `scripts/fourpiece/`**（`fp_extract.py` 抽结构 → `fp_design.py`／`fp_prompts.py` 生成，`fp_run.py` 一键出两件；配置模板 `assets/fourpiece-config.example.json`）。任何课程只要先有第 1 件课件 HTML，跑 `fp_run.py` 即可派生第 3、4 件，无需手抄。脚本全部显式 `encoding="utf-8"`，可直接用隔离 Python 运行。
- **批量文本处理一律走 Python**，不要用 PowerShell 的正则替长文件——PowerShell 的 UTF-8/GBK 转换会把中文和 emoji 弄乱，Python 显式 `encoding="utf-8"` 稳得多。
- **文件落盘后一定回读校验**：`(Get-FileHash -LiteralPath $a -Algorithm SHA256).Hash` 与目标比对，确认 `HASH SAME: True`，再宣布「部署完成」。

## 自我进化机制（遵循 `cyx-skill-evolution` 通用条款）

**本技能不是一次写死的。** 用户拿本技能做简版课件 / 学案时提的每一条修改意见，都可能是适用于**所有后续同类交付**的规则；把它挑出来写回本文件，本技能才会越用越准。判定、留痕、回退规则见 `cyx-skill-evolution`。

**触发**：用户对已交付的课件或学案提意见；同一类意见出现 ≥2 次 → 从「建议」升为强约束；我主动发现错命令、缺步骤 → 不等指令当场修。
