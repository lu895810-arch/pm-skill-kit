# Cyx Github Search Output

把一份 GitHub 开源调研的**内部草稿**，整理成**对外输出版**。

上游 `cyx-github-search` 产出的草稿是"给自己看的"——它要保留检索过程、方法学、留痕，方便复核。但对外（给老板、客户、公开文档）时，这些内部痕迹反而干扰阅读，且暴露"这是 AI 生成的草稿"。本技能就是一套"草稿 → 对外版"的精简手法，基于真实编辑短剧制作平台调研报告的实战提炼。

## 核心思想：草稿 vs 对外版

| 维度 | 草稿（保留） | 对外版（只留） |
|---|---|---|
| 目的 | 可追溯、可复核 | 干净、可读、直接当选型清单 |
| 内容 | 关键词矩阵、口径说明、方法说明、脚注、观察框 | 核心仓库表 + 选型与风险建议 |
| 语气 | 内部对齐口吻（"先对齐免得跑偏"） | 中性、专业、无生成器留痕 |

判据：**这条信息对"外人做选型决策"有没有用？没用就删。**

## 对外输出去冗余清单（按出现顺序）

从草稿里逐一判断、删除以下内部痕迹：

1. **第一节「关键词矩阵」（整节，id=sec-kw）**：检索用的中英文关键词表，对外无阅读价值 → 删整节（标题 + 表格）。
2. **标题副标题 `.sub`**（如"基于 GitHub 连接器真实检索的开源生态盘点…"）：宣传/汇总口吻 → 删。
3. **口径说明框 `.note`（第一个，含 DramaBox 对比）**：内部对齐用 → 删。
4. **chips 标签行 `.chips`**（口径 / 数据截至 / 检索 / 授权 4 个 span）：内部元信息 → 删。
5. **脚注 `.foot`**（"本报告由 xx 技能驱动：①…⑥…"）：生成器留痕 → 删（连同空 div，避免遗留底部分隔线）。
6. **「方法说明」节（id=sec-method）**：内部方法学 → 删整节。
7. **各节标题下的引导子句 `<p class="sub">`**（如"这类仓库多为…不直接生产用"）：删。
8. **观察框 `.note`（如 LibTV 开源替代威胁段）**：内部旁注 → 删。

### 必须保留（对外版核心）

- 眉题 `eyebrow` + 主标题 `h1`
- 左侧目录 `toc`（仅保留留下来的节）
- **一、线 A 整站 / 产品级参考表**
- **二、线 B 组件级复用表**
- **三、选型与风险提醒**（col2 双栏）—— 这是对外最有价值的一段，务必保留

> 注意：草稿里可能**有多个 `.note`**（口径说明、观察框等）。删之前用内部文本区分，别误删要保留的那个；当前模板里所有 `.note` 都是内部痕迹，全删即可，但表格正文里同名关键词（如 LibTV 出现在 Toonflow 描述与选型建议中）是正文内容，要留。

## 重排规则

- 删除某节后，目录 `.toc a` 与正文 `<h2>` 的"一/二/三"序号需**连续重排**；`id` 是锚点不用改，`href` 仍指原 id，只改文案序号。
- 整节删除时，**同时删** toc 里对应的 `<a href="#sec-xxx">`，否则目录会出现死链接/跳号。
- 若 footer 内有"①…②…③…"流程图，删掉的环节要**同步去掉并重编号**，保持连贯（例：删了关键词矩阵步骤后，原 ⑥ 步收成 ⑤ 步）。

## 时间口径修正

- 顶部 chips 的「数据截至 YYYY-MM-DD」→ 改成最新日期。
- 方法说明里的「（YYYY-MM-DD 查询）」→ 同步更新（若该节保留）。

> 旧日期常**多处并存**（数据截至 + 查询日期，有时还有文件名日期）。Grep 全部 `YYYY-MM-DD` 排查，避免遗漏。

## 编辑操作 SOP（基于真实踩坑）

1. **Read 当前文件最新内容**：多次编辑后行号会漂移，绝不可凭记忆里的行号去 Edit——先 Read 实际内容再用内容定位。
2. **Grep 用唯一中文串做锚点**：如"这类仓库多为""值得记下的观察""口径说明"，先精确定位真实行号与上下文。
3. **Edit 的 old_string 取短片段**：用"上一相邻块 + 目标块 + 下一相邻块"的 3~5 行片段，保证唯一，避免整段长匹配因空白/换行差异失败。
4. **删含闭合标签的整块时连同外层 div 一起删**：避免遗留空 div 撑出多余间距或底部分隔线（尤其 `.foot`、`.note`）。
5. **每删一处后 Grep 校验**：目标串应消失；全部改完后全局 Grep 一遍，确认无残留（含旧日期全量排查）。
6. **编号重排**：把后续 `<h2>` 序号前移（二→一、三→二…），同步改 toc 文案。
7. **present_files 刷新预览**：让用户对照原截图逐项核查。

## 已知坑

- **并行 Edit 同一 HTML 易失败**：报 `EBUSY` 或 `String not found`。遇此**单发重试**，不要对同一文件批量并行编辑。
- **旧日期多处**：Grep 全部 `YYYY-MM-DD`，逐个改。
- **同名关键词误删**：表格正文里的关键词（如 LibTV）与要删的框里关键词重名，删框时只删框，别动表格正文。
- **多个同类块**：`.note`、`.sub` 可能不止一个，逐个用内部文本区分，删对目标。

## 交付检查单

- [ ] 目录与正文节一一对应、编号连续、无死链
- [ ] 无内部痕迹（关键词矩阵 / 口径说明 / 方法说明 / 脚注 / chips / 引导句 / 观察框）
- [ ] 时间口径统一为最新日期
- [ ] 线 A、线 B 两张核心表 + 选型与风险建议完整保留
- [ ] Grep 校验目标串全部消失、无旧日期残留
