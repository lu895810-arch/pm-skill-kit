# GitHub 调研 · 对外输出规范

> 适用：把一份「GitHub 开源生态调研」内部草稿，整理成可直接对外（给老板 / 客户 / 公开文档）的干净版报告。
> 配套技能：`cyx-github-search-output`（执行 SOP + 坑位）、上游产出：`cyx-github-search`（产出草稿）。

## 一、为什么要整理

草稿是「给自己看的」——要保留检索过程、方法学、生成器留痕，方便复核。
对外版是「给别人用的」——这些内部痕迹干扰阅读，还暴露「这是 AI 生成的草稿」，削弱可信度。

**判据：这条信息对「外人做选型决策」有没有用？没用就删。**

## 二、去冗余清单（逐条核对）

| # | 草稿里的部件 | 位置特征 | 处理 |
|---|---|---|---|
| 1 | 关键词矩阵（第一节） | `id="sec-kw"` 整节：标题 + 中英文关键词表 | 删 |
| 2 | 标题副标题 | 主标题下的 `<div class="sub">` 汇总句 | 删 |
| 3 | 口径说明框 | 第一个 `.note`，含 DramaBox 对比、「先对齐免得跑偏」 | 删 |
| 4 | chips 标签行 | `.chips` 内 4 个 span（口径/数据截至/检索/授权） | 删 |
| 5 | 脚注 | `.foot`，「本报告由 xx 技能驱动：①…⑥…」 | 删（连同外层 div） |
| 6 | 方法说明节 | `id="sec-method"` 整节 | 删 |
| 7 | 节标题下引导句 | 各 `<h2>` 后的 `<p class="sub">` | 删 |
| 8 | 观察框 | 第二个 `.note`，如 LibTV 开源替代威胁段 | 删 |

## 三、必须保留（对外核心价值）

- 眉题 `eyebrow` + 主标题 `h1`
- 左侧目录 `toc`（仅保留留下来的节，编号连续）
- **一、线 A 整站 / 产品级参考表**（仓库 + 技术栈 + Star + 授权）
- **二、线 B 组件级复用表**（模块 + 组件 + 平台 + 授权）
- **三、选型与风险提醒**（双栏：能直接复用 / 建议自研，含授权红线）

## 四、版式重排规则

1. 删节后，目录 `<a>` 与正文 `<h2>` 序号连续重排（一/二/三…）；`id` 锚点不动，只改序号文案。
2. 整节删除时**同时删**对应目录 `<a>`，避免死链 / 跳号。
3. 若页脚有「①…⑥」流程图，删掉的环节同步重编号，保持连贯。

## 五、时间口径

- 顶部「数据截至 YYYY-MM-DD」→ 改最新日期。
- 方法说明「（YYYY-MM-DD 查询）」→ 同步更新（若该节保留）。
- 旧日期常多处并存，逐项排查。

## 六、交付检查单

- [ ] 目录与正文节一一对应、编号连续、无死链
- [ ] 无内部痕迹（关键词矩阵 / 口径说明 / 方法说明 / 脚注 / chips / 引导句 / 观察框）
- [ ] 时间口径统一为最新日期
- [ ] 两张核心表 + 选型与风险建议完整保留
- [ ] 全文检索目标串全部消失、无旧日期残留
