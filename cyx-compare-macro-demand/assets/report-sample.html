01核心结论：强项与弱项正好互补

两个项目都把自己定位在 AI 视频赛道的工作流编排层，不造模型，只把「剧本到画面」各环节串成生产线。但两者的完成度方向相反，形成互补：

Huobao Drama 把链路贯通到了成片（FFmpeg 本地合成、桌面端一键分发），却禁止商用、工程纪律松散、没有自动化测试；Jellyfish 工程扎实、许可证可商用、任务系统与状态约定写成文档，却止步于镜头素材，时间线与成片导出尚未实现。

两者的重叠项只有视觉一致性体系：都把角色、场景、道具做成实体库，保证跨镜头视觉统一。其余维度的强弱正好错开。

来源：两份项目分析（huobao-drama-analysis.html / Jellyfish项目分析.html）的成熟度与风险章节

02用户人群与使用场景

两者底层都是「剧本到画面」的编排层，但面向的人和解决的问题不同：Huobao 面向个人，部署与操作都在桌面端本地完成；Jellyfish 面向团队，走 Web 部署与工程化路线。下面按「用户群体 → 使用场景 → 解决的问题」三层展开。

来源：两项目分析的用户定位与部署形态章节（Huobao 桌面单机 / Jellyfish Web 自托管）

下表按用户、场景、问题逐项对照，便于核对与补充。

要素Huobao DramaJellyfish
目标用户群体个人创作者、短剧 / 漫剧爱好者；使用国内 AI 视频模型、想直接产出整片、但不熟悉剪映等剪辑工具的人；限个人 / 非商用要把 AI 短剧能力做成可商用产品的团队；重视工程纪律、需要长期演进的工程团队；自托管、要求任务状态可追溯的开发者
典型使用场景桌面单机（零外部依赖），导入小说或剧本，走完「项目 → 剧本 → 资产 → 分镜 → 视频 → 导出」六步，一键得到可播放成片并桌面分发浏览器工作台多人协作，完成「剧本 → 分镜 → 镜头素材」并接入自有产品或下游管线；容器化自托管部署
解决的问题把分镜、绘图、视频、拼接多个环节在一个桌面应用里自动串起，免去在多个工具间手工搬运与在剪映手动拼接；内置国内模型中转适配，省去配置海外模型的门槛提供可商用、工程规范、任务状态可追溯的生产底座，免去从零搭建 Web 服务与任务调度系统；适合作为长期产品地基演进

04主流程对比：成片 vs 素材

两条流水线前半段高度相似（项目 → 拆解 → 分镜 → 生成），分歧在最后一环：Huobao 多出「拼接导出」，Jellyfish 在「生成工作台」产出镜头素材后便结束。

来源：两项目主流程 SVG（huobao-drama 六步 / Jellyfish 六步含 ready 门禁）

这条差异决定了两者的真实产物形态不同：用 Huobao，最后拿到的是一段可播放、可下载的成片；用 Jellyfish，最后拿到的是一批镜头级视频素材，仍需自行到剪映等工具完成剪辑与拼接。Jellyfish 在 README 首页写「一键导出成片」，但其 roadmap 与前端目录都证实末段尚未实现，宣传与实现之间存在差距。

05架构对比

两者都是「前端 + 后端 + 基础设施」三层，但后端范式与部署取向相反：Huobao 走轻量单文件 + 桌面壳 + 内嵌二进制；Jellyfish 走企业级 Web 栈 + 独立 Worker + 外部组件。

来源：两项目架构 SVG（huobao-drama 内嵌基础设施 / Jellyfish 外部组件 + Worker）

两种范式各有取舍：Huobao 的 SQLite + 内嵌 FFmpeg + 桌面壳让个人用户零运维上手，代价是水平扩展与多用户能力缺失；Jellyfish 的 MySQL + Celery + Redis + RustFS 是标准企业级自托管组合，任务系统与状态语义因此更健壮，代价是部署与运维门槛更高，且仍停留在单机形态。

06能力成熟度对比（雷达）

八维相对评分（0–5，自估用于横向比较，非基准测试）。从图形看，两项目的优势区域互不重叠：Huobao 的高分轴对应 Jellyfish 的低分轴，唯一双方都得分较高的维度是视觉一致性体系。

来源：两项目成熟度评估（huobao-drama 七项 / Jellyfish 六项）合并归一为八维

Huobao 在链路完整度、国内模型适配、桌面分发三项得分高，在商用友好度、工程纪律、自动化测试三项得分低；Jellyfish 相反，在商用友好度、工程纪律、任务系统三项得分高，在链路完整度、国内模型适配、桌面分发三项得分低。双方唯一都得分较高的维度是视觉一致性体系，说明两者都把跨镜头视觉统一当作核心难点。

08选型建议：按使用目标选择

选型取决于使用目标，而非项目优劣。

来源：两项目综合判断章节（竞争位置 / 最大优势 / 最大短板）

若目标是既商用又要成片，两者单独使用都不完整：可把 Jellyfish 当底座（可商用 + 工程扎实），再参考 Huobao 的 FFmpeg 合成与桌面分发思路补上成片导出环节。两者许可证在此组合下互不冲突（Apache-2.0 允许派生，但 Huobao 的 CC BY-NC-SA 代码本身仍不能商用，只能借鉴其设计与二进制调用方式）。
