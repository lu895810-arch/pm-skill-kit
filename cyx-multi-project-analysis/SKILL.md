# 多项目批量分析 · GitHub 工具盘点（cyx-multi-project-analysis）

## Purpose（目的）

把「用户甩来一批 GitHub 仓库，让我整理成一份能看的报告」从随手堆表格，变成可复现的方法论：

1. **元数据先核验，不照抄用户给的标注**——Star/Fork/语言/许可证/更新时间全部走 GitHub API 取数，用户标注的许可证与 GitHub 对不上的，以 GitHub 为准，差异在口径里说清。
2. **按业务逻辑排序，不当字典排**——这批仓库如果构成一条生产链路（如「创意→剧本→分镜→一致性→剪辑」），所有章节都按这条链路排；同环节内再按 Star 高低。
3. **跨章节顺序一致**——流程图怎么分、对比表怎么排、详情卡怎么排、选型建议怎么分组，必须共用同一套环节编号（①②③④⑤）与同一顺序，否则读者会觉得「没有逻辑」。
4. **图元可点击**——流程图里的仓库胶囊点一下，直接跳到对应详情卡；靠锚点 id 唯一性保证跳转落点正确。

首例是 9 个 AI 短视频生产 Skills 仓库的盘点，方法论与具体赛道无关，任何「同类项批量盘点」都能套。

> 与 `cyx-github-analysis` 的关系：它是**单仓库深读**（产品×技术双视角、读源码核实现）；本技能是
> **多仓库横读**（只核元数据、按业务链路组织、不深挖单仓实现）。两者交付物都是单文件暗色 HTML，
> 布局与语言纪律对齐（见「四」「五」），避免各写一套。

## How to use（如何使用）

1. 收到仓库清单后，先按「一」批量核验元数据，**不要先动笔也别照抄用户给的 Star/许可证**。
2. 识别这批仓库的业务链路，定下环节编号轴（如 ① 创意 → ② 剧本 → ③ 分镜 → ④ 一致性 → ⑤ 剪辑/产出）。
3. 按「三」的布局起手（`assets/roundup-template.html` 改内容不改骨架）。
4. 语言遵循 `~/.workbuddy/MEMORY.md` 的**语言总纲**（通俗+严谨+逻辑闭环+去 AI 味+不口语化）与 `cyx-html-style` 禁词纪律；本技能的额外红线见「五」。
5. 交付前逐项走「六、交付前自查清单」。
6. 交付后按「七、自我进化机制」回扫本轮反馈，可复用的写回本文件并记账。

## 一、批量取材：用 GitHub REST API 逐一核验

对每个 `https://github.com/{owner}/{repo}`，调用 `https://api.github.com/repos/{owner}/{repo}`，取：

| 字段 | 用途 |
|---|---|
| `stargazers_count` | Star（按千分位加逗号） |
| `forks_count` | Fork |
| `language` | 主语言（API 返回 null 记「未声明」） |
| `license.spdx_id` | 许可证（返回 `null` 记「未声明」，**不写用户标的**） |
| `pushed_at` | 最近更新（取 YYYY-MM-DD） |
| `description` | 官方一句话定位（缺失时回退到用户提供的方向，并在正文标注「按用户提供的信息整理」） |

**核验纪律：**
- **许可证以 GitHub 识别为准**。用户标注 MIT/Apache 但 GitHub 返回 `license: null`（没识别到 LICENSE 文件），一律记「未声明」，差异在「数据口径」块一句话统一说明，不在表格里写括号（见「五.3」）。
- **AGPL-3.0 / 非标准协议（NOASSERTION）要标示**，这是商用合规硬信息，不能抹平。
- 一次性并行发多个 WebFetch（每个仓库一个），拿回结构化字段再填表，不要凭印象补数。

## 二、流水线排序法（本技能的核心）

当这批仓库构成一条生产/使用链路时，**用业务顺序当主键**，星标当次键：

1. 先画出链路（例：AI 短剧 = 创意立项 → 剧本/故事记忆 → 分镜/提示词 → 画面一致性 → 剪辑/产出）。
2. 给每个仓库定「所处环节」标签，可跨环节（如某工具既管分镜又出成片，标 ③⑤）。
3. **四节共用同一顺序**——
   - 制作流程视图（流程图）：按①→⑤分 stage，每 stage 内列仓库胶囊。
   - 横向对比总表：行按①→⑤排，同环节内 Star 高到低。
   - 逐个仓库详情：卡片顺序与表格完全一致。
   - 按目标选型建议：卡片带①→⑤环节徽章，分组与上面一致，每个工具只归入它**主打**环节（消除跨卡重复）。
4. **跨环节工具落到主环节**：某工具若夹在中间打断顺序（如标「③⑤」却排在第 4 位），把它挪到主环节位置、标签只留主环节编号，避免读起来跳。

判据：删掉任意一节，剩下三节的环节顺序还一致吗？不一致就重排。

## 三、交付物规格（单文件暗色 HTML）

起手直接用 `assets/roundup-template.html`，改内容不改骨架。

| 项 | 规格 |
|---|---|
| 整体布局 | `grid-template-columns: 232px minmax(0,1fr)`；去 `max-width`/`margin:auto`，正文贴左栏起排、占满剩余宽，不居中留空岛 |
| 左侧栏 | 全高贴左、带右边框分隔；顶部 brand 块（标题一行横排，不换行），下面紧跟目录（**不加「目录」小标签**，直接列章节），`position:sticky;top:0` 滚动跟随 |
| 窄屏 | `≤1000px`：左栏转 `static` 横排、正文单列 |
| 目录 | 章节锚点 `#s1`…`#s4`；条目带序号（与正文 `h2` 一字不差） |
| 数据口径块 | 标题区底部一个 `.scope` 框，列「数据来源 / 收录范围 / 许可证口径 / 定位表述」四条（见「五.3」）——替代逐卡警告 |
| 流程图 | 每环节一个 `.stage`，仓库为可点胶囊 `<a class="ptag" href="#cN">`，`href` 指向详情卡 id |
| 对比总表 | 列：名称 / 所处环节 / Star / 主语言 / 许可证（核验）/ 最近更新 / 核心定位 |
| 详情卡 | 每张 `id="cN"`（N 与流程图、表格对应的仓库一致）；**表格行 id 必须加 `row-` 前缀**（见「四」） |

**锚点唯一性（高频坑）：** 对比表行和详情卡若用同一套 `c1…cN` id，点流程图胶囊只会跳到先出现的表格行、永远到不了卡片。解法：**表格行 id 用 `row-cN`**，详情卡保留 `cN`，胶囊 `href="#cN"` 就稳落详情卡。卡片加 `scroll-margin-top` 留落点留白。

## 四、语言与版式红线（本技能额外项）

1. **第三人称**：统一「用户标注」「GitHub 识别为」，不写「你标注」「你标 MIT」。grep 复查全文第二人称零残留。
2. **去 AI 味、去口语**（遵循 MEMORY.md 语言总纲）：
   - 「一句话定位」→「核心定位」；「skill 集合」→「工具集」；「Agent 自动化剪映」→「让 AI 自动操作剪映」。
   - 「生产流水线」→「制作流程」；「持久化记忆」→「能记住全部设定与情节，防止前后矛盾」。
   - 禁 emoji、禁说明性文字（口径声明/方法论自述）、禁页脚免责语。
3. **括号清理**：许可证列写「未声明」不写「未声明（标 MIT）」；差异统一收口到「数据口径」块一句说明，不散在表格和卡片里。
4. **删冗余提示块**：不写逐卡「用户标注为 X，但 GitHub……需进仓确认」的黄色 note；这类信息要么进「数据口径」块，要么在正文轻描「按用户提供的信息整理」。
5. **术语白话定义**：AI 短剧/视频领域词第一次出现给「是什么 + 为什么叫这名字」（如分镜、Remotion、剪映），外行能复述才算讲清。
6. 叙述用「本次盘点」「报告」，不写「本报告」「本文将」。

## 五、多轮迭代纪律（截图指哪改哪，但改一处全局对齐）

用户常发截图圈出某处要求改。处理原则：

- **指单点，想全局**：用户圈「第 03 节顺序没逻辑」，根因往往是「全篇环节口径没统一」，要回头把流程图/表格/卡片/选型四节一起对齐，不是只挪那一节。
- **删块要连带**：删一个章节（如独立许可证章），要同步收目录条目、改后续章节序号、清无用样式。
- **布局割裂先看结构**：目录飘在左侧留大块空——根因是「卡片式浮动 + 内容流分离」，改成「全高左栏通栏 + 占满正文」的 grid 布局。
- 每次改完做三件事：grep 复查残留词（如「你」「未声明（」「目录」）→ 删无用 CSS → 刷新预览。

## 六、交付前自查清单

- [ ] 每个仓库的 Star/语言/许可证/更新都来自 GitHub API？用户标注与 GitHub 不符的是否已在口径中说明？
- [ ] 四节（流程图/表/卡/选型）环节编号与顺序完全一致？有无仓库夹在中间打断顺序？
- [ ] 流程图胶囊点击能落到详情卡（非表格行）？表格行 id 带 `row-` 前缀、卡片 id 无前缀？
- [ ] 左栏目录滚动跟随、窄屏回退单列？版心贴左栏无空岛？
- [ ] 全文第三人称、第二人称零残留？「你标注」「未声明（标 X）」等已清？
- [ ] 「数据口径」块齐全（来源/范围/许可证口径/定位口径）？逐卡黄色 note 已删？
- [ ] 章节标题名词短语、无 AI 味？术语首次出现有白话定义？
- [ ] 窄屏（≤1000px）布局不挤压、不溢出？

## 七、自我进化机制（遵循 cyx-skill-evolution 通用条款）

用户提的修改意见按三步判定：**通用**（换批仓库仍成立）→ 回写本文件对应章节；**个案**（只对这份产物成立）→ 只改当期产物。

| 反馈类型 | 典型原话 | 改本文件哪一节 |
|---|---|---|
| 排序逻辑 | 「这个顺序没有逻辑」「按制作先后排」 | 二（流水线排序法） |
| 锚点跳转 | 「点这个定位不到详情」 | 三（锚点唯一性） |
| 语言版式 | 「不要 AI 术语」「全文改第三人称」「括号去掉」 | 四（语言与版式红线） |
| 结构增删 | 「这节不要了」「加个数据口径」 | 三（交付物规格）/ 五（迭代纪律） |
| 布局 | 「目录放左边」「视觉割裂重排」 | 三（布局）/ 五（迭代纪律） |

**沉淀三步（每次反馈后必做）：** ① 规则与「六、自查清单」同步；② 在 `references/feedback-log.md` 追加一行（编号 `#N`、日期、原话节选、类别、落点、处置）；③ 一句话告知用户「这条记进本技能了」。
