# 界面问题清单（cyx-bug-demand）

## Purpose（目的）

把「产品负责人看着界面截图说这里有问题」这件事，变成一份**能拿去评审、能持续记账、能一眼看出重灾区**的问题台账。

它来自一次真实跑通的交付（爱创梦工厂 AI 短剧工作台界面问题清单，17 条问题、7 张证据截图、两轮图表返工、一次文件损坏整机恢复）。那次做对的三件事，也是本 skill 的交付标准：

1. **条目可追溯**——每条问题对应一张证据截图（截图页「上说明、下图片」统一格式），说明行标明对应的明细序号；截图同时落盘到项目 `screenshots/` 目录，不只活在会话里。
2. **台账可生长**——用户随时发新截图 + 一句话，就能追加；删条目、改标题、调图表都是原地增量修改，三页自动联动，不推倒重来。
3. **图表不说谎也不添乱**——统计公式联动明细（COUNTIF），改明细不改统计；排序「最严重在顶」；标签直接长在图元上，不依赖渲染器画对轴标签。

**与既有技能的分工**：

| 事项 | 归谁 |
|---|---|
| 三表结构、条目撰写、截图证据页、多轮联动维护 | **本 skill** |
| 首轮建表的设计范式（记录型+统计型原型、schema 原则） | 借 `tencent-docs-sheet-generation` 的 references，起步用 |
| openpyxl 图表 / 图片 / zip 补丁的具体代码 | **本 skill** `references/snippets.py` |
| 语言纪律（条目描述通俗、去 AI 味） | `~/.workbuddy/MEMORY.md`「语言总纲」 |
| Excel 修改的文档路由（改既有 xlsx 走哪条路） | `tencent-docs-routing` |

## When to use（何时触发）

**触发**：

- 用户发来产品界面截图，说「把这里的问题整理成表格」「写上去」「记到清单里」。
- 已有本 skill 产出的问题清单 xlsx，用户继续发截图追加、要求删某条、调图表样式、改标题、改截图页排版。
- 用户要求「bug 清单 / 问题登记表」，材料是截图或口述的界面问题。

**不触发**：

- 用户要写需求文档 / PRD（哪怕材料也是截图）→ `cyx-summary-need`；本 skill 的落点是**问题台账**（现状缺陷 + 修复建议），不是需求条目（要做什么 + 验收标准）。
- 通用 Excel 生成（非问题台账）→ `tencent-docs-sheet-generation`。
- 用户已在对话里明确用别的表格流程。

## 交付物结构（三工作表，固定骨架）

单文件 xlsx，三个工作表：

### 1. 问题清单（明细主表）

- 第 1 行：标题（A1:H1 合并、微软雅黑 14 加粗居中、行高 30，命名格式「产品名（产品形态）界面问题清单（日期）」——随内容覆盖面更新，别停留在最早一张截图的范围）。
- 第 2 行：表头，八列：`序号 | 界面模块 | 问题类型 | 严重程度 | 问题描述 | 用户影响 | 建议解决方案 | 修复优先级`。
- 第 3 行起：数据行。带 auto_filter；严重程度条件格式高亮（高=红、中=黄、低=绿）；「问题类型」「严重程度」「修复优先级」三列下拉验证（DataValidation），**范围一次拉到比当前数据多若干行**，减少后续碎片补丁。
- 列宽：问题描述 / 用户影响 / 解决方案三列 40+，开启 wrap_text。
- **主表内不嵌图片**（用户明确要求过）——图片只进「界面截图」页。

### 2. 统计可视化

两块统计表 + 两张图，全部公式联动明细：

- **问题类型统计**：A 列类型名、B 列 `=COUNTIF(问题清单!$C$3:$C$末行,A行)`、C 列占比 `=B行/$B$合计行`；**按数量从高到低排**（平手时保持用户列举顺序）；合计行在类型区下方。
- **严重程度统计**：高/中/低三行，同样 COUNTIF + 占比。
- **横向条形图**（各类型问题数量）：见「图表配置标准」。
- **饼图**（严重程度占比）：见「图表配置标准」。

### 3. 界面截图（证据页）

每块固定格式（用户明确要求的统一格式）：

```
说明行（蓝底加粗，全文如「证据 N（对应序号 X）模块：问题一句话」）
  └─ 空一行
图片（统一 1500px 宽、按原图比例等比高、OneCellAnchor 固定像素尺寸）
  └─ 空 2 行
下一块说明行……
```

- 全表行高统一 15pt（=20px），图片占行数按 `ceil(图高px / 20)` 折算，保证视觉间距处处一致。
- 说明行与明细序号的对应关系在删条目后必须改写（见「删除条目」）。

## 工作流

### 首轮建表

1. **截图落盘**：`cp <剪贴板缓存路径> <项目>/screenshots/YYYY-MM-DD_模块_问题关键词.png`。这是长期规矩：对话里的截图必须落盘，不能只留在会话。
2. **路由**：用户意图是「生成新 Excel」→ 按 office_skill_routing 走 `tencent-docs-routing` → `tencent-docs-sheet-generation` 借设计范式；脚本自己写（openpyxl），落盘工作区根目录，工作脚本放 `.问题清单名.ref/` 隐藏目录。
3. **读图提炼条目**：一张截图通常拆 1~N 条（见下节）；严重程度与优先级的判定依据是「是否阻断主流程 / 是否有绕行方案」。
4. **生成三表**：按上面骨架写 build 脚本；证据图同步嵌入截图页。
5. **重算校验**：跑 `tencent-docs-sheet-generation` 的 `scripts/recalc.py`（LibreOffice 引擎），公式 0 错误才算完。
6. **present_files 交付**，汇报里引用用户原话确认理解（「你说的 X 我记成了 Y，原意相反告诉我改」）。

### 追加条目（最高频操作）

用户发新截图 + 一句话 → 一轮闭环：

1. 截图落盘 + 作为新证据块追加进「界面截图」页（按统一格式接在末尾）。
2. 明细追加 N 行（序号接续），问题类型若是新分类 → 加进下拉验证的选项列表。
3. 统计公式范围扩到新末行；**若统计表带合计行且插在类型区下方，新增类型时要在类型区插入行**（合计行、程度表、图表引用整体下移）。
4. 条件格式、下拉验证覆盖新行。
5. recalc 校验 + 补工作日志 + 交付汇报（说明记了第几条、怎么理解的、联动更新了什么）。

### 删除条目

删一行牵三页，必须同步：

1. 明细删行 + **后续序号重排** + auto_filter / DV / CF **整段重建**（删行后碎片范围不可靠，别打补丁，全清重建覆盖整个数据区）。
2. 统计公式范围收缩；被删类型若归零，从统计表移除该类（图表引用同步）。
3. 证据页对应说明行改写：序号引用前移、已删问题的表述去掉；图片锚点不受 delete_rows 影响（图片在别的 sheet 时），但要人工确认。
4. recalc + 交付时告知「原文在哪个脚本里可以捞回」。

### 其他高频修改

- **改标题**：A1 + 工作簿属性 title 一起改；命名要覆盖当前全量内容。
- **统计表排序**：重排类型区行 + 重写本行 COUNTIF 公式（引用本行 A 列）+ 图表类别轴反转（见下节）。
- **图表美化 / 修标签**：重建图表前先记录旧图的 anchor / width / height 原位复用。

## 问题条目撰写规范（一句话 → 条目）

用户一句话里常含**多个问题**，拆开各记一条，宁可多拆不合并。拆分维度：

- **状态矛盾**（如 ACTIVE + UNVERIFIED 同挂）、**反馈缺失**（配置后无验证结果）、**按钮无状态**（无 loading/失败提示）是三个问题，不是一条。
- **功能缺陷**（点了报错）和**报错文案笼统**（不知道怎么自救）分记，后者可并入前者解决方案但影响面不同。
- **用户口述的设计决策**（「以集为单位、后续迭代分镜级」）记为「主流程设计」类，解决方案原样保留用户的分步建议。
- **用户的判断句**（「这两个功能重复了，去除一个」「改个名字」）也是问题条目：类型归「信息架构」，解决方案就是用户给的指令。

每条的字段纪律：

- **问题描述**：写现象不写猜测，报错原文引用进描述（「生成服务暂时失败，请稍后重试」）。
- **用户影响**：写链路断点（「配音链路在这里断掉」「评审第一眼看不到最高风险项」），不写空话。
- **解决方案**：分两层记——治本（接入 TTS 模型 / 互斥状态机）+ 治标兜底（未接入时按钮置灰并提示具体缺什么）。
- 汇报时**逐条引用用户原话对照**，理解反了当场改（真实案例：「资产从剧本提取 vs 剧本前先备资产」记反方向，靠对照发现）。

## 图表配置标准（踩坑换来的定式）

### 横向条形图（各类型问题数量）

- `type='bar'`（横向），`gapWidth=60`，尺寸约 15×7.5~9cm。
- **数据标签直接长在条上**：`showCatName=True + showVal=True`，`separator='  '`，`dLblPos='outEnd'`，字号 10——预览渲染器对轴标签的渲染不可靠（跳显、漂移、画到顶部平铺都遇到过），标签上条后渲染器再怎么画错轴都不影响识读。
- 类别轴隐藏游离标签：`tickLblPos='none'`（**openpyxl 不序列化这个值，必须 zip 层往 catAx 的 minorTickMark 之后插 `<tickLblPos val="none"/>`**）。
- **「最严重在顶」= 数据降序 + 类别轴反转两者缺一不可**：`x_axis.scaling.orientation='maxMin'` + `y_axis.crosses='max'`（数值轴保持在底部）。横向条形图类别自下而上排列是 OOXML 标准行为。
- 数值轴整数刻度：`number_format='0'` + `majorUnit=1`。

### 饼图（严重程度占比）

- **语义配色**：高=C00000 红、中=ED7D31 橙、低=70AD47 绿（DataPoint + GraphicalProperties 逐点上色）。
- **右侧图例**（`position='r'`，11 号字）承载类别名；扇区标签只留百分比（`showPercent=True`，其余全关，`numFmt='0.0%'`，`dLblPos='outEnd'` 外侧防遮挡，加粗 11 号）。
- **数值和占比不能同显**：两者共用一个 numFmt，同显必坏一个（占比渲染成 0 的事故根源）。类别名给图例、数值给旁边的统计表。
- `numFmt` 必须带 `sourceLinked="0"`（openpyxl 默认不写，zip 层补），否则部分渲染器跟随源单元格格式又变回 0。

### 图表生命周期铁律

1. **LibreOffice recalc 每次都会重写图表 XML**：丢饼图 numFmt、把 tickLblPos 重置回 nextTo、把集合级 dLbls 改写成逐点 dLbl。**recalc 之后必须复查图表 XML，必要时 zip 层回补，补完必验**。
2. openpyxl 重建图表后 chart1/chart2 编号会互换——核验按内容找文件，别按文件名。
3. XML 校验字符串要含空格：`'<legendPos val="r" />'` 写成 `'/>'` 结尾会误判 False。
4. `DataLabelList.numFmt` 是字符串描述符，赋 NumFmt 对象会把 repr 写进 XML。

## 硬约束（踩坑清单，违反必翻车）

1. **保存安全**：对含图片的工作簿做大改动，**先存临时路径再覆写原文件**。真实事故：openpyxl 写图片阶段报错，`wb.save` 半途而废，ZIP 中央目录未写，原文件损坏且不可抢救（图片 ref 的 BytesIO 被 PIL 消费关闭所致）。
2. **加载态图片的字节**：保存前把每个 `img.ref` 读成原始字节并换成新 `io.BytesIO`；更稳的做法是**从 xlsx 压缩包的 `xl/media/` 取字节重建 Image 对象**，完全绕开 ref 状态问题。PIL 读尺寸用独立的 BytesIO，别碰 ref。
3. **清统计表旧区域前先 unmerge**：合并单元格是 MergedCell 只读，直接清值报错。
4. **DV / CF 删行后整段重建**，不修补碎片范围。
5. **目标文件被 Excel / 预览进程锁定时**：先读盘确认现状是否已满足要求，满足就不强写；确要写时 `os.replace` 会报 WinError 5，但 `open(p,'wb')` 直接覆写往往可行（zip 层修补走「写 tmp → 读字节 → 覆写原文件」）。
6. **脚本命名别撞标准库**：`inspect.py` 会导致 openpyxl 循环导入，用 `check_wb.py` 这类名字。
7. **每轮修改后必跑 recalc + 核验图表 XML + 补工作日志**，三项缺一不可。
8. **核验显示尺寸要解包 xlsx 看 drawing XML 的 cx/cy**（EMU÷9525=px）；openpyxl 读回的 `img.width/height` 是原生尺寸不是保存的显示尺寸。

## 多轮交互纪律

- **每轮交付必汇报**：记了第几条、怎么理解用户原话的、联动更新了哪些（下拉选项 / 统计范围 / 图表 / 证据页），三页数据分布（共 N 条，高 X / 中 Y / 低 Z）。
- **发现连带问题主动说**但不擅自记（「顶部横幅报错和序号 9 是同一类病，想单独立条可以拆出来」）。
- **重大事故如实汇报**：文件损坏、恢复来源、哪些修改是重放的、桌面副本落后了要同步——不藏着。
- **可复用脚本留档**：建表 / 追加 / 删除 / 恢复脚本都放 `.问题清单名.ref/`，删掉的条目原文能从脚本里捞回。
