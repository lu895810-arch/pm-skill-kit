# HTML 呈现风格指南（cyx-html-style）

## Purpose（目的）

提供 HTML 产出物的**呈现侧**规范：暗色科技风视觉（统一配色变量、字体、网格背景、语义色板与组件类），以及跨格式通用的语言约束（去 AI 味、反塑料味、克制图文、论证不跳脱）。配套 `assets/cyx-html-style.css` 含完整 CSS 变量与组件类，复制到产出物即可套用。

**与 `cyx-md-style` 的分工**：本 skill 管「渲染出来长什么样」；`cyx-md-style` 管「Markdown 里写什么、怎么组织结构」。本 skill 第一节的语言约束（去 AI 味、反塑料味等）对 Markdown 与 HTML 两种格式同样适用，`cyx-md-style` 不重复维护、直接引用本节。

## When to use（何时触发）

- 用户要求内容「去 AI 味 / 图文并茂 / 简洁专业 / 逻辑闭环」。
- 用户要求「暗色科技风 / cyx 风格 / 统一配色」的视觉产出。
- 用户要求生成单文件 HTML（报告、落地页、看板、复盘、对比页）并指定风格。
- 用户希望内容摆脱"AI 生成痕迹"、强调可视图文表达。

若用户已指定其他设计系统（如公司品牌规范、浅色主题），不触发本 skill，改遵其规范。

## How to use（如何使用）

1. 复制 `assets/cyx-html-style.css` 的 `:root` 变量与组件类，注入到产出物 `<style>`（或 `<link>` 本文件）。
2. 语言层遵守「一、语言风格规范」；论证层遵守「一.6 论证缜密、不跳脱」；视觉层遵守「二、色彩与视觉风格」+「四、AI 塑料味反面案例与避坑」。
3. SVG 内用 `<tspan>` 而非 `<sup>`/`<b>`（见「三、SVG 渲染规则」）。
4. 交付前按「六、交付前自查清单」核对。
5. **交付后**：用户提的任何修改意见，先判通用性，再把通用项按「七、自我进化机制」回写本文件与 `assets/cyx-html-style.css`——本 skill 靠这一步越用越准。

| 赋能、抓手、闭环、颗粒度、组合拳等空话 | 具体动作与结果 |
| **「首先／其次／最后」三段套** | 直接陈述；必要处最多用一个承接词 |
| **「综上所述 / 值得注意的是 / 不难看出」等过渡填充句** | **删**（无信息量的过场话） |
| **「不仅……而且……」「既……又……」对称排比充字数** | 拆成两句陈述，各说各的事实 |
| **口语 / 大白话 / 方言腔**：「变砖」「捏成」「塞一个」「躲限流」「卖铲子挖矿」「抽走」「卡准」「强绑」「拼成」「说白了」「你看」「那几家伙」这类口头语、俚语式动词、聊天开场；以及**轻度口语词**：「很麻烦 / 很烦 / 就能用 / 白白消耗 / 活儿 / 东西 / 手感 / 挑片 / 抽卡 / 把功夫花在 / 底子」 | **改成中性书面语**，通俗度不减（「上游一抽薪就变砖」→「上游一旦收紧，功能即刻失效」；「把模型拼成流水线」→「把多家模型编排成流水线」；「来回切很麻烦」→「来回切换操作繁琐」；「活儿都还在」→「任务都还在」）。**「去 AI 味」的对岸不是「口语化」——两头都是毛病**（2026-09-28 Lulu 原话「去除口语等内容，语言要通俗易懂且专业」）。判据：**这句话放进给客户的正式材料，是"严谨专业"还是"聊天口气"？**（2026-09-29 补充轻度口语样本） |

| **行业缩语 / 黑话（未经白话定义的术语）**：耦合、粒度、跑通、运维、兜底、语义、系统性、可插拔、全量、交付、排障、空烧、打补丁、各做擅长的事、试错零成本、数据主权、可视化、透视、降级、快照语义、生产节拍、链路、幂等、对齐比对 | **直接改用中性书面白话**（耦合→绑在一起；粒度→控制范围；跑通→走完流程；运维→安装和维护；兜底→保底；语义→含义/方式；系统性→整套；可插拔→可选；全量→全部；交付→用法/部署；排障→排查问题；空烧→白白消耗；打补丁→加一段统一处理；各做擅长的事→分工明确；试错零成本→反复试也不浪费；数据主权→数据由用户掌握；可视化/透视→一目了然/可一键；降级→备用方案；快照语义→记下当时状态；生产节拍→推进节奏；链路→过程；幂等→重复提交不重复；对齐比对→逐一比对）。**原则：行业缩语一律直接换白话，不靠读者猜**（2026-09-29 全文审查补充，覆盖 AI 短视频对比文档去味改写） |

写法原则：**直给内容，不教读者"怎么读"；用短句和数据说话，不用排比口号。**
**「去 AI 味」≠「说口语」**：目标是**通俗易懂 + 专业严谨**两点同时成立——外行能用自己的话复述，但不出现 slang、不出现聊天口气。判据：**这句话放进一份要交给客户的正式材料里，合适吗？**

> **跨格式语言总纲（2026-09-21 定，凌驾于本表之上）**：一切文字产出——不限 HTML——都要满足
> **通俗易懂、专业严谨、叙事逻辑闭环、段落衔接流畅、去 AI 味**五条；本表是"去 AI 味"在 HTML 场景的下钻，
> 「一.4 通俗易懂且专业」「一.5 逻辑闭环严谨」「一.6 论证缜密、不跳脱」是其余三条的落地。
> 总纲原文见 `~/.workbuddy/MEMORY.md`「语言总纲」。

**不要机械清洗词语：**「分析」「推演」「论证」「总结」等词在正文中有明确对象和动词关系时可以正常使用；只禁止它们脱离内容、单独充当小节标题、角标或装饰 chip。优先删除无信息的标签，不要为了避开某个词而硬换成另一套同样生硬的词。

### 0. 数据可信强红线（最高约束，凌驾于风格之上）

**这一条独立于「去 AI 味 / 反塑料味」之上，是产出「能不能交付」的硬性条件。**

**铁律：** **以事实为基础，宁可不写，不知道的请勿盲目自信生成。**

具体执行：

1. **每个数据点必须有出处**——脚注写明「机构 + 报告名 + 时间 + 可信级标签」，缺一不可。
2. **拿不准的数据不能写**——若没有可信来源，宁可标注「推演 / 估算 / 抽样」「数据待补」，也不写一个看似权威但实为编造的数。
3. **机构估算 ≠ 官方普查**——媒体转述某机构估算、机构官网无原文 PDF 的，脚注必须显式标「媒体转述，非机构官方直接发布」。
4. **口径换算要写明推导锚点**——当数字是从其他指标折算出来的，把原始基数、渗透率、折算系数列清楚，不能直接给一个看似精确的「合成数」。
5. **样本结论不越界外推**——样本 N=128 推出的结论，不能直接写成「全行业 / 普遍认为」；外推处必须标注边界与风险。
6. **绝不「自信生成」看似有理的数**——常见高危场景：
   - 「市场上大概有 XX%」「行业普遍为 YY 元」（无来源）
   - 「预计未来 3 年将增长到 XX 亿」（无模型、无锚点）
   - 「同类工具报价约 ZZ 元」（未经定价页核对）
   - 「约 100 家厂商」（无枚举依据）
   - 「90% 用户偏好 A」（无调研）
7. **当无 P0/P1 来源、只剩 P2/P5 估算时**，正文必须标「行业抽样推演（非全行业普查）」「量级仅供参考」，并在脚注写「精确数字需上线后自采问卷 / 后台画像回填」。
8. **来源不同必须拆开**——两个数字哪怕相邻、出处不同就拆成两个脚注，绝不混在一条里含糊带过。
9. **修改过程中保留原文出处**——任何数据更新时，脚注中要同步反映新的来源和可信级，禁止脚注停留在初版来源。
10. **结论性表述同样要有案例证据**——判断、定性、排名、趋势不是「表达观点」，是对已核查事实的概括：结论句必须带**主体 + 数字 / 时间 / 资料名**。无主体断言（「不少厂商」「业内普遍」「行业领先」）与无对象无度量的空话（「赋能」「大幅提升」「前景广阔」）一律不许出现；无依据的排名与趋势要么补上比较维度与来源，要么不写。
11. **查不到就删，不改成模糊表述**——结论若回查不到事实，**整句删除**。改成更模糊的说法保留下来，等于把印象伪装成结论，比不写更糟。

**反例 → 正例：**

| 反例（盲目自信生成） | 改成（基于事实） |
|---|---|
| 「市场规模约 500 亿，年增长 30%」（无来源） | 「2026 年短视频工具市场 62.8 亿（头豹研究院 2026-05，② 第三方）；同比 +127%。」 |
| 「同类工具平均定价 500 元/月」（未经核对） | 「MiniMax 海螺订阅 $9.99–29.99/月（官网定价页，④ 实测）；国内即梦 ≈ ¥0.3/秒（官网定价页，④ 实测）。**全行业统一定价口径不存在**，各厂定价不一。」 |
| 「承制方净利率 10%」（无调研） | 「DataEye 2026H1：约 90% 承制团队亏损；承制方净利率区间 5–15%（财新周刊转述，⑤ 媒体）。」 |
| 「点众的案例说明行业普遍现象」（个案外推） | 「点众 2025 营收约 145 亿、短剧净利率不到 1%（公司自述）；该案例可作头部参照，但外推到 100+ 家承制方全样本需自采抽样。」 |
| 「预计未来 3 年增长 200%」（无锚点） | 「不预测。无 P0/P1 级预测来源。详见「必须自采」段。」 |

**自检三问**（每写完一个数据点问一遍）：
1. 这个数有可信来源吗？没有 → 删，或者改标「推演 / 待补」。
2. 来源是 P0/P1 还是 P2/P5？P2/P5 单独不能支撑核心结论。
3. 这个数是不是从其他数折算的？折算锚点写清楚了吗？

### 2. 图文并茂（克制版）
- **文字优先**：能用一句话说清就不上表；能用表说清就不上图。
- 可视化只在**比文字更清晰**时用，不为"好看"堆图。
- **大数字 `.big` 是稀缺品**：仅在数据有冲击时用，不当装饰；不要"摘要页三张大数字"的标准 AI 三件套。
- 表格、列表用最朴素的呈现，不靠配色和边框炫技。
- 图配一句话解读，解读要直给结论，**不写"从图可见"这类元语言**。

### 3. 简洁（一句话原则）
- 能用一句话说清的，绝不用两句话。
- 删冗余修饰、重复强调、废话连接词；每个板块只保留一个核心结论，一句话点透。
- 不为"详尽"而堆字——读者要的是判断，不是字数。

### 4. 通俗易懂且专业
- 专业术语首次出现时用一句人话解释；面向非本行业读者（管理层 / 投资人）也要看得懂。
- 不堆术语、不炫技；把数据"翻译"成结论，不只罗列数字。
- **段落分层**：每段一个主题，判语只在段首或段尾；同层段落用同一种结构（都分点或都整段）；**只读每段首句也要能复述该段要点**。"章法三查"（首句查 / 对称查 / 复述查）见 `cyx-research-report/SKILL.md` 八.19。

### 5. 逻辑闭环严谨
- 每页 / 每板块：数据 → 结论 → 支撑，链条完整，不出现「结论无数据支撑」或「数据推不出结论」的断点。
- 前后口径一致：同一指标全文用一个口径，版本 / 年份差异显式标注，不自相矛盾。

### 6. 论证缜密、不跳脱（强约束）

**链式论证：每个判断必须由「前提 → 推断 → 结论」三步组成，缺一步即为跳脱。**

- **前提**：可核查的事实或数据（带来源 / 口径 / 时间）。
- **推断**：从前提到结论之间的因果或换算逻辑，必须写出来，不能让读者自己补。
- **结论**：由前两步唯一推出，不超出前提能支撑的范围。

**呈现方式：让三步在自然段落顺序中出现，不要为三步加标签。**

- ❌ 左侧三行加粗「**前提**：…」「**推断**：…」「**结论**：…」三件套——这是元符号，教读者"怎么读"，与"一句话结论"是同一病灶。
- ✅ 三个段落按"事实 → 因果 → 判断"自然展开；用句首承接词过渡（"数据上看……""原因在于……""因此……""所以……"）。
- 检验：删掉所有可能为这三步添加的标签后，读者仍能从段落顺序看出"为什么这样判断"——能，则论证合格；不能，则论证本身缺环节。
- 例：
  - ❌ 标签三件套：「**前提**：付费率 3%。**推断**：71% 创作者有未满足的批量剪辑需求。**结论**：B 端内嵌是主要增量。」
  - ✅ 自然三段：「付费率约 3%<sup class="fn">3</sup>。调研显示 71% 创作者反映批量剪辑需求未被现有工具覆盖<sup class="fn">4</sup>——需求存在但 C 端转化受阻，原因主要是 3 人以上团队缺权限和审片工作流。因此主要增量在 B 端内嵌。」

**禁止的跳跃：**
| 跳脱写法 | 问题 | 改成 |
|---|---|---|
| 「付费率低，所以市场潜力大」 | 缺推断：付费率低也可能是需求不成立 | 「付费率 3%，且调研显示 71% 创作者有批量剪辑需求未满足——需求存在但转化受阻，增量在 B 端内嵌场景」 |
| 「A 增长快，因此 A 会赢」 | 增速不等于终局 | 「A 增速 40% 但基数仅为 B 的 1/5，按当前增速需 4 年才追平」 |
| 「数据显示……」（后面直接跟结论） | 省略推断 | 「数据显示 X，因为 Y 机制，所以 Z」 |
| 一个板块内换口径却不说明 | 前后不可比 | 「此处改用 2025 年 12 月口径，原因是……，与上节的差异为……」 |
| 结论范围大于数据范围（样本 128 人 → 全行业结论） | 以偏概全 | 「在 N=128 的创作者样本中……；该结论外推到全行业需谨慎，因为……」 |

**反跳脱自检三问（每写完一个判断问一遍）：**
1. 这个结论的依据在上文出现过吗？没有 → 补数据或删结论。
2. 从依据到结论的推理过程写出来了吗？没有 → 补一句因果。
3. 结论的适用范围超出数据范围了吗？超了 → 收窄表述或标注边界。

**衔接纪律：** 相邻段落之间必须有显性承接（「因此」「但」「进一步」「反过来看」），不靠读者脑补；板块末尾若有未解矛盾，显式写出而非略过。

**叙事链四环：** 结论 → 依据 → 来源 → 可信级，任一环断掉，结论就悬空；读到一处判断先问「它的依据在本文哪一节」——答不上来就是链断了。相邻结论若冲突（口径 / 时间 / 样本不同），当场说明原因，不留给读者自己调和。

### 7. 标题层级编号
- 一级标题（大板块）：`1` `2` `3` …（阿拉伯数字）。
- 二级标题（板块下内容模块）：`1.1` `1.2` `2.1` …。
- **三级标题（子节下的并列项）**：`1.1.1` `1.1.2` `2.1.1` …。**仅在子节内并列项 ≥ 3 时使用**，不要为三级标题另起新节。
- 卷首「摘要/总览」页不编入序号。
- 不重复放平铺页码（如 `01` + `1.1` 二选一，只保留层级编号）。

### 8. 标题语言风格（强约束）

标题是读者**进入板块前唯一能看到的东西**，所以必须用「读标题即知该节讲什么」的标准。推荐风格：**总结性 + 对仗**。

- **句式**：上句说**现象 / 范围 / 现状**，下句点**结论 / 判断 / 出路**。例：「份额看口径，赚钱看层次」(5+5) / 「平台端钱厚，工具层利薄」(5+5) / 「钱聚平台端，路在工具层」(5+5)。
- **字数对称**：上句字数 = 下句字数。常用 5+5、6+6、4+4。推荐 5+5（克制，便于扫读）。
- **结构对称**：上下句词性对应（名词对名词、动词对动词、方位对方位）。
- **不带修辞动作**：不要把「拆解 / 拆开 / 看一看 / 聊一聊 / 厘清 / 跑通 / 打法 / 闭环 / 抓手」等修辞动词放进标题——这是「写作动作」而非「内容」。「拆解各家盈利模式」→「各家怎么赚钱、各占多少」。
- **不带读法标签**：不用「读法 / 小结 / 解读 / 看清 / 速读 / 洞察 / 观察」等元语言作标题——见第 1 节。
- **不带模板数字**：不要「三步走 / 四个维度 / 五大关键 / 三大趋势」这种「数字 + 名词」的空洞标题——写具体名称。
- **不带描述性前缀**：不要「关于 X 的分析」「X 问题的研究」「浅谈 X」「X 综述」这种论文式前缀——直接给结论。
- **不带元描述**：不要「cyx-html-style · 暗色科技风 · 整理自xx」「本文采用 xxx 风格」等 eyebrow 元描述 chip——见第 1 节。

**反例 → 正例：**

| 反例（典型 AI 标题） | 改成（总结性 + 对仗） |
|---|---|
| 「关于短视频制作公司市场份额的调研报告」 | 「份额看口径，赚钱看层次」 |
| 「AI 短视频工具行业拆解」 | 「平台端钱厚，工具层利薄」 |
| 「核心结论：谁在真赚钱、谁在靠融资」 | 「谁在真赚钱，谁在靠融资」 |
| 「三步走：看清各家真实盈利」 | 「财报最齐全，份额可查证」 |
| 「数据来源与可信级说明」 | 「原文出处，逐条挂标签」 |
| 「机制推演：内容方薄利的原因」 | 「客户不赚钱，工具难提价」 |
| 「方法论与口径边界」 | 「口径不同，份额不同」 |
| 「结论与下一步建议」 | 「逐层排除之后，只剩一条路走」 |

**自检三问**（每写完一个标题问一遍）：
1. 读者只看标题（不读正文）能知道这节讲什么吗？
2. 上下句字数对得上吗？词性对得上吗？
3. 标题里有修辞动词、读法标签、模板数字、元描述吗？

### 9. 导航 / Brand 命名规则（强约束）

报告顶部的导航栏承担「目录 + 进度提示」双重作用，命名规则如下：

**导航右侧（跳转入口）：**
- **保留原始章节名**：用「摘要 / 口径 / 大盘 / 逐家 / 规律 / 来源」等章节原词直接做 nav 项。
- **不要「凝练为逻辑链」**（如「谁赚 / 怎么比 / 钱往哪 / 谁拿了 / 五条规律 / 来源」）——逻辑链看似高级，但实际跳读时会丢失章节身份，与正文标题不一致。
- **不要给 nav 项加序号**（如「1 摘要 / 2 口径」），nav 是目录不是序号。**示例模板 `assets/template.html` 已按此执行**（nav 为「摘要 / 市场盘子 / 需求与供给 / 竞争与机会 / 来源」）——套模板时不要把序号加回去；正文板块的编号（`.part-banner` 里的 `.pnum` 数字块）属于板块标识，与 nav 是两套体系，不冲突。
  - 机检：`grep -oE '<a href="#[^"]+">[0-9]' file.html` 应无输出；出现即说明 nav 项被加了序号。
- **数量**：6–8 项为佳，与大节数对齐；过多会破坏扫读节奏。
- **锚点**：每一项对应一个 section 的 `id`（如 `href="#p2"`）。

**导航左侧（brand / 报告名）：**
- 用「**一句话点全文**」的对仗短语作为品牌区，可附 logo 字块。
- 例：「钱聚平台端，路在工具层」——上句点出现状（钱在哪里厚），下句点出结论（出路在哪里）。
- 不要放文件名式 brand（「report.html」「市场调研 v3」），无信息量。
- 不要放「cyx-html-style · 暗色科技风」这类 eyebrow 元描述 chip——见第 1 节。
- 5+5 或 6+6 字数对仗，与正文标题风格一致。

**反例 → 正例：**

| 反例 | 改成 |

| nav：「1 摘要 / 2 口径 / 3 大盘 / 4 逐家 / 5 规律 / 6 来源」 | nav：「摘要 / 口径 / 大盘 / 逐家 / 规律 / 来源」 |
| nav：「首页 / 目录 / 第一章 / 第二章」 | nav：「摘要 / 口径 / 大盘 / 逐家 / 规律 / 来源」 |

**左侧目录面板（`.toc`，长报告默认加，2026-09-28 按 Lulu 参考图升级为面板式）：**

- **何时加**：大节 ≥ 4 或正文超过两屏的单页报告，默认加左侧目录；短页（一屏内看完）不加，避免导航比正文还长。
- **面板式结构**：`<div class="layout"><nav class="toc">…</nav><main>…</main></div>`——`.toc` 是**通栏深色边栏**：自带更深的底色（比正文背景暗一档）+ 右侧分隔线，`position:sticky; top:0; height:100vh; overflow-y:auto`，不是漂浮的一小列；`main` **占满剩余空间**（紧贴侧栏起排、上限宽度 1200px 级，不做居中留大块空档——2026-09-28 Lulu 明确「左右布局增大」）。
  **2026-09-28 按参考图实测的尺寸（照着抄，别凭感觉调）：**
  ```css
  .layout{display:grid;grid-template-columns:196px minmax(0,1fr);min-height:100vh}
  .toc{position:sticky;top:0;align-self:start;height:100vh;overflow-y:auto;
       padding:22px 14px 30px 26px;border-right:1px solid var(--border)}
  .toc-title{display:flex;align-items:center;gap:9px;font-size:15px;font-weight:700;
  ```

  关键点：**`.layout` 上不挂 `max-width` / `margin:0 auto`**——一挂上去侧栏就离开视口左边缘，整体变成居中的浮岛，和参考图不是一回事。宽度靠 `main` 的内容列封顶来控。
- **窄屏行为（二选一，按用途定）**：长报告用「整条收起，正文独屏」——视口宽 < 1100px 级时 `.toc` 直接 `display:none`；短页或需要移动端能跳转的用「折到正文上方横排」——`@media(max-width:820px){.layout{grid-template-columns:1fr;min-height:0}.toc{position:static;height:auto;border-right:0;border-bottom:1px solid var(--border)}.toc nav{flex-direction:row;flex-wrap:wrap}}`。
- **目录标题 = 主色竖条 + 「目录」**：`.toc-title` 用 `display:flex;gap:9px`，前面放一个 4×16px 圆角主色块（`::before`），字号比目录项大一档（15px）、`font-weight:700`、`letter-spacing:2px`、颜色用正文色。**不要换成列表图标**——2026-09-28 放大参考图核对过，那条小标记是主色竖条，不是汉堡/列表图标。
- **命名规则**：项名用**章节原词**，**带章节序号**（「一、关键词矩阵」），序号与正文标题一字不差；每项对应一个章节 `id` 锚点。序号**不单独调暗**——参考图里「一、」和后面的字同色，加 `opacity` 或换 muted 色都会显得比参考图脏。
  ⚠️ **序号必须与正文 `h2` 同步编号**。目录项排到「七、」而正文写「六、」是最容易被一眼看穿的错，改序号时两处一起改。
- **多级目录必须看得出层级**（2026-09-29 补）：目录里有「章 → 分组 → 条目」三层时，三层要同时靠**缩进 + 字重 + 颜色**区分，只拉开缩进一档看不出来：
  ① 一级（章）：常规字重、muted 色；② 二级（分组标题）：缩进一档、`font-weight:600`、**换成正文色**——它是一组的头，要比一级更重；
  ③ 三级（条目）：再缩一档、字号小半档、**比一级更浅**，左侧加一小段细短横线当引导线（`::before` 宽 9px 级、绝对定位在缩进空档里）。
  判据：**遮住文字只看深浅和缩进，能不能数出三层？** 数不出来就是层级没做出来。
  反面：分组标题（A./B./C.）和它下面的条目（A1/A2…）共用同一个缩进档——截图上完全平齐，层级信息为零。
- **当前节高亮（`.active`）**：**主色文字 + 左侧 3px 主色实线 + 主色 10% 透明底**，`border-radius:0 8px 8px 0`（左侧直角好让竖线贴边），`font-weight:600`。竖线是有的——参考图上当前项左边那条蓝线就是它，别省。滚动时跟随，不常亮，用几行原生 JS 的 scrollspy 实现。
- **目录项正文色**：非当前项一律 muted，只有当前项变主色；`hover` 才提亮。全项常亮就没有「当前在哪」的信息了。
- **这套报表的正文头部（同一参考图）**：`main` 顶部依次是——`.eyebrow` 眉题（小号大写、字距拉开）→ `h1` → 一句话简介 → `.chips` 标签行（口径 / 数据截至 / 方法，一行深色小圆角片）。这些口径信息归头部，不散进正文。
- **与 topnav 的分工**：顶部导航管全局（含摘要、来源），左侧目录管章节间跳转；两者可并存，项名必须与正文标题用词一致，一套词两处用，不各起一套。
- **配套的正文头部（同一参考图）**：`main` 顶部依次是——`.eyebrow` 眉题（小号大写、字距拉开、主色）→ `h1` → 一句话简介 → `.chips` 标签行（口径 / 数据截至 / 方法，一行深色小圆角片）。这些口径信息归头部，不散进正文。
- **配套的章节标题**：`h2` 用**主色左竖条**（`border-left:3px solid var(--accent)` + `padding-left`），不用下划线——与左侧目录的高亮竖条同构，视线能对上。
- **判据**：删掉侧栏，读者在长页里是否要靠滚动找章节？是 → 该加；否（短页）→ 不加。

**字体与背景：**
- 正文：`"PingFang SC","Microsoft YaHei","HarmonyOS Sans SC",-apple-system,"Segoe UI",sans-serif`。
- 等宽 / 数字：`"JetBrains Mono",Consolas,monospace`（用于大数字、编号、公式）。
- 背景：深空蓝底色 + 径向霓虹光晕（`body::before`）+ 细网格（`body::after`，`--grid` 60px）。
- 所有面板 / 卡片用半透明深色 + 青色描边，营造"玻璃质感科技风"。

**组件类速查（完整 CSS 见 assets/cyx-html-style.css）：**
- 导航：`.topnav` / `.brand` / `.nav-links`；左侧目录面板：`.layout` + `.toc`（`.toc-title` 带小标识 + 带序号章节链接，当前节 `.active` 淡底高亮，通栏深色边栏，`.layout` 不挂 max-width，窄屏按一.9 二选一处理）——长报告默认加，规则见一.9；配套正文头部 `.eyebrow` + `.chips`（`.chip`）与色条式 `h2` 同见一.9
- 板块标题：`.part-banner`（`.pnum` 数字块 + `h1` + `.pdesc`）——在 `<main>` 内，**不得自带左右 gutter**（main 已给一份，再加一份标题会与 `.page` 卡片左边缘错开，观感上「标题与正文割裂」）
- 页面：`.page` / `.page-head`（`.page-title` + `.pace`）/ `.page-body`
- 小节标题：`.info-title`（加 `.mag/.yel/.pur/.ora` 换色）
- 实体级小标题（逐家 / 逐项详情块）：`h4.co-sub`（青色左竖线，比 `.info-title` 低一级）
- 要点列表：`ul.pts`（+ 二级 `<ul>` 子项）、`.pts-tail`（收尾判语）、`.db-title`（`.define-box` 内框标题）
- 说明注：`.note`（分层依据）、`.viz-cap`（图表读法）、`.fn-note` + `.mk`（口径 / 评级依据）
- 说明框：`.define-box`（加 `.mag/.yel` 换色）、`.ops`、`.formula`（公式）
- 徽章：`.chip`（加 `.m/.p/.y/.o/.g` 换色）
- 卡片网格：`.grid2` / `.grid3` + `.mini`（加 `.mag/.pur/.yel/.ora/.gre`）
- 大数字：`.big`（加 `.mag/.yel/.pur/.gre/.ora`）
- 表格：`table.t`（行高亮 `.hl` 青色 / `.hl2` 黄色，外层 `.tw` 横向滚动）
- 页面口径标签：`.layout-tag`（把本节口径范围写在正文开头一行）
- 插图容器：`.scene`（内联 SVG，渲染规则见 cyx-research-report 第十节）
- 星级强度：`.star`（用于「难度 / 成熟度」这类强度标示，必须同句写明依据）
- 脚注：`sup.fn` / `.footnotes` / `.fn-item` / `.fn-n`——**编号全文连续**：同一来源跨页复用同一编号，新来源顺延，不按页重启
- 可信级徽章：`.tag.l1 ~ .tag.l5`
- 术语标识：`.tag.term`（紧随术语的小徽章，青底虚线框，表示「这个词下面有解释」）
- 页脚：`footer` / `footer .src`（来源总索引）/ `footer .wm`（署名徽章）

速查里出现的类，`assets/cyx-html-style.css`（与 `cyx-research-report/assets/template.html` 内联样式同源）中必须有定义；改动任一处后跑 `python scripts/check-template.py` 机检三方对齐。

**配色纪律：**
- 暗底为主，文字用 `--text` / `--text-dim`，避免纯白刺眼。
- 高饱和色（magenta / orange / yellow）只作点缀与强调，面积占比小，不铺满。
- 同页色彩使用有节制：一个板块通常 1 个主色 + 至多 1 个强调色。
- 链接用 `cyan`，悬停转 `yellow`。

**视觉克制原则（防塑料味）：**
1. **文字优先，图表是补充**：能用一段说清，就不堆表 + 卡片 + SVG + 徽章。
2. **一个板块一种视觉**：不要"标题 + 卡片 + 表格 + 图表 + 徽章"全套堆砌。
3. **大数字 `.big` 是稀缺品**：仅在数据有冲击时用，不当装饰；不连续铺 3 张以上。
4. **高饱和色是调料**：单板块 cyan / magenta / yellow / orange 加起来不超过 2 处。
5. **无意义装饰删除**：竖条、阴影、渐变、光晕如果只为"好看"而非"信息"，删。
6. **不堆"科技感符号"**：避免"全息渐变 + 发光阴影 + 霓虹色 + 玻璃质感"全套一起上。
7. **左侧竖条是分隔符，不是招牌**：`.define-box` 的左侧竖条仅作内容类型提示（如"口径"），不要每段都套。
8. **`.define-box` 留作"边界声明"**：仅在"口径说明 / 边界 / 反直觉结论"等真正需要框出时用；不当作普通段落的装饰框。**严禁用于"解读 / 看清 / 洞察 / 观察 / 速读"等读法标签**——这些是教读者"怎么读"的空标签，删。

## 三、SVG 渲染规则（关键坑）

SVG `<text>` 内 **HTML 的 `<sup>`、`<b>` 不生效**，必须用 `<tspan>`：
```xml
<!-- ❌ 错误 -->
<text>... 0–300 元/年<sup>1</sup> <b>扩大边界</b></text>
<!-- ✅ 正确 -->
<text>... 0–300 元/年<tspan baseline-shift="super" font-size="9" fill="#00F5D4">1</tspan></text>
<text><tspan fill="#00F5D4" font-weight="700">扩大边界</tspan><tspan dx="4" baseline-shift="super" font-size="9" fill="#00F5D4">2</tspan></text>
```
- 用 `fill` 不用 `color`；上标用 `baseline-shift="super"`；加粗用 `font-weight`；间距用 `dx`。

## 四、AI 塑料味反面案例与避坑（核心）

### 反面案例 → 改成

| 反例（典型 AI 塑料味） | 为什么 | 改成 |
|---|---|---|
| 「一句话结论：xxx」 | 教读者"怎么读"，是"读法"变种；标签本身无信息量 | 直接陈述结论，删掉"一句话结论："标签 |
| 「一句话解读」「核心要点」「核心观点」「核心结论」作小节标题 | 空标签，没信息量 | 用具体内容名（如"市场盘子的三个口径差异"） |
| 单独「解读 / 看清 / 看懂 / 速读 / 速览 / 洞察 / 观察」作小标签（常带左侧装饰条） | 教读者"怎么读"，是"读法"变种；标签本身无信息量 | 删标签，直接写内容；用具体名词 |
| **页头 `.pace` 角标使用修辞动作**：「机制推演 / 路径推演 / 逻辑梳理 / 推导过程 / 论证」 | 角标在描述作者正在做什么，不是在说明内容 | 删除角标；必须保留时改为真实信息（如「2025.12 口径」「样本 N=128」） |
| **小节副标题 / `.info-title` 写「机制分析 / 路径拆解 / 逻辑梳理 / 推导过程」** | 修辞动作词 | 改用内容名（「渗透率低的三个原因」/「用户从试用到付费的变化」/「投入与回报的关系」） |
| 「三步走」「四个维度」「五个关键」「三大趋势」 | 空洞的"数字+名词"模板 | 直接列"第一步做什么、做什么、做什么"；如非要结构，列具体名称 |
| 「⚡ 干货」「📌 划重点」「💡 注意」「🔥 必看」 | emoji 装点，AI 报告标志 | 删；如确需强调，用一个粗体字 |
| 「干货」「硬核」「炸裂」「颠覆」「封神」 | 自夸词 | 删 |
| 「保姆级」「吐血整理」「敲黑板」 | 营销词 | 删 |
| 「可圈可点」「不容错过」「深度好文」 | 营销词 | 删 |
| 摘要页固定三件套：「一句话结论」+ 三张大数字 + 板块编号 | 模板化、塑料感重 | 因内容而异，能省就省；不要"三张 .big 卡片"的标准 AI 模板 |
| 段落前大竖条 + 内部嵌套卡片 + 大数字 + 徽章堆叠 | 装饰过度、视觉过载 | 一个板块一种视觉；装饰只为信息，不为"好看" |
| 大量霓虹色 + 全息渐变 + 发光阴影 + 玻璃质感 | 视觉过载、AI 报告感 | 暗底为主，色彩仅作 1-2 处点缀 |
| 「从图可见…」「如上图所示」「数据告诉我们…」「一目了然」 | 元语言，AI 报告常用 | 直接说图说明了什么，不绕弯 |
| **「前提：…」「推断：…」「结论：…」三件套作段落标签（常带左侧装饰条、套 `.define-box`）** | **教读者"怎么读"，是"读法"变种** | **删标签，三步在自然段落中呈现，用句首承接词过渡** |
| **eyebrow 元描述 chip**：「cyx-html-style · 暗色科技风 · 整理自xx」「本文采用 xxx 风格」 | 描述本文格式/来源的元标签，与内容无关 | 删 |
| **段首交待「本节要干什么」**（「本部分不逐家罗列，只做横向归纳，把……讲清楚」「下面我们来分析……」） | 空转一句——读者不关心你打算写什么，只看你写了什么 | 直接进入内容；范围、口径等限定并进事实句 |
| **修订流水进文档**（「最近修订：××。本日 N 件事——（1）……（4）……」） | 报告是给读者看结论的，不是给作者记工时 | 删；修订记录放版本管理 / 交付说明 |

### 装饰删除纪律

以下装饰**只在有信息价值时使用**，否则删：
- 左侧发光竖条：仅 `.define-box` 的"口径说明 / 边界 / 反直觉结论"框、`.info-title` 的小节分隔。**`.define-box` 严禁套读法标签（"解读 / 看清 / 洞察 / 观察 / 速读"等）。**
- 大数字 `.big`：仅数据有冲击时（如"市场规模 62.8 亿"），不当装饰。
- 大数字块 `.pnum`：仅板块编号的视觉锚，不滥用。
- 公式 `.formula`：仅需要展示计算逻辑时。
- 徽章 `.chip`：仅短标签 / 分类时（如"官方""第三方"），不堆叠。
- 术语标识 `.tag.term`：**仅标非本行业读者猜不出意思的词**（如"SaaS 云平台型""单校样板校"），紧跟在那个词后面；本行已自明的词（"课程""师资培训"）不加。它是"这里有白话解释"的路标，不是强调装饰。
- 卡片 `.mini` / `.grid3`：仅多组并列信息时；不要"一段话也要装进卡片"。
- **层级只用三层**：`.info-title`（小节）→ `h4.co-sub`（实体详情块）→ 正文。需要更细一层时改用 `ul.pts` 分点，不要继续造标题层级。
- **列表只用两级**：一级点 + 二级子项（逐家 / 逐项）。出现第三级就说明这段该拆成多个小节，或改用表格。

## 五、工作流程（执行顺序）

1. **确定风格范围**：确认产出物是否需要暗色科技风；若需其他风格则跳出不套用。
2. **注入样式**：复制 `assets/cyx-html-style.css` 的 `:root` 变量与组件类到产出物。
3. **按语言规范写作**：去 AI 味、克制图文、简洁、通俗、逻辑闭环、层级编号。
4. **按视觉规范排版**：用组件类表达结构，配色遵守语义色板与配色纪律。
5. **过反塑料味速查**：见「四」末尾。
6. **处理 SVG**：图内用 `<tspan>`。
7. **自查清单**过一遍再交付。

- [ ] **结论有案例证据**：每条结论句能回查到主体 + 数字 / 时间 / 资料名；无「不少厂商 / 业内普遍 / 行业领先」类无主体断言，无「赋能 / 大幅提升 / 前景广阔」类空话；无依据的排名与趋势已补来源或删除
- [ ] **事实优先、宁缺毋造**：查不到事实的结论已**整句删除**（未改成模糊表述保留）；未用「据悉 / 预计 / 有望」填空；推演项已标「非普查」并列锚点；缺口逐个显式列出
- [ ] **叙事链闭合**：结论 → 依据 → 来源 → 可信级四环无断点；相邻段落有显性承接；相邻矛盾结论已当场说明原因（口径 / 时间 / 样本不同）

## 七、自我进化机制（本 skill 同步更新规则）

> **上游通用条款**：判定、留痕、回退的共性规则见 `cyx-skill-evolution`；本节与本技能包内 `cyx-research-report`「十六」同源，
> 冲突时以本技能包为准（有专属账本 `../references/feedback-log.md` 与机检 `../scripts/check-template.py`）。

**本 skill 不是一次写死的。** 用户就视觉与观感提的每一条意见，都可能是一条适用于**所有后续 HTML 产出物**的规则；把它挑出来写回本文件与样式表，本 skill 才会越用越准。本节与 `cyx-research-report`「十六」、`cyx-md-style`「六」同构，三者共用一本账（`../references/feedback-log.md`）与一次校验（`../scripts/check-template.py`）。

### 7.1 触发时机

- 用户对**呈现侧**提意见：配色、字号、版心留白、组件样式、图表、SVG、导航命名、观感「像 AI 生成的」。
- **同一类意见反复出现（≥2 次）**——最强信号：不是这一份产出物的问题，而是**默认值或默认写法错了**，必须升级为强约束。
- 典型前车之鉴：用户连提 4 次「边距窄」，真因是默认留白偏窄、且前三次都调错了变量（动了 `--wrap`，而视口窄于上限时只有 `--gut` 生效）。**遇到反复出现的视觉意见，先找默认值与判定方法的问题，不要只改当期数值。**

### 7.2 视觉侧反馈 → 本 skill 落点

| 反馈类型 | 典型原话 | 改本文件哪一节 | 还需同步 |
|---|---|---|---|
| 版心与留白 | 「两边边距宽一点」「两侧太窄」「内容太长」 | 二（色彩与视觉风格）的变量块与版心说明 | `assets/cyx-html-style.css` 的 `:root` + 当期构建脚本 + `../assets/template.html` |
| 配色与语义色 | 「太刺眼」「主色太杂」「风险色不对」 | 二（配色纪律与语义色板） | `assets/cyx-html-style.css` |
| 组件类 | 「这个卡片太重」「新增 / 改名 / 删除某组件」 | 二（组件速查）+ 四（反塑料味） | `assets/cyx-html-style.css` + `../assets/template.html` 正文示例 |
| 去 AI 味 | 「不要 emoji / 读法标签 / 元描述 chip」「一眼 AI 味」 | 一.1（去 AI 味）+ 四（反面案例 → 改成） | `../scripts/check-template.py` 硬规则区 |
| 命名 | 「导航 / brand 名不对」 | 一.9（导航 / Brand 命名规则） | `../assets/template.html` |
| 数据可信 | 「数字要有来源」「别夸大」 | 一.0（数据可信强红线） | `cyx-research-report`（脚注与来源索引） |
| 通用语言 | 「太啰嗦」「看不懂」「逻辑跳」 | 一.2 简洁 / 一.4 通俗 / 一.5 逻辑闭环 / 一.6 不跳脱 | `cyx-md-style` 三 / 四（同一份清单，不重复维护） |

**推演要点**：改**变量**必须走「改一处动五处」的同步表（见 `cyx-research-report` 十六.5），否则模板、样式表、两份 SKILL 会互相打架；改**硬规则**必须同时落成机检项，否则下次交付仍会漏。

### 7.3 越界处理：不属于呈现侧的反馈转出去

| 反馈其实落在 | 转给 | 对方落点 |
|---|---|---|
| 骨架 / 层级 / 标记 / 措辞 / 视角 / 口径 / 术语 | `cyx-md-style` | 其「六.2 内容侧反馈 → 本 skill 落点」表 |
| 数据来源可信度 / 脚注 / 论证链红线 / 多格式链路 | `cyx-research-report` | 其「十六.4 / 十六.5」 |
| 只对这一份产出物成立的问题 | — | 不改 skill，只改当期产物 |

### 7.4 落盘纪律（三不写）

1. **不与已有条目重复**：同类已在 → 就地强化并把该条升为强约束，不新起一节。
2. **不写死具体数值**：用户说「边距再宽点」，写「默认宽留白 + 判定方法（视口 < `--wrap` 时只有 `--gut` 生效）」，不写「边距 = 64px」——数值只是当前默认。
3. **写不成判据或机检项的模糊直觉不进文件**：要么落成变量 / 组件类的改动，要么落成 `../scripts/check-template.py` 的一项。

### 7.5 留痕与校验

1. 在 `../references/feedback-log.md` 追加一行：`日期 / 原话节选 / 类别 / 归属 skill / 落点 / 处置`，「归属 skill」填 `cyx-html-style`。
2. 同类 ≥2 次 → 在本文件对应条目加粗升为强约束，并把该条前置进「六、交付前自查清单」。
3. 跑 `../scripts/check-template.py`（第 9 组校验三个 skill 的进化条款是否齐全），全过才算沉淀完成。
4. 一句话告知用户：「这条我记进 cyx-html-style 了，以后默认这样做。」

### 7.6 规则也会过时：允许回退

用户后续推翻某条（「这条不用这样」）→ ① 改本文件与样式表对应条目，**标注适用边界**而不是直接删除；② 在 feedback-log 追加「规则回退」；③ 查有无其他条目与它冲突（尤其二（变量）与四（反塑料味）之间）。

### 7.7 交付后自检

- [ ] 改变量是否已按「改一处动五处」同步？（`../assets/template.html`、`assets/cyx-html-style.css`、两份 SKILL、当期构建脚本）

- [ ] 越界项（内容 / 方法论）是否已转给对应 skill？
